# DAGs von Hand ausführen

Im Normalbetrieb **muss nichts von Hand ausgelöst werden**: Bronze läuft nach seiner Uhr, und Silver und Gold starten über Assets von selbst. Ein manueller Lauf ist nur beim ersten Mal nötig, um eine Lücke zu füllen oder um eine Änderung sofort zu sehen. Jeder DAG ist idempotent, ein erneuter Lauf ist also immer sicher: Er überschreibt dieselben Dateien mit demselben Ergebnis.

## Was wovon abhängt

<DagDependencies />

`&` bedeutet *alle müssen seit dem letzten Lauf geschrieben haben*; `|` bedeutet *eine genügt*. Wer also einen Bronze-DAG auslöst, startet damit auch die Silver-DAGs, deren übrige Eingaben schon frisch sind, und diese starten wiederum Gold.

| Zum Aktualisieren von… | Auslösen | Startet danach von selbst |
| --- | --- | --- |
| Wechselkursen | `bronze_f7_fx` | `silver_fx_daily` (und `silver_reservas_daily`, sobald Snapshot und Kataloge auch frisch sind) |
| Buchungen sofort | `bronze_neon_f2_f3` | `silver_reservas_daily` |
| Belegung | `bronze_neon_full_load`, dann `bronze_neon_dims` | `silver_ocupacion_daily`, `silver_reservas_daily` |
| Kalender | `bronze_f6_holidays` (oder `bronze_f6_events` + `bronze_neon_dims`) | `silver_calendario_daily` |
| Bewertungen | `bronze_f5_reviews`, dann `silver_resenas_daily` | – (Silver der Bewertungen läuft nach der Uhr) |
| F1-Historie | `bronze_f1_historical` | `silver_f1_historico` |
| Gold | `gold_modelo_daily` direkt (liest, was in Silver liegt) | `gold_neon_writeback` |

## Erster Lauf in einer neuen Umgebung

Diese einmal in dieser Reihenfolge ausführen und warten, bis jeder grün ist:

1. `bronze_f1_historical`: die Historie (nur ein einziges Mal).
2. `bronze_f7_fx`: erste Kurse; `silver_fx_daily` folgt.
3. `bronze_f6_holidays` und `bronze_f6_events`.
4. `bronze_neon_full_load`: die gesamte Neon-Historie.
5. `bronze_neon_dims`: Kataloge. Jetzt starten `silver_reservas_daily`, `silver_ocupacion_daily` und `silver_calendario_daily` von selbst.
6. `bronze_f5_reviews` und dann `silver_resenas_daily`.
7. Wenn die vier Silver-Tabellen fertig sind, startet `gold_modelo_daily` von selbst (oder auslösen), danach `gold_neon_writeback`.

## Auslösen in der Airflow-UI

1. `https://airflow-buenavista.coderhivex.com` öffnen, den DAG suchen und **▶ Trigger** drücken.
2. Im Dialog eine **eindeutige Run ID** angeben, zum Beispiel `manual__2026-11-09_1`.
   **Warum:** Airflow 3 richtet das logische Datum eines manuellen Laufs am Zeitplanintervall des DAGs aus. Zwei manuelle Läufe im selben Intervall erhalten dasselbe logische Datum, und der zweite wird mit **409 Conflict** abgelehnt. Eine eindeutige Run ID verhindert das.
3. Oder, um einen bestehenden Lauf zu wiederholen (zum Beispiel eine fehlgeschlagene Stunde), ihn öffnen und **Clear** drücken: Airflow führt dasselbe Intervall erneut aus und überschreibt dieselben Dateien.

Über die Kommandozeile auf der Kern-Maschine:

```bash
docker compose -f docker-compose.nucleo.yaml exec airflow-apiserver \
  airflow dags trigger bronze_neon_full_load --run-id manual__$(date +%Y%m%d%H%M)
```

## Das Ergebnis lesen

- **Grid-Ansicht:** grün = fertig, rot = nach allen Wiederholungen fehlgeschlagen. Die **Logs** der Aufgabe öffnen: Jeder Job gibt zurück, wie viele Zeilen er geschrieben hat (am Ende des Logs sichtbar), und eine fehlgeschlagene Qualitätsprüfung nennt Tabelle und Regel.
- **Assets-Ansicht:** zeigt, wann jedes Asset zuletzt aktualisiert wurde und welche DAGs darauf warten. Hilfreich, um zu sehen, warum ein Silver- oder Gold-DAG noch nicht gestartet ist (eine seiner `&`-Eingaben fehlt noch).
- **Flower** (`flower-buenavista.coderhivex.com`): welcher Worker (`bronze`, `silver`, `gold`) was ausführt.

## Häufige Fälle

| Symptom | Ursache | Was tun |
| --- | --- | --- |
| Ein Silver-DAG startet nicht | Eine seiner `&`-Eingaben hat seit dem letzten Lauf nicht geschrieben | Assets-Ansicht prüfen und den fehlenden Bronze-DAG auslösen |
| 409 Conflict beim Auslösen | Gleiches logisches Datum wie ein bestehender Lauf | Eindeutige Run ID verwenden oder den bestehenden Lauf mit Clear wiederholen |
| `silver.reservas: rows without total_cop` | Eine Währung hat noch keinen Kurs | `bronze_f7_fx` auslösen (füllt jeden Tag vorwärts) |
| `bronze has no inventory snapshot yet` | Der Voll-Snapshot lief nie | `bronze_neon_full_load` auslösen |
| `NEON_READ_URL is empty` | Variable fehlt auf den Workern | In die `.env` der Worker eintragen und sie neu starten |
| In Gold fehlen P5 oder der Preisvorschlag | Silver der Bewertungen oder die Tarife sind noch nicht im Lake | `silver_resenas_daily` / `bronze_neon_dims` ausführen, dann Gold |
