# Extraktion und Laden: Verbindung zu Neon und S3

Die ganze Pipeline besteht aus **zwei Verbindungen**: Sie **extrahiert** aus Neon (und einigen APIs) und **lädt** nach S3. Diese Seite ist die praktische Anleitung: welchen String jede braucht, ein Beispiel für jeden String und der Code, um sie in einer Minute zu testen.

:::warning[Nur Platzhalter]
Jeder Wert in `<spitzen Klammern>` ist ein Platzhalter. Echte Passwörter stehen nur in der `.env` jeder Maschine (nie in Git) und werden im Team privat geteilt. Wurde ein Passwort jemals in einen Chat oder Commit kopiert, in Neon ändern (**Roles → Reset password**).
:::

## Der Prozess in 6 Schritten

| Schritt | Von | Nach | Wie | Genutzte Verbindung |
| --- | --- | --- | --- | --- |
| 1. Stündlich extrahieren | Neon `operation`, `streaming` | S3 `bronze/f2_ledger/`, `f3_reservations/`… | `SELECT … WHERE updated_at >= Start AND < Ende` → JSON Lines → `put_object` | `NEON_READ_URL` + IAM-Rolle |
| 2. Nachts extrahieren | Neon (ganze Tabellen) | S3 `bronze/*_full/fecha=…/` | eine `REPEATABLE READ`-Transaktion, Seiten zu 50.000 Zeilen, `_SUCCESS` am Ende | `NEON_READ_URL` + IAM-Rolle |
| 3. Aus APIs und Dateien extrahieren | F1, F5, F6, F7 (HTTP) | S3 `bronze/…` | `requests.get` → `put_object` | Basis-URLs in `.env` + IAM-Rolle |
| 4. F4-Dateien laden | EC2 Quellen | S3 `bronze/f4_agencias/semana=…/` | `s3.upload_file` aus `f4-weekly` | IAM-Rolle der EC2 Quellen |
| 5. Transformieren und laden | S3 bronze / silver | S3 silver / gold | Spark `read.json` / `write.mode("overwrite").parquet` | IAM-Rolle (`s3a://`) |
| 6. Write-back | S3 gold | Neon `operation.cancellation_rate_by_lead` | `INSERT … ON CONFLICT DO UPDATE` | `NEON_WRITE_URL` |

## Neon (PostgreSQL)

### Aufbau des Connection-Strings

<UriAnatomy parts={[
  ['postgresql', 'Schema', 'airflow'], ['://'], ['etl_reader', 'Rolle', 'neon'], [':'], ['<password>', 'Passwort', 'bad'], ['@'],
  ['ep-<endpoint-id>-pooler.us-east-2.aws.neon.tech', 'Host (Endpoint des Branches)', 'aws'], ['/'], ['hospedaplus', 'Datenbank', 'neon'],
  ['?'], ['sslmode=require', 'SSL Pflicht', 'out'],
]} />

| Teil | Wert in HospedaPlus | Hinweise |
| --- | --- | --- |
| Schema | `postgresql://` | `postgresql+psycopg2://` für SQLAlchemy |
| Rolle | `etl_reader` (nur lesen), `app_writer` (lesen/schreiben), `hospedaplus_owner` (Schemaänderungen) | Die Rolle mit den wenigsten Rechten wählen, die ausreicht |
| Host | `ep-<endpoint-id>.us-east-2.aws.neon.tech` | Jeder Branch (`production`, `development`) hat seinen eigenen Endpoint |
| `-pooler` | `ep-<endpoint-id>-pooler…` | Gepoolter Host (PgBouncer): für viele kurze Verbindungen (Simulatoren, Apps). Für Migrationen und Sitzungen mit `SET` den **direkten** Host nutzen |
| Port | `5432` | Standard, kann entfallen |
| Datenbank | `hospedaplus` | Nicht `neondb` |
| Parameter | `sslmode=require` (immer), `channel_binding=require` (optional, für den Owner) | Neon lehnt Verbindungen ohne SSL ab |

### Beispiel-Strings nach Verwendung

```bash title=".env-Beispiele (Platzhalter)"
# Airflow-Bronze-DAGs: nur lesen
NEON_READ_URL=postgresql://etl_reader:<password>@ep-<endpoint-id>.us-east-2.aws.neon.tech/hospedaplus?sslmode=require
# gold_neon_writeback: schreibt operation.cancellation_rate_by_lead
NEON_WRITE_URL=postgresql://app_writer:<password>@ep-<endpoint-id>.us-east-2.aws.neon.tech/hospedaplus?sslmode=require
# F3-Simulator / F2-Consumer / F4-Loader: viele kurze Schreibvorgänge, gepoolter Host
NEON_APP_URL=postgresql://app_writer:<password>@ep-<endpoint-id>-pooler.us-east-2.aws.neon.tech/hospedaplus?sslmode=require
# Schemaänderungen und Seed (db_simulated init, buenavista-streaming-Migrationen): Owner, direkter Host
NEON_OWNER_URL=postgresql://hospedaplus_owner:<password>@ep-<endpoint-id>.us-east-2.aws.neon.tech/hospedaplus?sslmode=require&channel_binding=require
```

**Wo man ihn kopiert:** Neon-Konsole → Projekt `hospedaplus_database` → **Connect** → Branch `production`, Datenbank `hospedaplus` und Rolle wählen → *Connection String* kopieren. Für den `-pooler`-Host **Connection pooling** einschalten.

### Verbinden (Test in einer Minute)

```bash title="psql"
# Verbindet sich mit dem vollständigen String, führt eine Abfrage aus (-c) und beendet sich
psql "postgresql://etl_reader:<password>@ep-<endpoint-id>.us-east-2.aws.neon.tech/hospedaplus?sslmode=require" \
  -c "SELECT count(*) FROM operation.reservations;"
```

```python title="Python · psycopg2 (was die DAGs nutzen)"
# os liest Umgebungsvariablen; psycopg2 ist der PostgreSQL-Treiber
import os, psycopg2

# Öffnet die Verbindung mit dem String aus .env und einen Cursor
with psycopg2.connect(os.environ["NEON_READ_URL"]) as conn, conn.cursor() as cur:
    # Die 5 zuletzt geänderten Buchungen
    cur.execute("SELECT code, status, updated_at FROM operation.reservations ORDER BY updated_at DESC LIMIT 5")
    # Geht die Ergebniszeilen durch
    for row in cur.fetchall():
        # Gibt jede aus
        print(row)
```

```python title="Python · psycopg 3 (was die Simulatoren nutzen)"
# psycopg ist Version 3 des PostgreSQL-Treibers
import os, psycopg

# Verbindet sich (gibt nach 10 s auf); am Blockende geschlossen
with psycopg.connect(os.environ["NEON_APP_URL"], connect_timeout=10) as conn:
    # Wer bin ich und wie spät ist es in der Datenbank
    print(conn.execute("SELECT current_user, now()").fetchone())
```

```python title="Python · SQLAlchemy + pandas (Notebooks, Exploration)"
# pandas für Tabellen in Python
import os, pandas as pd
# SQLAlchemy verwaltet die Verbindungen für pandas
from sqlalchemy import create_engine

# SQLAlchemy braucht den Treiber im Schema: postgresql+psycopg2://
url = os.environ["NEON_READ_URL"].replace("postgresql://", "postgresql+psycopg2://", 1)
# pool_pre_ping testet die Verbindung vor der Nutzung (Neon schließt inaktive)
engine = create_engine(url, pool_pre_ping=True)
# Führt die Abfrage aus und liefert einen DataFrame
df = pd.read_sql("SELECT * FROM operation.hotels", engine)
```

### Häufige Fehler

| Meldung | Ursache | Lösung |
| --- | --- | --- |
| `password authentication failed` | Falsches Passwort oder falsche Rolle | String erneut aus **Connect** kopieren; Branch prüfen |
| `could not translate host name` / `invalid URI` | Das Passwort enthält `@`, `#`, `/` oder `:` | Neu setzen nur mit Buchstaben, Ziffern, `-` und `_`, oder URL-kodieren (`@` → `%40`) |
| `SSL connection is required` | `sslmode` fehlt | `?sslmode=require` ergänzen |
| `permission denied for table …` | `etl_reader` versucht zu schreiben | `app_writer` (`NEON_WRITE_URL`) nur dort nutzen, wo geschrieben werden soll |
| `prepared statement … does not exist` | Sitzungsfunktionen über `-pooler` | Direkten Host (ohne `-pooler`) nutzen |

## S3 (Lakehouse)

### Aufbau der Adressen

<UriAnatomy parts={[
  ['s3', 'Schema', 'airflow'], ['://'], ['hospedaplus-lakehouse-buenavista', 'Bucket', 'aws'], ['/'], ['bronze', 'Schicht', 'bronze'], ['/'],
  ['f3_reservations', 'Quelle', 'neon'], ['/'], ['fecha=2026-11-10', 'Partition nach Datum', 'gold'], ['/'], ['hora=14.jsonl', 'Datei', 'out'],
]} />

- `s3a://hospedaplus-lakehouse-buenavista/silver/reservas`: dieselbe Art Adresse mit dem Schema, das Spark (Hadoop) nutzt.
- `https://hospedaplus-lakehouse-buenavista.s3.us-east-2.amazonaws.com/<key>`: HTTP-Form; der Bucket ist privat, daher braucht es eine signierte Anfrage.

| Was | Wert |
| --- | --- |
| Bucket | `hospedaplus-lakehouse-buenavista` (Variable `S3_BUCKET`) |
| Region | `us-east-2` (Variable `AWS_DEFAULT_REGION`) |
| Zugangsdaten auf AWS | IAM-Rolle der EC2 (`hospedaplus-pipeline-role`): **keine Keys** |
| Zugangsdaten auf dem Laptop | `aws configure` / `AWS_PROFILE`, oder `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` Ihres IAM-Benutzers |
| Lokale Tests (MinIO) | `S3_ENDPOINT_URL=http://localhost:9000` |

```bash title=".env-Beispiel"
# Name des Lake-Buckets
S3_BUCKET=hospedaplus-lakehouse-buenavista
# Region des Buckets
AWS_DEFAULT_REGION=us-east-2
# Nur auf einem Laptop ohne Rolle (nie auf der EC2, nie in Git):
# AWS_ACCESS_KEY_ID=<access-key-id>
# AWS_SECRET_ACCESS_KEY=<secret-access-key>
# Nur für MinIO:
# S3_ENDPOINT_URL=http://localhost:9000
```

### Verbinden (Test in einer Minute)

```bash title="AWS CLI"
# Listet die Ordner in bronze/
aws s3 ls s3://hospedaplus-lakehouse-buenavista/bronze/ --region us-east-2
# Gibt die ersten Zeilen einer Datei aus (- heißt "auf den Bildschirm")
aws s3 cp s3://hospedaplus-lakehouse-buenavista/bronze/f7_fx/fecha=2026-11-10.json - | head
```

```python title="Python · boto3 (was die bronze-DAGs nutzen)"
# boto3 ist das AWS-SDK für Python
import boto3, json

# findet die IAM-Rolle oder dein Profil selbst
s3 = boto3.client("s3", region_name="us-east-2")
# Der Lake-Bucket
bucket = "hospedaplus-lakehouse-buenavista"

# Laden (schreiben)
s3.put_object(Bucket=bucket, Key="bronze/test/hello.json", Body=json.dumps({"ok": True}).encode(),
              ContentType="application/json")
# Extrahieren (lesen)
body = s3.get_object(Bucket=bucket, Key="bronze/test/hello.json")["Body"].read()
# auflisten
for obj in s3.list_objects_v2(Bucket=bucket, Prefix="bronze/f7_fx/").get("Contents", []):
    # Name und Größe in Bytes jeder Datei
    print(obj["Key"], obj["Size"])
```

```python title="Python · eine ganze Datei hochladen (was f4-weekly macht)"
# Lädt eine lokale Datei hoch (Pfad auf der Platte, Bucket, Key in S3)
s3.upload_file("output/f4_agency_files/2026-W46/AG01.xlsx", bucket,
               "bronze/f4_agencias/semana=2026-W46/AG01.xlsx")
```

```python title="PySpark · bronze lesen, silver schreiben (was die silver/gold-Jobs machen)"
# Hilfsfunktionen des Projekts: Spark-Session und Lake-Adressen
from spark_jobs.session import spark, path

# local[*] + s3a-Jars + IAM-Rolle
s = spark("test")
# Liest alle JSON-Lines-Dateien eines Bronze-Tages
raw = s.read.json("s3a://hospedaplus-lakehouse-buenavista/bronze/f3_reservations/fecha=2026-11-10/")
# Schreibt sie als Parquet nach s3a://…/silver/reservas_test und ersetzt den Inhalt
raw.write.mode("overwrite").parquet(path("silver", "reservas_test"))
```

### Häufige Fehler

| Meldung | Ursache | Lösung |
| --- | --- | --- |
| `NoCredentialsError` / `Unable to locate credentials` | Weder Rolle noch Keys | Auf EC2: IAM-Rolle an die Instanz hängen. Auf dem Laptop: `aws configure` |
| `AccessDenied` | Der Rolle fehlt `s3:PutObject` / `ListBucket` | Policy von oben ergänzen |
| `PermanentRedirect` / `AuthorizationHeaderMalformed` | Falsche Region | `AWS_DEFAULT_REGION=us-east-2` |
| Spark `ClassNotFoundException: S3AFileSystem` | Jars fehlen | Pipeline-Image nutzen (es enthält `hadoop-aws` und `aws-java-sdk-bundle`) |
| Spark `No FileSystem for scheme "s3"` | `s3://` in Spark genutzt | In Spark `s3a://` nutzen; `s3://` in boto3 und der CLI |

## Write-back nach Neon (die einzige Ladung in Neon)

```python title="dags/gold_neon_writeback.py"
# Fügt eine Zeile ein oder aktualisiert sie, wenn (Hotel, Vorlauf-Klasse) schon existiert
UPSERT = """
INSERT INTO operation.cancellation_rate_by_lead (hotel_code, lead_bucket, cancel_rate, updated_at)
VALUES (%s, %s, %s, NOW())
ON CONFLICT (hotel_code, lead_bucket) DO UPDATE
   SET cancel_rate = EXCLUDED.cancel_rate, updated_at = EXCLUDED.updated_at
"""
# Verbindet sich mit der Schreibrolle
with psycopg2.connect(os.environ["NEON_WRITE_URL"]) as conn, conn.cursor() as cur:
    # eine Transaktion; erneutes Ausführen ergibt dieselbe Tabelle
    cur.executemany(UPSERT, rows)
```
