# Silver-Schicht

Silver macht aus den Rohkopien in Bronze **eine saubere, verlässliche Tabelle pro Entität**. Jeder Job ist in PySpark geschrieben (`spark_jobs/silver_*.py`), läuft auf dem Worker `silver`, liest Bronze mit explizitem Schema (ohne Inferenzdurchlauf), führt seine Qualitätsprüfungen aus und überschreibt erst dann seinen Parquet-Ordner.

| Silver-Tabelle | Gebaut aus | Eine Zeile pro | Hauptnutzung |
| --- | --- | --- | --- |
| `tasa_cambio_diaria` | F7 | Tag × Währung | Jeden Betrag in COP umrechnen |
| `reservas` | Buchungen in Neon (F2, F3, F4) + Kataloge + Kurse | Buchungscode | P1, P3, P4 |
| `cancelaciones` | `reservas` | stornierte Buchung / No-Show | P1 |
| `reservas_rechazadas` | Anomalien in Neon | abgelehnte Buchung | Datenqualität (Fehler 5.3) |
| `ocupacion_diaria` | Neon-Snapshot: Bestand, Umbuchungen, Ablehnungen | Hotel × Zimmertyp × Nacht | P2, P3 |
| `calendario_hotel` | F6-Feiertage + F6-Events + Hotels | Hotel × Tag | P3 |
| `resenas` | F5-Bewertungen + Hotels | Bewertung (Original) | P5 |
| `historico_f1` | F1-Kaggle-CSV | historische Buchung | P1 |

## Transformationen: wie und warum

### `tasa_cambio_diaria` (F7)

1. Liest alle Frankfurter-Antworten (Zeilen `date, base, quote, rate`, Basis USD) und ergänzt USD = 1.
2. Baut für jede Währung ein **tägliches Raster** vom ersten bis zum letzten Datum und füllt jeden Tag mit dem **letzten bekannten Kurs** (Vorwärtsfüllung).
3. Berechnet `cop_por_unidad = Kurs(USD→COP) / Kurs(USD→Währung)`.

**Warum:** An Wochenenden und Feiertagen gibt es keine Kurse, aber Buchungen, also braucht jeder Kalendertag einen Kurs. Frankfurter v2 kann jede Währung anders datieren (EUR oder MXN können ein anderes Datum als COP haben), daher wird jede Währung **vor** der Division durch COP auf ihrem eigenen Raster gefüllt; sonst gingen ganze Tage verloren.
**Prüfungen:** nicht leer, keine Nullwerte, `(fecha, moneda)` eindeutig, Kurs > 0, keine fehlenden Tage.

Code (`spark_jobs/silver_fx.py`):

```python
rates = (raw.select(F.to_date("date").alias("fecha"), F.col("quote").alias("moneda"),
                    F.col("rate").cast("double").alias("rate"))
         .dropna().dropDuplicates(["fecha", "moneda"]))           # + USD = 1.0 every day
days = bounds.select(F.explode(F.sequence("a", "b")).alias("fecha"))   # every calendar day
grid = days.crossJoin(rates.select("moneda").distinct())               # day x currency
w = Window.partitionBy("moneda").orderBy("fecha").rowsBetween(Window.unboundedPreceding, 0)
filled = (grid.join(rates, ["fecha", "moneda"], "left")
          .withColumn("rate", F.last("rate", ignorenulls=True).over(w))  # forward fill
          .dropna(subset=["rate"]))
cop = filled.filter("moneda = 'COP'").select("fecha", F.col("rate").alias("usd_cop"))
out = filled.join(cop, "fecha").select(
    "fecha", "moneda", (F.col("usd_cop") / F.col("rate")).alias("cop_por_unidad"))
```

### `reservas`, `cancelaciones`, `reservas_rechazadas` (F2, F3, F4)

Alle Kanäle schreiben über `reservar()` in `operation.reservations`, daher verarbeitet ein Job alle Buchungen.

1. **Nur das Nötige lesen:** den neuesten Voll-Snapshot (mit `_SUCCESS`) plus die stündlichen Dateien ab dem Tag vor diesem Snapshot.
2. **Neueste Version pro Code.** Dieselbe Buchung erscheint mehrmals (erstellt, geändert, storniert). Ein Fenster pro `code` behält die Zeile mit dem neuesten `updated_at` (in älteren Dateien den neuesten Wert aus erstellt/storniert/letztes Event); bei Gleichstand gewinnt die stündliche Datei gegen den Snapshot.
   **Warum:** Silver muss den aktuellen Stand jeder Buchung zeigen, genau einmal.
3. **Kataloge verknüpfen** (neueste Kopie von Hotels, Kanälen, Zimmertypen), um Hotelcode, Land, Kategorie, Zeitzone, Kanaltyp und Provision zu erhalten.
4. **Abgeleitete Felder:** `noches`, `huespedes`, `fecha_reserva`, `lead_time_dias` (Check-in − Buchungsdatum), `es_cancelada` (storniert oder No-Show), `es_duplicado` (Status `duplicate`).
5. **Währung nach COP** mit dem Kurs des Buchungstags. Buchungen vor dem ersten veröffentlichten Kurs nutzen den ältesten und werden mit `fx_estimada = true` markiert.
   **Warum:** Das Geschäft berichtet in COP, und die Hotels verkaufen in EUR, COP, MXN und BRL.
6. **Provision und Netto:** `comision_cop = total_cop × Provisionssatz des Kanals` und `neto_cop = total_cop − comision_cop` (P4).
7. **`cancelaciones`:** nur stornierte Buchungen / No-Shows, die keine Duplikate sind, mit `horas_antes_checkin` (von der Stornierung bis zum Check-in um 15:00) und einer Vorlaufklasse (`0-1`, `1-3`, `3-7`, `7-30`, `30-90`, `90+` Tage) für P1.
8. **`reservas_rechazadas`:** von Neon abgelehnte Buchungen (null Gäste, Check-out vor Check-in), eine pro Code.

Wie jeder Datenqualitätsfehler der Quellen behandelt wird:

| Fehler | Wo er behandelt wird | Ergebnis in Silver |
| --- | --- | --- |
| F3 null Gäste / Check-out vor Check-in | Von Neon abgelehnt, in `reservation_anomalies` protokolliert | `reservas_rechazadas`, nie in Kennzahlen |
| F4 doppelte Buchung | In Neon als `duplicate` markiert | `es_duplicado = true`, aus jeder Gold-Kennzahl ausgeschlossen |
| F4 fehlende Währung | Der Loader nimmt die Hotelwährung | Beibehalten |
| F2 Events in falscher Reihenfolge | In Neon gelöst (`last_event_at`) | Schon in Ordnung |

**Prüfungen:** nicht leer, `code` eindeutig, keine Zeile ohne `total_cop` (die Fehlermeldung nennt Quelle/Währung ohne Kurs), keine Nullwerte in Schlüsselspalten, `check_out > check_in`, mindestens ein Erwachsener, keine negativen Beträge, eindeutige Codes in `cancelaciones`. Die Tabelle ist nach `source` (F2, F3, F4) partitioniert.

Code (`spark_jobs/silver_reservas.py`):

```python
# 1. newest full snapshot + hourly files from the day before it on
def plan_days(full_days, hourly_days):
    newest = full_days[-1]
    since = (dt.date.fromisoformat(newest) - dt.timedelta(days=1)).isoformat()
    return [newest], [d for d in hourly_days if d >= since]

# 2. one row per booking code: the newest version (hourly file wins a tie: _src = 1)
version = F.coalesce(F.to_timestamp("updated_at"), legacy_greatest_of_dates)
w = Window.partitionBy("code").orderBy(F.col("_version").desc(), F.col("_src").desc())
r = raw.withColumn("_version", version).withColumn("_rn", F.row_number().over(w)).filter("_rn = 1")

# 4. derived fields
df = (df.withColumn("noches", F.datediff("check_out", "check_in"))
        .withColumn("lead_time_dias", F.datediff("check_in", "fecha_reserva"))
        .withColumn("es_duplicado", F.col("status") == "duplicate")
        .withColumn("es_cancelada", F.col("status").isin("cancelled", "no_show")))

# 5-6. COP with the rate of the booking day, then commission and net
df = (df.join(F.broadcast(fx), ["currency", "fecha_reserva"], "left")
        .withColumn("fx_estimada", F.col("_tasa").isNull())
        .withColumn("tasa_cop", F.coalesce("_tasa", "_tasa_min")))
df = (df.withColumn("total_cop", F.round(F.col("total") * F.col("tasa_cop"), 2))
        .withColumn("comision_cop", F.round(F.col("total_cop") * F.col("comision_pct") / 100, 2))
        .withColumn("neto_cop", F.col("total_cop") - F.col("comision_cop")))

# 7. hours between cancellation and check-in (15:00)
horas = (F.unix_timestamp(F.to_timestamp(F.concat_ws(" ", F.col("check_in").cast("string"), F.lit("15:00:00"))))
         - F.unix_timestamp("cancelada_en")) / 3600
```

### `ocupacion_diaria` (F3-Bestand)

1. Nimmt den neuesten Bestands-Snapshot: Zimmer, verkaufte Zimmer und Überbuchungsgrenze pro Hotel, Zimmertyp und Nacht.
2. Ergänzt **Umbuchungen** pro Nacht und **abgelehnte Zimmer** pro Nacht (jede abgelehnte Buchung wird in ihre Nächte aufgeteilt).
3. Berechnet `disponibles = Zimmer + Überbuchungsgrenze − verkauft`, `ocupacion_pct` und `sobrevendidas` (verkauft über die physischen Zimmer hinaus).

**Warum:** P2 (Überbuchung) und P3 (Umsatz) brauchen eine dichte Nacht-für-Nacht-Sicht auf die Kapazität und darauf, wie oft Überbuchung einen Gast getroffen hat.
**Prüfungen:** `(Hotel, Zimmertyp, Nacht)` eindeutig, keine Nullwerte, und nie mehr verkauft als Zimmer + Überbuchungsgrenze.

Code (`spark_jobs/silver_ocupacion.py`):

```python
# rejected bookings: one row per night they wanted
nights = F.explode(F.sequence(F.to_date("check_in"), F.date_sub(F.to_date("check_out"), 1)))
j = (rej.select("hotel_id", "room_type_id", nights.alias("fecha"), F.col("rooms_count").cast("int").alias("n"))
     .groupBy("hotel_id", "room_type_id", "fecha").agg(F.sum("n").alias("habitaciones_rechazadas")))

out = (base.join(j, KEY, "left").fillna(0, ["reubicadas", "habitaciones_rechazadas"])
       .withColumn("disponibles", F.col("habitaciones") + F.col("limite_sobreventa") - F.col("vendidas"))
       .withColumn("ocupacion_pct", F.round(F.col("vendidas") * 100.0 / F.col("habitaciones"), 2))
       .withColumn("sobrevendidas", F.greatest(F.lit(0), F.col("vendidas") - F.col("habitaciones"))))

# check: never sold above rooms + overbooking limit
bad = out.filter("vendidas > habitaciones + limite_sobreventa OR vendidas < 0").count()
```

### `calendario_hotel` (F6)

1. Liest die Nager-Feiertage (tolerant gegenüber der Form der Antwort) und nimmt das Land aus dem Dateinamen.
2. Baut eine Zeile pro **Hotel × Tag** und markiert `es_festivo` mit dem Feiertagsnamen im Land des Hotels.
3. Ergänzt die **lokalen Events** des Hotels (mehrtägige Events werden auf jeden Tag aufgeteilt; überschneiden sich mehrere, gewinnt die höchste Kategorie: low < medium < high).
4. Ergänzt Jahr, Monat, Wochentag und Wochenende.

**Warum:** Feiertage hängen vom Land ab und Events vom Hotel, daher muss der Kalender pro Hotel sein. Gold verknüpft ihn mit Belegung und Preis (P3).
**Prüfungen:** `(Hotel, Tag)` eindeutig, keine Nullwerte, keine fehlenden Tage.

Code (`spark_jobs/silver_calendario.py`):

```python
cal = (hotels.crossJoin(days)                         # hotel x every day
       .join(holidays, ["pais", "fecha"], "left")       # holiday of the hotel's country
       .withColumn("es_festivo", F.col("nombre_festivo").isNotNull()))

ev = (events.select("hotel_code", "name", "category",
                    F.explode(F.sequence(F.to_date("start_date"), F.to_date("end_date"))).alias("fecha"))
      .withColumn("_rank", rank[F.col("category")])     # low=1, medium=2, high=3
      .groupBy("hotel_code", "fecha")
      .agg(F.concat_ws(" / ", F.collect_set("name")).alias("evento"), F.max("_rank").alias("_rank")))
```

### `resenas` (F5)

1. **Neueste Version** jeder Bewertungs-ID (bearbeitete Bewertungen kommen mit neuerem `updated_at` zurück).
2. **Plattformübergreifende Duplikate:** Derselbe Gast veröffentlicht dieselbe Bewertung Minuten oder Stunden später auf einer anderen Plattform, mit einer Namensvariante und manchmal ohne Schlusspunkt. Gleiches Hotel + Aufenthaltsdatum + Bewertung + normalisierter Text (Kleinbuchstaben, ohne Leerzeichen an den Enden, ohne Satzzeichen am Ende) = dieselbe Bewertung. Die zuerst veröffentlichte bleibt, und `copias_en` / `duplicados` zeigen, wohin sie kopiert wurde.
3. Hotelland aus dem Katalog und **Stimmung** aus der Bewertung: 4–5 positiv, 3 neutral, 1–2 negativ.

**Warum:** Ohne Duplikatentfernung würde eine Meinung mehrfach in die Reputation (P5) eingehen.
**Prüfungen:** `review_id` eindeutig, keine Nullwerte, Bewertung zwischen 1 und 5, bekanntes Hotel. Partitioniert nach `fecha_publicacion`.

Code (`spark_jobs/silver_resenas.py`):

```python
def _norm_text(c):   # "Great stay." == "great stay"
    return F.regexp_replace(F.lower(F.trim(c)), r"[\s.!]+$", "")

w_id = Window.partitionBy("id").orderBy(F.to_timestamp("updated_at").desc())
latest = raw.withColumn("_rn", F.row_number().over(w_id)).filter("_rn = 1")   # newest edit

key = ["hotel_code", "fecha_estadia", "puntaje", "_texto_norm"]
w_dup = Window.partitionBy(*key).orderBy("publicada_en", "review_id")
r = (r.withColumn("_texto_norm", _norm_text(F.col("texto")))
      .withColumn("_rn", F.row_number().over(w_dup))
      .withColumn("copias_en", F.collect_set("plataforma").over(Window.partitionBy(*key))))
original = (r.filter("_rn = 1")                                   # first one published
             .withColumn("copias_en", F.expr("array_remove(copias_en, plataforma)"))
             .withColumn("duplicados", F.size("copias_en")))
sentimiento = (F.when(F.col("puntaje") >= 4, "positivo")
                .when(F.col("puntaje") == 3, "neutro").otherwise("negativo"))
```

### `historico_f1` (F1)

1. Benennt und typisiert die Kaggle-Spalten, bildet Anreisedatum, Nächte, Gäste und Umsatz (`adr × Nächte`, in EUR).
2. Ordnet `market_segment` den Kanaltypen des Projekts zu (Online TA → `ota`, Offline TA/TO und Groups → `agency`, Corporate und Aviation → `corporate`, Direct und Complementary → `direct`).
3. Dieselben Vorlaufklassen wie `cancelaciones`.
4. Verwirft Zeilen ohne Gäste, ohne Nächte, mit negativem ADR oder ohne Anreisedatum und zählt sie.

**Warum:** F1 ist die lange Historie (2015–2017), die zeigt, wie Stornierungen von Vorlaufzeit und Anzahlungsart abhängen, was die Live-Daten nicht haben. Beträge bleiben in EUR, weil die Kurse erst 2026 beginnen.

Code (`spark_jobs/silver_f1.py`):

### Wie jeder Job Silver schützt

Alle Silver-Jobs folgen denselben drei Schritten: **transformieren → prüfen → überschreiben**. Die Prüfungen liegen in einem Modul:

```python title="spark_jobs/quality.py"
class QualityError(Exception): ...

def unique(df, name, keys):
    dup = df.groupBy(*keys).count().filter("count > 1").count()
    if dup:
        raise QualityError(f"{name}: {dup} duplicated keys {keys}")

# every job:  transform -> check(out) -> out.write.mode("overwrite").parquet(...)
# if check() raises, the Airflow task fails and yesterday's Parquet stays untouched
```

## Wie lange es dauert

Die gesamte Silver-Schicht läuft in etwa 2 Minuten. `silver_reservas_daily` läuft außerdem nach jeder stündlichen Bronze-Kopie, Silver liegt also etwa eine Stunde hinter Neon.
