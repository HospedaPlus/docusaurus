# <SourceTitleIcon icon="file" tone="sky" />F4 · Dateien klassischer Reisebüros <SourceType>CSV- / Excel-Dateien</SourceType>

Simulierte wöchentliche Dateien mit den Buchungen, die klassische Reisebüros verkaufen. Klassische Reisebüros sind weder über eine API noch über einen Ereignisstrom angebunden: Sie schicken einmal pro Woche eine Tabelle. Das Team simuliert diese Dateien mit einem Generator in Python.

| Zugriffsmethode | CSV-Dateien, eine pro Reisebüro |
| Häufigkeit | Wöchentlich |
| Volumen | 15 Reisebüros, ~183 Buchungen pro Woche |

## Zugriff

Jedes Reisebüro liefert eine CSV-Datei pro Woche, und die Plattform lädt die Dateien im Batch. In der Simulation schreibt der Generator die 15 Wochendateien nach `output/f4_agency_files/`, zusammen mit einer Zusammenfassung dessen, was er erzeugt hat.

## Wie die Daten erzeugt werden

Der Generator ist das Modul `buenavista_csv.f4_generator` im Repository [buenavista-csv](https://github.com/HospedaPlus/buenavista-csv). Er erstellt eine Datei pro Reisebüro nach diesen Regeln:

- **Reproduzierbar.** Er verwendet einen festen Seed (standardmäßig `7`), daher erzeugt ein erneuter Lauf genau dieselben Dateien.
- **Normale Buchungen.** Jedes Reisebüro erhält standardmäßig 12 Buchungen. Jede Buchung hat ein zufälliges Hotel von `hotel-001` bis `hotel-028`, eine Anreise zwischen dem 1. November 2026 und dem 30. Januar 2027, einen Aufenthalt von 1 bis 6 Nächten, einen Zimmertyp (`SINGLE`, `DOUBLE`, `TWIN` oder `SUITE`), eine Währung (`EUR` oder `USD`) und einen Betrag zwischen 80 und 2.000.
- **Feste Provision.** Jede Buchung hat eine Provision von `0.10`, die 10 %, die klassische Reisebüros berechnen.
- **Buchungs-IDs.** Die IDs folgen dem Muster `AG<Reisebüro>-<Zähler>`, zum Beispiel `AG01-00001`. Der Zähler läuft über alle Reisebüros weiter, daher wiederholt sich eine ID nie.
- **Zwei Layouts.** Die Reisebüros wechseln zwischen zwei Spaltenlayouts, um zu simulieren, dass jedes Reisebüro sein eigenes Format hat. Die 8 Reisebüros mit ungerader Nummer verwenden Layout B, die 7 mit gerader Nummer Layout A.

### Parameter

| Parameter | Standard | Beschreibung |
| --- | --- | --- |
| `--seed` | `7` | Seed des Zufallsgenerators. |
| `--bookings-per-agency` | `12` | Normale Buchungen pro Reisebüro. |
| `--duplicate-count` | `3` | Aus F2 kopierte Buchungen, um kanalübergreifende Duplikate zu erzeugen. |
| `--missing-currency-rate` | `0.10` | Anteil der Buchungen ohne Währung, zwischen `0.0` und `1.0`. |
| `--f2-events` | `data/f2_reference/events.jsonl` | F2-Ereignisse, aus denen die Duplikate stammen. |
| `--output-dir` | `output/f4_agency_files` | Ordner, in den die Dateien geschrieben werden. |

### Eingebaute Datenfehler

Der Generator fügt zwei der Datenqualitätsfehler ein, mit denen die Plattform umgehen muss:

- **Fehlende Währung.** Bei etwa 10 % der Buchungen ist das Feld `currency` leer. Mit dem Standard-Seed haben 14 der 183 Buchungen keine Währung.
- **Kanalübergreifende Duplikate.** Der Generator liest `reservation.created`-Ereignisse aus [F2](./f2-channel-manager-events.mdx) und kopiert einige davon in die Dateien der Reisebüros. Die Kopie behält Hotel, Abreise, Zimmertyp, Währung und Betrag, erhält aber eine neue Reisebüro-ID, eine um −1, 0 oder +1 Tag verschobene Anreise und meist einen leicht abweichenden Gästenamen. Der Generator ändert den Namen auf eine dieser Arten: Vor- und Nachname vertauscht (`Ferreira Diego`), Nachname auf den Anfangsbuchstaben gekürzt (`Diego F.`), zwei Buchstaben vertauscht (`Diego Ferriera`) oder Nachname kleingeschrieben (`Diego ferreira`). Mit den Standardwerten erhalten die ersten drei Reisebüros je ein Duplikat.

F2-Ereignisse enthalten keinen Gästenamen, daher leitet der Generator aus jeder `reservation_id` mit einem eigenen Seed einen Namen ab. So lassen sich die ursprüngliche F2-Buchung und ihre F4-Kopie über den Namen vergleichen.

| `agency_booking_id` | `booking_ref` | Text | Buchungs-ID im Reisebüro, zum Beispiel `AG01-00001`. |

| `hotel_id` | `hotel_id` | Text | Hotelcode, von `hotel-001` bis `hotel-028`. |
| `check_in` | `checkin_date` | Datum `YYYY-MM-DD` | Anreisedatum. |

### Zusammenfassung der Erzeugung

`_generation_summary.json` beschreibt jeden Lauf. Mit den Standardwerten meldet sie 183 Zeilen, davon 14 ohne Währung, und die 3 Duplikate mit der F2-Buchung, aus der sie stammen:

    "SolyMar Tours": { "file": "solymar_tours_week.csv", "rows": 13, "layout": "A" }
  },
  "duplicates_created": [
    {
      "agency": "ViajaFacil",

Das sind die 3 Duplikate des Standardlaufs:

| Datei des Reisebüros | Reisebüro-ID | F2-Buchung | F2-Kanal | Gast in F2 | Gast in F4 | Verschiebung der Anreise |
| --- | --- | --- | --- | --- | --- | --- |

`warning` wird gefüllt, wenn die F2-Datei fehlt, keine `reservation.created`-Ereignisse enthält oder weniger Ereignisse enthält als angeforderte Duplikate.

### Prüfung der Ausgabe

Das Repository enthält auch einen Validator, `buenavista_csv.validator`, der die Dateien prüft, ohne sie zu verändern. Er erkennt das Layout jeder Datei an ihrer Kopfzeile und meldet jeden gefundenen Fehler nach Typ, etwa `MISSING_CURRENCY` oder `CROSS_CHANNEL_DUPLICATE`. Beim Standardlauf lautet das Ergebnis `PASSED_WITH_CATALOGUED_DEFECTS`: Die 15 Dateien haben eine gültige Struktur, und er findet 14 Buchungen ohne Währung und 3 Duplikate. Der Bericht wird nach `output/validation_reports/quality_validation_report.json` geschrieben.

<AccessNote icon="alert" title="Bekannte Datenqualitätsprobleme">

- Die Reisebüros verwenden zwei unterschiedliche Layouts, daher müssen die Dateien vereinheitlicht werden, bevor sie zusammengeführt werden.
- Etwa 10 % der Buchungen haben keine Währung, daher lässt sich ihr Betrag erst umrechnen, wenn die Währung bekannt ist.
- Einige Buchungen existieren bereits über F2, mit leichten Abweichungen im Gästenamen und einer um bis zu einen Tag verschobenen Anreise. Erscheinen derselbe Gast, dasselbe Hotel und dieselben Daten (±1 Tag) in zwei Kanälen, wird die Buchung markiert, und es gilt die Buchung aus dem Kanal mit der niedrigsten Provision.

</AccessNote>

## Lokal ausführen

Mit Python 3.11 oder neuer und [uv](https://docs.astral.sh/uv/) klonst du das Repository und startest den Generator:

```bash
git clone https://github.com/HospedaPlus/buenavista-csv.git
cd buenavista-csv
uv sync --extra test
uv run -m buenavista_csv.f4_generator --seed 7 --bookings-per-agency 12 --duplicate-count 3 --missing-currency-rate 0.10
```

Der Befehl gibt aus, wie viele Dateien, Zeilen, Duplikate und Buchungen ohne Währung er erzeugt hat. Um die Dateien zu prüfen, führe `uv run -m buenavista_csv.validator` aus.

<Note>

Die Dateien werden bei jedem Lauf neu erzeugt. Mit demselben Seed und denselben Parametern ist die Ausgabe identisch, daher lassen sich die Beispielzeilen auf dieser Seite reproduzieren.

</Note>
