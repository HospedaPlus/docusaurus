# <SourceTitleIcon icon="file" tone="sky" />F4 · Dateien klassischer Reisebüros <SourceType>CSV- / Excel-Dateien</SourceType>

Simulierte Wochendateien mit den Buchungen, die klassische Reisebüros verkaufen. Diese Reisebüros sind weder per API noch per Event-Stream angebunden: Jedes schickt einmal pro Woche eine Tabelle, in seinem eigenen Format. Das Team simuliert die Dateien mit einem Python-Generator.

<AccessTable>

| Eigenschaft | Wert |
| --- | --- |
| Typ | Simulierte Dateien, vom Team erzeugt |
| Speicherort | Service `f4-weekly` auf AWS EC2 · Quellcode in [HospedaPlus/hospedaplus-csv](https://github.com/HospedaPlus/hospedaplus-csv) |
| Zugriffsmethode | Eine CSV- oder Excel-Datei pro Reisebüro und ISO-Woche, z. B. `AG07_2026-W45.xlsx` |
| Frequenz | Wöchentlich, jeden Montag 06:00 UTC |
| Volumen | 15 Reisebüros, ~183 Buchungen pro Woche |
| Zuerst gespeichert in | **S3 Bronze, direkt** (Rohdateien, `bronze/f4_agencias/semana=YYYY-Www/`) + **Neon** (jede Buchung, über `operation.reservar()`) |

## Simulation

Der Service `f4-weekly` (`python -m buenavista_csv.weekly`, Docker Compose) verarbeitet die aktuelle Woche direkt beim Start und danach jeden Montag um 06:00 UTC:

1. **Erzeugt** die 15 Dateien der Woche (`buenavista_csv.f4_generator`). Jedes Reisebüro `AG01`…`AG15` bekommt standardmäßig 12 Buchungen, mit einem Hotel aus dem gemeinsamen Katalog (`HP-CO-001`…), Daten relativ zur Woche, Zimmertyp, Anzahl Zimmer, Erwachsene und Kinder, Erstattungskennzeichen, dem Gast (`guest_ref` `G-0000001`…, gemeinsam mit F2 und F3), dem Betrag nach den Katalograten in der Währung des Hotels (`COP`, `MXN`, `BRL`, `EUR`, `USD`) und 10 % Provision.
2. **Validiert** die Dateien (`buenavista_csv.validator`), ohne sie zu ändern.
3. **Bucht** jede Zeile in Neon mit `operation.reservar('AGxx', …)`, sodass Reisebürobuchungen Zimmer aus demselben Bestand wie die anderen Kanäle belegen.
4. **Lädt** die Rohdateien nach S3 hoch.

Er ist reproduzierbar (Seed `7`) und kann gefahrlos neu gestartet werden: Eine vorhandene Woche wird nicht erneut erzeugt, und `reservar()` ignoriert eine Buchung, die es schon hat.

### Frequenz und Volumen

| Variable | Standard | Bedeutung |
| --- | --- | --- |
| `F4_RUN_WEEKDAY`, `F4_RUN_HOUR_UTC` | `0`, `6` | Montag, 06:00 UTC. |
| `F4_BOOKINGS_PER_AGENCY` | `12` | Reguläre Buchungen pro Reisebüro: 15 × 12 = 180. |
| `F4_DUPLICATE_RATE` | `0.10` | Zusätzliche, aus F2 kopierte Buchungen (oder `F4_DUPLICATE_COUNT` für eine feste Anzahl). |
| `F4_MISSING_CURRENCY_RATE` | `0.10` | Anteil der Buchungen ohne Währung. |

Die Woche `2026-W45` ergab 183 Zeilen: 21 ohne Währung und 3 Duplikate von F2-Buchungen. Der Neon-Import bestätigte 183 Buchungen mit 0 Überbuchung.

## Speicherort

<F4Flow />

Die Dateien gehen **direkt nach S3**, unverändert, weil es Dateien sind und der Lake die Rohkopie behält. Die darin enthaltenen Buchungen gehen nach **Neon**, weil sie echte Zimmer belegen. Der Airflow-DAG `bronze_f4_agencias` läuft eine Stunde später und prüft, ob die 15 Dateien der Woche in S3 liegen.

Neben den Dateien meldet `_generation_summary.json` die Zeilen pro Datei, die erzeugten Duplikate und die Zeilen ohne Währung, und `_load_report.json` das Ergebnis von `reservar()` für jede Zeile.

<AccessNote icon="alert" title="Bekannte Datenqualitätsprobleme">

- Drei Layouts mit unterschiedlichen Namen, Reihenfolgen und Einheiten, daher müssen die Dateien vereinheitlicht werden, bevor sie zusammengeführt werden.
- Etwa 10 % der Buchungen haben keine Währung.
- Etwa 10 % der Buchungen existieren bereits in F2 (aus Neon mit `etl_reader` gelesen): gleiches Hotel, gleicher Zimmertyp und Check-out, ein um bis zu einen Tag verschobener Check-in und ein leicht abweichender Gastname (vertauscht, nur Initiale, zwei Buchstaben vertauscht oder kleingeschrieben).

</AccessNote>

## Lokal ausführen

```bash
# Lädt das F4-Repository herunter
git clone https://github.com/HospedaPlus/hospedaplus-csv.git
# Wechselt in seinen Ordner
cd hospedaplus-csv
# Erstellt deine .env aus dem Beispiel (optional: NEON_READ_URL, NEON_DATABASE_URL, F4_S3_BUCKET)
cp .env.example .env
# Baut das Image und startet den Wochenjob im Hintergrund
docker compose up -d --build
# Verfolgt seine Logs (Strg+C zum Beenden)
docker compose logs -f f4-weekly
```
