# Datenquellen

HospedaPlus Revenue integriert sieben Datenquellen, von F1 bis F7. F1, F6 und F7 sind echte öffentliche Daten. F2 bis F5 sind **simuliert**: Das Team hat für jede einen Generator gebaut, der ständig auf AWS läuft und Daten in der Frequenz und dem Volumen erzeugt, die das Projekt verlangt.

## Wo jede Quelle zuerst gespeichert wird

<SourcesFlow />

- **Zuerst Neon (F2, F3, F6-Veranstaltungen, F4-Buchungen).** Das sind operative Daten: Jede Buchung, egal aus welchem Kanal, läuft über dieselbe Funktion `operation.reservar()`, daher teilen sich alle Kanäle einen Bestand und es gibt nie eine Überbuchung. Die Pipeline liest Neon mit einer Nur-Lese-Rolle und kopiert die Änderungen stündlich nach S3, dazu jede Nacht einen vollständigen Snapshot.
- **Zuerst S3 (F1, F4-Dateien, F6-Feiertage, F7).** Das sind Dateien oder öffentliche APIs ohne operative Logik, daher gehen sie unverändert nach `s3://…/bronze/`.
- **F5** speichert ihre Bewertungen in der eigenen Datenbank der API, wie es eine echte Plattform tun würde; die Pipeline liest die API stündlich.

<Note>
  **Daten-Seed.** Alle Daten der simulierten Quellen erzeugt Code, der in jedem Repository versioniert ist. Die Generatoren verwenden einen festen Zufalls-Seed, damit die Daten reproduzierbar sind, sind idempotent, erlauben die Wahl des Volumens (kleiner Entwicklungsmodus oder vollständiger Modus), halten die referenzielle Integrität über einen gemeinsamen Katalog (überall dieselben Codes für Hotel, Zimmertyp, Kanal und Gast), injizieren die bekannten Qualitätsprobleme mit einer konfigurierbaren Rate und laufen sowohl lokal mit Docker als auch auf AWS.
</Note>

<AccessNote icon="alert" title="Bekannte Datenqualitätsprobleme">

Die Daten kommen mit folgenden Fehlern an, und die simulierten Quellen injizieren sie absichtlich:

- F1 enthält `"NULL"` als Text in den Feldern agent und company sowie negative oder extreme ADR-Werte.
- Buchungen mit null Erwachsenen, null Kindern und null Babys (F1, F3).
- Abreisedaten vor dem Anreisedatum (F3).
- Fehlende Währungen in den Reisebürodateien (F4, ~10 %).
- Kanalübergreifend doppelte Buchungen mit leichten Unterschieden im Gastnamen (F4, ~10 %) und plattformübergreifend doppelte Bewertungen (F5, ~5 %).
- Änderungs-Events, die vor dem Erstellungs-Event ankommen (F2, ~5 %).

</AccessNote>
