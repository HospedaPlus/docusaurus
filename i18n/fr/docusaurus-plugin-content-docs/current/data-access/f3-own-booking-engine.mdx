# <SourceTitleIcon icon="database" tone="teal" />F3 · Moteur de réservation propre <SourceType>Base de données PostgreSQL</SourceType>

Base opérationnelle simulée du moteur de réservation propre de la chaîne. Elle contient le catalogue des hôtels, l'inventaire des chambres, les tarifs par saison et les réservations directes et entreprises. C'est aussi là qu'aboutissent les réservations des autres canaux (OTA de F2, agences de F4), via une seule fonction de réservation.

## Simulation

Deux tâches, toutes deux avec l'image du dépôt :

1. **Seed** (`python -m seed all`). Charge le catalogue, 365 nuits d'inventaire et de tarifs à venir, 60 000+ clients et l'historique des réservations (`dev` : 90 nuits passées, `full` : 400). Les hôtels urbains reçoivent plus d'arrivées du dimanche au mardi, les resorts le week-end, la haute saison amène plus de clients et l'occupation future baisse à mesure qu'on regarde loin, comme dans une vraie courbe de réservation. Même graine + même date de début = les mêmes données, ligne par ligne.
2. **Simulateur** (`python -m seed simulate`). Tourne en permanence sur AWS EC2. Chaque minute, il réserve un séjour direct ou entreprise avec `operation.reservar()` (`rejected` quand l'hôtel est complet), annule de temps en temps une réservation avec `operation.cancelar()`, continue d'injecter des lignes défectueuses et, une fois par jour, met en vente une nouvelle nuit à 365 jours.

### Fréquence et volume

- `SIM_BOOKINGS_PER_MIN=1` (réglé ainsi sur l'EC2) : environ 1 440 tentatives de réservation par jour, donc F3 est une source continue et le pipeline trouve toujours de nouvelles lignes.
- `SEED_MODE=full` charge l'historique complet ; `dev` est une petite version pour le développement.
- `python -m seed check` exécute 24 contrôles de santé et d'intégrité et ne réussit que si tous réussissent (comptages, catalogue, pas d'orphelins, inventaire = réservations confirmées, aucune réservation antérieure au jour où elle a été faite).

## Stockage

<F3Flow />

Neon est le stockage opérationnel. Le lac reçoit F3 de deux façons : toutes les heures, les lignes modifiées depuis la dernière exécution (`reservations.updated_at` est mis à jour par un trigger à chaque changement), et chaque nuit un instantané complet des réservations, anomalies, inventaire, relogements et refus, pris dans une seule transaction et marqué par `_SUCCESS`. La table `guests` n'est jamais copiée : les données personnelles restent dans Neon.

## Comment y accéder

| Propriété | Valeur |
| --- | --- |
| Hôte | Endpoint Neon de la branche `production` (hôte avec `-pooler` pour les clients, hôte direct pour le seed) |
| Port | `5432` |
| Base de données | `hospedaplus` |
| SSL | `sslmode=require` |

Chaque client utilise son propre rôle. Demandez les chaînes de connexion à l'équipe : elles ne sont jamais écrites dans le dépôt ni sur ce site.

| Rôle | Utilisé par | Peut |
| --- | --- | --- |
| `hospedaplus_owner` | Seed et migrations | Tout. |
| `app_writer` | Consommateur F2, simulateur F3, chargeur F4, réécriture du pipeline | Lire et écrire les données ; ne modifie pas le schéma. |
| `etl_reader` | Worker bronze d'Airflow, équipe (DBeaver, psql) | Lecture seule. |

## Contenu

| Table | Contenu |
| --- | --- |
| `hotels`, `room_types`, `rooms` | 28 hôtels (`HP-CO-001`…) avec fuseau horaire et devise ; `SINGLE`, `DOUBLE`, `TWIN`, `SUITE` ; 4 000 chambres. |
| `channels` | 21 canaux de vente avec leur commission (RN-02). |
| `rates` | Prix par nuit par hôtel, type de chambre et saison (RN-05). |
| `inventory` | Chambres totales, vendues et limite de surréservation par hôtel, type de chambre et nuit (RN-03). |
| `guests` | Clients `G-0000001`…, avec le même `guest_ref` et niveau de fidélité que F2 (données personnelles, RN-11). |
| `reservations` | Réservations de tous les canaux, avec annulations, no-shows et pénalités. |
| `reservation_anomalies` | Lignes avec des problèmes de qualité connus, mises à part volontairement. |
| `reservation_rejections`, `relocations` | Réservations refusées faute de chambres (RN-04), réservations relogées. |
| `cancellation_policies`, `cancellation_rate_by_lead` | Politiques par canal (RN-07) ; taux d'annulation réécrits par le pipeline. |
| `local_events` | Les événements locaux de F6. |

<AccessNote icon="alert" title="Problèmes de qualité de données connus">

Les lignes qui violeraient les contraintes vont dans `reservation_anomalies` (2 % chacune par défaut, `SEED_ZERO_GUESTS_RATE` et `SEED_INVALID_DATES_RATE`), dans le seed comme dans le simulateur continu :

- Réservations avec zéro client.
- Dates de départ antérieures à la date d'arrivée.

</AccessNote>
