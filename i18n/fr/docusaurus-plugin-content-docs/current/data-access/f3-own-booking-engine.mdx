## Comment y accéder

La base de données partagée de l'équipe tourne sur Neon (PostgreSQL 16 managé), chargée en mode `full` et vérifiée avec `python -m seed check`.

| Propriété | Valeur |
| --- | --- |
| Hôte | `ep-divine-cake-b48dsbxg-pooler.c-6.us-east-2.aws.neon.tech` (pooled) · `ep-divine-cake-b48dsbxg.c-6.us-east-2.aws.neon.tech` (direct) |
| Port | `5432` |
| Base de données | `hospedaplus` |
| SSL | `sslmode=require`, `channel_binding=require` |

### Rôles

Chaque client se connecte avec son propre rôle et n'a que l'accès dont il a besoin : un bug ou une URL divulguée à un endroit ne peut pas effacer les données.

| Rôle | Utilisé par | Peut |
| --- | --- | --- |
| `hospedaplus_owner` | Seed (`init`, `seed`, rechargements) | Tout. |
| `hospedaplus_api` | FastAPI, consommateurs Kafka | Lire toutes les tables ; mettre à jour `inventory` ; insérer et mettre à jour `reservations` et `guests` ; jamais supprimer. |
| `hospedaplus_reader` | Équipe (DBeaver, psql), worker bronze d'Airflow | Lecture seule. |

### Chaînes de connexion

Utilisez `hospedaplus_reader` sauf si vous devez écrire.

```text title="hospedaplus_reader"
postgresql://<ROLE>:<PASSWORD>@<NEON_HOST>/<DATABASE>?sslmode=require&channel_binding=require
```

```text title="hospedaplus_api"
postgresql://<ROLE>:<PASSWORD>@<NEON_HOST>/<DATABASE>?sslmode=require&channel_binding=require
```

```text title="hospedaplus_owner"
postgresql://<ROLE>:<PASSWORD>@<NEON_HOST>/<DATABASE>?sslmode=require&channel_binding=require
```

Par exemple, avec `psql` :

```bash
psql "postgresql://<ROLE>:<PASSWORD>@<NEON_HOST>/<DATABASE>?sslmode=require&channel_binding=require"
```

### Hôte pooled ou direct

L'hôte `-pooler` place PgBouncer devant la base : beaucoup de connexions clientes partagent quelques connexions réelles. Il fonctionne en mode transaction, donc tout ce qui a besoin d'une session fixe (un `SET` durable, des tables temporaires, de longs chargements en masse) passe par l'hôte direct.

| Client | Hôte |
| --- | --- |
| FastAPI, consommateurs Kafka, Airflow | Pooled |
| Seed (`init`, chargement `COPY`) | Direct (le même hôte sans `-pooler`) |
| Équipe dans DBeaver ou psql | Pooled |

- Dans DBeaver ou pgAdmin, créez une connexion PostgreSQL avec les informations ci-dessus et réglez le mode SSL sur `require`.
- La base de données se met en veille après 5 minutes d'inactivité et se réveille à la requête suivante : la première requête peut donc prendre quelques secondes.
- Pour exécuter le seed en local, le dépôt inclut un fichier Docker Compose avec PostgreSQL 16 sur le port `5437`, pour ne jamais entrer en conflit avec Neon.

## Contenu

| Table | Contenu |
| --- | --- |
| `hotels` | 28 hôtels urbains et resorts, avec code (`HP-CO-001`…), ville, pays, fuseau horaire et devise. |
| `room_types` | `SINGLE`, `DOUBLE`, `TWIN` et `SUITE`, avec leur nombre maximal de clients. |
| `rooms` | Les 4 000 chambres physiques, par hôtel et type de chambre. |
| `channels` | 21 canaux de vente avec leur commission (RN-02). |
| `rates` | Prix par nuit par hôtel, type de chambre et saison (`LOW`, `MID`, `HIGH`, RN-05). |
| `inventory` | Chambres totales et disponibles par hôtel, type de chambre et nuit. |
| `guests` | Données personnelles des clients, pseudonymisées avant l'analyse (RN-11). |
| `reservations` | Réservations directes et entreprises, avec annulations et no-shows. |
| `reservation_anomalies` | Lignes avec les problèmes de qualité de données connus, mises à part volontairement. |

Les hôtels, types de chambre et canaux viennent du **catalogue partagé** que F2, F4 et F5 lisent aussi, afin que le pipeline puisse croiser toutes les sources.

## Seed de données

Toutes les données sont générées par le seed du dépôt (`python -m seed`), jamais chargées à la main ni depuis un dump. Le seed :

- **Est reproductible.** Le même seed et la même date de début produisent les mêmes données, ligne par ligne.
- **Est idempotent.** Il remplace les données en une seule transaction : l'exécuter plusieurs fois laisse une seule copie, et en cas d'échec les données précédentes restent intactes.
- **Propose deux volumes.** Le mode `dev` couvre 90 nuits passées et 30 futures ; le mode `full` couvre 400 passées et 180 futures.
- **Simule une demande réaliste.** Les hôtels urbains reçoivent plus d'arrivées du dimanche au mardi, les resorts le week-end, et la haute saison amène plus de clients.
- **Ne fait jamais de surréservation.** Le générateur refuse une réservation quand le type de chambre est complet, et la base rejette `available_rooms < 0`.
- **Rejette les réservations dans le passé.** Un trigger rejette toute réservation dont le check-in est antérieur au jour où elle a été faite.
- **Est sûr par défaut.** Les commandes destructives s'arrêtent sur les bases distantes, sauf avec `--allow-remote`.
- **Se vérifie lui-même.** `python -m seed check` exécute 21 contrôles de santé et d'intégrité et ne réussit que si tous réussissent.

| Commande | Ce qu'elle fait |
| --- | --- |
| `python -m seed init` | Crée les tables et les index. |
| `python -m seed seed` | Vide les tables et charge un nouveau jeu de données. |
| `python -m seed check` | Exécute les contrôles de santé et d'intégrité (lecture seule). |
| `python -m seed all` | `init` + `seed` + `check`. |

<AccessNote icon="alert" title="Problèmes de qualité de données connus">

Les lignes qui casseraient les contraintes vont dans `reservation_anomalies` au lieu de `reservations` (2 % chacune par défaut, configurable) :

- Réservations avec zéro client.
- Dates de check-out antérieures à la date de check-in.

</AccessNote>
