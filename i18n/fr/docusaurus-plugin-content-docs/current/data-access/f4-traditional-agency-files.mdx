# <SourceTitleIcon icon="file" tone="sky" />F4 · Fichiers des agences traditionnelles <SourceType>Fichiers CSV / Excel</SourceType>

Fichiers hebdomadaires simulés contenant les réservations vendues par les agences de voyages traditionnelles. Les agences traditionnelles ne se connectent ni par une API ni par un flux d'événements : elles envoient un tableur une fois par semaine. L'équipe simule ces fichiers avec un générateur écrit en Python.

## Comment y accéder

Chaque agence livre un fichier CSV par semaine, et la plateforme charge les fichiers en batch. Dans la simulation, le générateur écrit les 15 fichiers hebdomadaires dans `output/f4_agency_files/`, avec un résumé de ce qu'il a généré.

## Génération des données

Le générateur est le module `buenavista_csv.f4_generator` du dépôt [buenavista-csv](https://github.com/HospedaPlus/buenavista-csv). Il crée un fichier par agence selon ces règles :

- **Reproductible.** Il utilise une graine fixe (`7` par défaut), donc une nouvelle exécution produit exactement les mêmes fichiers.
- **Réservations normales.** Chaque agence reçoit 12 réservations par défaut. Chaque réservation a un hôtel aléatoire de `hotel-001` à `hotel-028`, une arrivée entre le 1er novembre 2026 et le 30 janvier 2027, un séjour de 1 à 6 nuits, un type de chambre (`SINGLE`, `DOUBLE`, `TWIN` ou `SUITE`), une devise (`EUR` ou `USD`) et un montant entre 80 et 2 000.
- **Commission fixe.** Toutes les réservations portent une commission de `0.10`, les 10 % que facturent les agences traditionnelles.
- **Identifiants de réservation.** Les identifiants suivent le modèle `AG<agence>-<compteur>`, par exemple `AG01-00001`. Le compteur continue d'augmenter d'une agence à l'autre, donc un identifiant n'est jamais répété.
- **Deux formats.** Les agences alternent entre deux formats de colonnes pour simuler que chaque agence a le sien. Les 8 agences de numéro impair utilisent le format B et les 7 de numéro pair le format A.

### Paramètres

| Paramètre | Par défaut | Description |
| --- | --- | --- |
| `--seed` | `7` | Graine du générateur aléatoire. |
| `--bookings-per-agency` | `12` | Réservations normales par agence. |
| `--duplicate-count` | `3` | Réservations copiées depuis F2 pour créer des doublons entre canaux. |
| `--missing-currency-rate` | `0.10` | Part des réservations sans devise, entre `0.0` et `1.0`. |
| `--f2-events` | `data/f2_reference/events.jsonl` | Événements F2 utilisés comme origine des doublons. |
| `--output-dir` | `output/f4_agency_files` | Dossier où les fichiers sont écrits. |

### Défauts injectés

Le générateur ajoute deux des défauts de qualité de données que la plateforme doit gérer :

- **Devise manquante.** Environ 10 % des réservations ont le champ `currency` vide. Avec la graine par défaut, 14 des 183 réservations n'ont pas de devise.
- **Doublons entre canaux.** Le générateur lit des événements `reservation.created` de [F2](./f2-channel-manager-events.mdx) et en copie certains dans les fichiers des agences. La copie garde l'hôtel, la date de départ, le type de chambre, la devise et le montant, mais reçoit un nouvel identifiant d'agence, une arrivée décalée de −1, 0 ou +1 jour et, en général, un nom de client légèrement différent. Le générateur modifie le nom d'une de ces façons : prénom et nom inversés (`Ferreira Diego`), nom réduit à son initiale (`Diego F.`), deux lettres interverties (`Diego Ferriera`) ou nom en minuscules (`Diego ferreira`). Avec les valeurs par défaut, les trois premières agences reçoivent chacune un doublon.

Les événements F2 ne contiennent pas le nom du client, donc le générateur en dérive un à partir de chaque `reservation_id` avec sa propre graine. Ainsi, la réservation F2 d'origine et sa copie F4 peuvent être comparées par le nom.

| Fichier de l'agence | Identifiant agence | Réservation F2 | Canal F2 | Client dans F2 | Client dans F4 | Décalage de l'arrivée |

### Validation de la sortie

Le dépôt inclut aussi un validateur, `buenavista_csv.validator`, qui vérifie les fichiers sans les modifier. Il reconnaît le format de chaque fichier par son en-tête et signale chaque défaut trouvé par type, comme `MISSING_CURRENCY` ou `CROSS_CHANNEL_DUPLICATE`. Avec l'exécution par défaut, le résultat est `PASSED_WITH_CATALOGUED_DEFECTS` : les 15 fichiers ont une structure valide, et il trouve 14 réservations sans devise et 3 doublons. Le rapport est écrit dans `output/validation_reports/quality_validation_report.json`.

<AccessNote icon="alert" title="Problèmes de qualité de données connus">

- Les agences utilisent deux formats différents, donc les fichiers doivent être unifiés avant d'être combinés.
- Environ 10 % des réservations n'ont pas de devise, donc leur montant ne peut pas être converti tant que la devise n'est pas connue.
- Certaines réservations existent déjà via F2, avec de légères différences dans le nom du client et une arrivée décalée d'un jour au plus. Lorsque le même client, le même hôtel et les mêmes dates (±1 jour) apparaissent dans deux canaux, la réservation est signalée et c'est celle du canal le moins commissionné qui prévaut.

</AccessNote>

## L'exécuter en local

Avec Python 3.11 ou plus et [uv](https://docs.astral.sh/uv/), clonez le dépôt et lancez le générateur :

```bash
git clone https://github.com/HospedaPlus/buenavista-csv.git
cd buenavista-csv
uv sync --extra test
uv run -m buenavista_csv.f4_generator --seed 7 --bookings-per-agency 12 --duplicate-count 3 --missing-currency-rate 0.10
```

La commande affiche combien de fichiers, de lignes, de doublons et de réservations sans devise elle a générés. Pour vérifier les fichiers, lancez `uv run -m buenavista_csv.validator`.

<Note>

Les fichiers sont régénérés de zéro à chaque exécution. Avec la même graine et les mêmes paramètres, la sortie est identique, donc les lignes d'exemple de cette page peuvent être reproduites.

</Note>
