# <SourceTitleIcon icon="file" tone="sky" />F4 · Fichiers des agences traditionnelles <SourceType>Fichiers CSV / Excel</SourceType>

Fichiers hebdomadaires simulés avec les réservations vendues par les agences de voyage traditionnelles. Ces agences ne se connectent ni par API ni par flux d'événements : chacune envoie un tableur une fois par semaine, dans son propre format. L'équipe simule les fichiers avec un générateur Python.

<AccessTable>

| Propriété | Valeur |
| --- | --- |
| Type | Fichiers simulés, générés par l'équipe |
| Emplacement | Service `f4-weekly` sur AWS EC2 · code source dans [HospedaPlus/hospedaplus-csv](https://github.com/HospedaPlus/hospedaplus-csv) |
| Méthode d'accès | Un fichier CSV ou Excel par agence et par semaine ISO, par exemple `AG07_2026-W45.xlsx` |
| Fréquence | Hebdomadaire, chaque lundi à 06:00 UTC |
| Volume | 15 agences, ~183 réservations par semaine |
| Stockée d'abord dans | **S3 bronze, directement** (fichiers bruts, `bronze/f4_agencias/semana=YYYY-Www/`) + **Neon** (chaque réservation, via `operation.reservar()`) |

## Simulation

Le service `f4-weekly` (`python -m buenavista_csv.weekly`, Docker Compose) traite la semaine en cours dès son démarrage, puis chaque lundi à 06:00 UTC :

1. **Génère** les 15 fichiers de la semaine (`buenavista_csv.f4_generator`). Chaque agence `AG01`…`AG15` reçoit 12 réservations par défaut, avec un hôtel du catalogue partagé (`HP-CO-001`…), des dates relatives à la semaine, le type de chambre, le nombre de chambres, d'adultes et d'enfants, l'indicateur remboursable, le client (`guest_ref` `G-0000001`…, partagé avec F2 et F3), le montant selon les tarifs du catalogue dans la devise de l'hôtel (`COP`, `MXN`, `BRL`, `EUR`, `USD`) et une commission de 10 %.
2. **Valide** les fichiers (`buenavista_csv.validator`), sans les modifier.
3. **Réserve** chaque ligne dans Neon avec `operation.reservar('AGxx', …)`, ainsi les réservations d'agence prennent des chambres dans le même inventaire que les autres canaux.
4. **Envoie** les fichiers bruts dans S3.

Il est reproductible (graine `7`) et peut être redémarré sans risque : une semaine existante n'est pas régénérée, et `reservar()` ignore une réservation qu'il a déjà.

### Fréquence et volume

| Variable | Par défaut | Signification |
| --- | --- | --- |
| `F4_RUN_WEEKDAY`, `F4_RUN_HOUR_UTC` | `0`, `6` | Lundi, 06:00 UTC. |
| `F4_BOOKINGS_PER_AGENCY` | `12` | Réservations régulières par agence : 15 × 12 = 180. |
| `F4_DUPLICATE_RATE` | `0.10` | Réservations supplémentaires copiées de F2 (ou `F4_DUPLICATE_COUNT` pour un nombre fixe). |
| `F4_MISSING_CURRENCY_RATE` | `0.10` | Part des réservations sans devise. |

La semaine `2026-W45` a produit 183 lignes : 21 sans devise et 3 doublons de réservations F2. Son chargement dans Neon a confirmé 183 réservations avec 0 surréservation.

## Stockage

<F4Flow />

Les fichiers vont **directement dans S3**, sans modification, car ce sont des fichiers et le lac garde la copie brute. Les réservations qu'ils contiennent vont dans **Neon**, car elles occupent de vraies chambres. Le DAG Airflow `bronze_f4_agencias` s'exécute une heure plus tard et vérifie que les 15 fichiers de la semaine sont dans S3.

À côté des fichiers, `_generation_summary.json` indique les lignes par fichier, les doublons créés et les lignes sans devise, et `_load_report.json` le résultat de `reservar()` pour chaque ligne.

<AccessNote icon="alert" title="Problèmes de qualité de données connus">

- Trois formats avec des noms, un ordre et des unités différents, donc les fichiers doivent être unifiés avant d'être combinés.
- Environ 10 % des réservations n'ont pas de devise.
- Environ 10 % des réservations existent déjà dans F2 (lues dans Neon avec `etl_reader`) : même hôtel, type de chambre et check-out, un check-in décalé d'au plus un jour et un nom de client légèrement différent (inversé, initiale seule, deux lettres permutées ou en minuscules).

</AccessNote>

## L'exécuter en local

```bash
git clone https://github.com/HospedaPlus/hospedaplus-csv.git
cd hospedaplus-csv
cp .env.example .env          # optionnel : NEON_READ_URL, NEON_DATABASE_URL, F4_S3_BUCKET
docker compose up -d --build
docker compose logs -f f4-weekly
```
