# Extraction et chargement : se connecter à Neon et S3

Tout le pipeline tient en **deux connexions** : il **extrait** depuis Neon (et quelques APIs) et **charge** dans S3. Cette page est le guide pratique : quelle chaîne chacune demande, un exemple de chaque chaîne et le code pour la tester en une minute.

:::warning[Placeholders uniquement]
Toute valeur entre `<chevrons>` est un placeholder. Les vrais mots de passe vivent uniquement dans le `.env` de chaque machine (jamais dans git) et l'équipe les partage en privé. Si un mot de passe a déjà été collé dans un chat ou un commit, changez-le dans Neon (**Roles → Reset password**).
:::

## Le processus en 6 étapes

| Étape | Depuis | Vers | Comment | Connexion utilisée |
| --- | --- | --- | --- | --- |
| 1. Extraire chaque heure | Neon `operation`, `streaming` | S3 `bronze/f2_ledger/`, `f3_reservations/`… | `SELECT … WHERE updated_at >= début AND < fin` → JSON Lines → `put_object` | `NEON_READ_URL` + rôle IAM |
| 2. Extraire chaque nuit | Neon (tables entières) | S3 `bronze/*_full/fecha=…/` | une transaction `REPEATABLE READ`, pages de 50 000 lignes, `_SUCCESS` à la fin | `NEON_READ_URL` + rôle IAM |
| 3. Extraire des APIs et fichiers | F1, F5, F6, F7 (HTTP) | S3 `bronze/…` | `requests.get` → `put_object` | URLs de base dans `.env` + rôle IAM |
| 4. Charger les fichiers F4 | EC2 sources | S3 `bronze/f4_agencias/semana=…/` | `s3.upload_file` depuis `f4-weekly` | rôle IAM de l'EC2 sources |
| 5. Transformer et charger | S3 bronze / silver | S3 silver / gold | Spark `read.json` / `write.mode("overwrite").parquet` | rôle IAM (`s3a://`) |
| 6. Write-back | S3 gold | Neon `operation.cancellation_rate_by_lead` | `INSERT … ON CONFLICT DO UPDATE` | `NEON_WRITE_URL` |

## Neon (PostgreSQL)

### Anatomie de la chaîne de connexion

| Partie | Valeur dans HospedaPlus | Notes |
| --- | --- | --- |
| Schéma | `postgresql://` | `postgresql+psycopg2://` pour SQLAlchemy |
| Rôle | `etl_reader` (lecture seule), `app_writer` (lecture/écriture), `hospedaplus_owner` (changements de schéma) | Utilisez le rôle le moins privilégié qui suffit |
| Hôte | `ep-<endpoint-id>.us-east-2.aws.neon.tech` | Chaque branche (`production`, `development`) a son propre endpoint |
| `-pooler` | `ep-<endpoint-id>-pooler…` | Hôte avec pool (PgBouncer) : pour beaucoup de connexions courtes (simulateurs, apps). Utilisez l'hôte **direct** pour les migrations et les sessions avec `SET` |
| Port | `5432` | Par défaut, peut être omis |
| Base | `hospedaplus` | Pas `neondb` |
| Paramètres | `sslmode=require` (toujours), `channel_binding=require` (optionnel, pour le propriétaire) | Neon refuse les connexions sans SSL |

### Chaînes d'exemple par usage

```bash title="Exemples de .env (placeholders)"
# DAGs bronze d'Airflow : lecture seule
NEON_READ_URL=postgresql://etl_reader:<password>@ep-<endpoint-id>.us-east-2.aws.neon.tech/hospedaplus?sslmode=require
# gold_neon_writeback : écrit operation.cancellation_rate_by_lead
NEON_WRITE_URL=postgresql://app_writer:<password>@ep-<endpoint-id>.us-east-2.aws.neon.tech/hospedaplus?sslmode=require
# Simulateur F3 / consommateur F2 / chargeur F4 : beaucoup d'écritures courtes, hôte avec pool
NEON_APP_URL=postgresql://app_writer:<password>@ep-<endpoint-id>-pooler.us-east-2.aws.neon.tech/hospedaplus?sslmode=require
# Changements de schéma et seed (init de db_simulated, migrations de buenavista-streaming) : propriétaire, hôte direct
NEON_OWNER_URL=postgresql://hospedaplus_owner:<password>@ep-<endpoint-id>.us-east-2.aws.neon.tech/hospedaplus?sslmode=require&channel_binding=require
```

**Où la copier :** console Neon → projet `hospedaplus_database` → **Connect** → choisissez la branche `production`, la base `hospedaplus` et le rôle → copiez la *connection string*. Activez **Connection pooling** pour l'hôte `-pooler`.

### Se connecter (test en une minute)

```bash title="psql"
# Se connecte avec la chaîne complète, exécute une requête (-c), puis sort
psql "postgresql://etl_reader:<password>@ep-<endpoint-id>.us-east-2.aws.neon.tech/hospedaplus?sslmode=require" \
  -c "SELECT count(*) FROM operation.reservations;"
```

```python title="Python · psycopg2 (ce qu'utilisent les DAGs)"
# os lit les variables d'environnement ; psycopg2 est le pilote PostgreSQL
import os, psycopg2

# Ouvre la connexion avec la chaîne du .env et un curseur
with psycopg2.connect(os.environ["NEON_READ_URL"]) as conn, conn.cursor() as cur:
    # Les 5 réservations modifiées le plus récemment
    cur.execute("SELECT code, status, updated_at FROM operation.reservations ORDER BY updated_at DESC LIMIT 5")
    # Parcourt les lignes du résultat
    for row in cur.fetchall():
        # Affiche chacune
        print(row)
```

```python title="Python · psycopg 3 (ce qu'utilisent les simulateurs)"
# psycopg est la version 3 du pilote PostgreSQL
import os, psycopg

# Se connecte (abandonne après 10 s) ; fermée à la fin du bloc
with psycopg.connect(os.environ["NEON_APP_URL"], connect_timeout=10) as conn:
    # Qui suis-je et quelle heure est-il dans la base
    print(conn.execute("SELECT current_user, now()").fetchone())
```

```python title="Python · SQLAlchemy + pandas (notebooks, exploration)"
# pandas pour les tableaux en Python
import os, pandas as pd
# SQLAlchemy gère les connexions pour pandas
from sqlalchemy import create_engine

# SQLAlchemy veut le pilote dans le schéma : postgresql+psycopg2://
url = os.environ["NEON_READ_URL"].replace("postgresql://", "postgresql+psycopg2://", 1)
# pool_pre_ping teste la connexion avant de l'utiliser (Neon ferme celles inactives)
engine = create_engine(url, pool_pre_ping=True)
# Exécute la requête et obtient un DataFrame
df = pd.read_sql("SELECT * FROM operation.hotels", engine)
```

### Erreurs fréquentes

| Message | Cause | Solution |
| --- | --- | --- |
| `password authentication failed` | Mauvais mot de passe ou rôle | Recopiez la chaîne depuis **Connect** ; vérifiez la branche |
| `could not translate host name` / `invalid URI` | Le mot de passe contient `@`, `#`, `/` ou `:` | Changez-le avec seulement lettres, chiffres, `-` et `_`, ou encodez-le en URL (`@` → `%40`) |
| `SSL connection is required` | `sslmode` manquant | Ajoutez `?sslmode=require` |
| `permission denied for table …` | `etl_reader` essaie d'écrire | Utilisez `app_writer` (`NEON_WRITE_URL`) seulement là où l'écriture est voulue |
| `prepared statement … does not exist` | Fonctions de session via `-pooler` | Utilisez l'hôte direct (sans `-pooler`) |

### Anatomie des adresses

- `s3a://hospedaplus-lakehouse-buenavista/silver/reservas` : le même type d'adresse avec le schéma utilisé par Spark (Hadoop).
- `https://hospedaplus-lakehouse-buenavista.s3.us-east-2.amazonaws.com/<key>` : forme HTTP ; le bucket est privé, il faut donc une requête signée.

| Quoi | Valeur |
| --- | --- |
| Bucket | `hospedaplus-lakehouse-buenavista` (variable `S3_BUCKET`) |
| Région | `us-east-2` (variable `AWS_DEFAULT_REGION`) |
| Identifiants sur AWS | Rôle IAM de l'EC2 (`hospedaplus-pipeline-role`) : **aucune clé** |
| Identifiants sur un portable | `aws configure` / `AWS_PROFILE`, ou `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` de votre utilisateur IAM |
| Tests locaux (MinIO) | `S3_ENDPOINT_URL=http://localhost:9000` |

```bash title="Exemple de .env"
# Nom du bucket du lac
S3_BUCKET=hospedaplus-lakehouse-buenavista
# Région du bucket
AWS_DEFAULT_REGION=us-east-2
# Seulement sur un portable sans rôle (jamais sur l'EC2, jamais dans git) :
# AWS_ACCESS_KEY_ID=<access-key-id>
# AWS_SECRET_ACCESS_KEY=<secret-access-key>
# Seulement pour MinIO :
# S3_ENDPOINT_URL=http://localhost:9000
```

### Se connecter (test en une minute)

```bash title="AWS CLI"
# Liste les dossiers dans bronze/
aws s3 ls s3://hospedaplus-lakehouse-buenavista/bronze/ --region us-east-2
# Affiche les premières lignes d'un fichier (- veut dire "à l'écran")
aws s3 cp s3://hospedaplus-lakehouse-buenavista/bronze/f7_fx/fecha=2026-11-10.json - | head
```

```python title="Python · boto3 (ce qu'utilisent les DAGs bronze)"
# boto3 est le SDK AWS pour Python
import boto3, json

# trouve tout seul le rôle IAM ou ton profil
s3 = boto3.client("s3", region_name="us-east-2")
# Le bucket du lac
bucket = "hospedaplus-lakehouse-buenavista"

# chargement (écrire)
s3.put_object(Bucket=bucket, Key="bronze/test/hello.json", Body=json.dumps({"ok": True}).encode(),
              ContentType="application/json")
# extraction (lire)
body = s3.get_object(Bucket=bucket, Key="bronze/test/hello.json")["Body"].read()
# lister
for obj in s3.list_objects_v2(Bucket=bucket, Prefix="bronze/f7_fx/").get("Contents", []):
    # Nom et taille en octets de chaque fichier
    print(obj["Key"], obj["Size"])
```

```python title="Python · envoyer un fichier entier (ce que fait f4-weekly)"
# Envoie un fichier local (chemin sur le disque, bucket, key dans S3)
s3.upload_file("output/f4_agency_files/2026-W46/AG01.xlsx", bucket,
               "bronze/f4_agencias/semana=2026-W46/AG01.xlsx")
```

```python title="PySpark · lire bronze, écrire silver (ce que font les jobs silver/gold)"
# Outils du projet : session Spark et adresses du lac
from spark_jobs.session import spark, path

# local[*] + jars s3a + rôle IAM
s = spark("test")
# Lit tous les fichiers JSON Lines d'un jour de bronze
raw = s.read.json("s3a://hospedaplus-lakehouse-buenavista/bronze/f3_reservations/fecha=2026-11-10/")
# L'écrit en Parquet dans s3a://…/silver/reservas_test, en remplaçant le contenu
raw.write.mode("overwrite").parquet(path("silver", "reservas_test"))
```

### Erreurs fréquentes

| Message | Cause | Solution |
| --- | --- | --- |
| `NoCredentialsError` / `Unable to locate credentials` | Ni rôle ni clés | Sur EC2 : attachez le rôle IAM à l'instance. Sur un portable : `aws configure` |
| `AccessDenied` | Il manque `s3:PutObject` / `ListBucket` au rôle | Ajoutez la politique ci-dessus |
| `PermanentRedirect` / `AuthorizationHeaderMalformed` | Mauvaise région | `AWS_DEFAULT_REGION=us-east-2` |
| Spark `ClassNotFoundException: S3AFileSystem` | Jars manquants | Utilisez l'image du pipeline (elle contient `hadoop-aws` et `aws-java-sdk-bundle`) |
| Spark `No FileSystem for scheme "s3"` | `s3://` utilisé dans Spark | Utilisez `s3a://` dans Spark ; `s3://` dans boto3 et la CLI |

## Write-back vers Neon (le seul chargement dans Neon)

```python title="dags/gold_neon_writeback.py"
# Insère une ligne, ou la met à jour si (hôtel, tranche d'anticipation) existe déjà
UPSERT = """
INSERT INTO operation.cancellation_rate_by_lead (hotel_code, lead_bucket, cancel_rate, updated_at)
VALUES (%s, %s, %s, NOW())
ON CONFLICT (hotel_code, lead_bucket) DO UPDATE
   SET cancel_rate = EXCLUDED.cancel_rate, updated_at = EXCLUDED.updated_at
"""
# Se connecte avec le rôle d'écriture
with psycopg2.connect(os.environ["NEON_WRITE_URL"]) as conn, conn.cursor() as cur:
    # une transaction ; relancer donne la même table
    cur.executemany(UPSERT, rows)
```
