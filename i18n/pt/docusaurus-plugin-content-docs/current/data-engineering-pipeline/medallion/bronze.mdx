# Camada bronze

O bronze é a cópia bruta de cada fonte no S3. É gravado por tarefas em Python simples (sem Spark) no worker `bronze`, e nada muda no caminho: o que a fonte enviou é o que o bronze guarda.

## O que chega ao bronze

| Fonte | DAG | Horário (UTC) | Chave no S3 | Formato |
| --- | --- | --- | --- | --- |
| F2 eventos OTA (ledger no Neon) | `bronze_neon_f2_f3` | a cada hora | `bronze/f2_ledger/fecha=YYYY-MM-DD/hora=HH.jsonl` | JSON Lines |
| Reservas F3/F2/F4 (Neon) | `bronze_neon_f2_f3` | a cada hora | `bronze/f3_reservations/…/hora=HH.jsonl`, `f3_anomalies/…` | JSON Lines |
| Foto completa do Neon | `bronze_neon_full_load` | 03:00 diário | `bronze/f3_*_full/fecha=…/part-NNNNN.jsonl` + `_SUCCESS` | JSON Lines |
| Catálogos do Neon | `bronze_neon_dims` | 03:15 diário | `bronze/neon_dims/<tabela>/fecha=….jsonl` | JSON Lines |
| F5 avaliações (API) | `bronze_f5_reviews` | a cada hora | `bronze/f5_reviews/fecha=…/hora=HH.jsonl` | JSON Lines |
| F6 eventos locais (Neon) | `bronze_f6_events` | 02:30 diário | `bronze/f6_events/fecha=….jsonl` | JSON Lines |
| F6 feriados (Nager v4) | `bronze_f6_holidays` | 02:00 no dia 1 de cada mês | `bronze/f6_holidays/anio=YYYY/pais=XX.json` | JSON |
| F7 câmbio (Frankfurter v2) | `bronze_f7_fx` | 01:00 diário | `bronze/f7_fx/fecha=YYYY-MM-DD.json` | JSON |
| F4 arquivos das agências | enviados pelo job da F4; `bronze_f4_agencias` os verifica | segunda 06:00 / 07:00 | `bronze/f4_agencias/semana=YYYY-Www/` | CSV e Excel |
| F1 histórico Kaggle | `bronze_f1_historical` | manual, uma vez | `bronze/f1_historical/hotel_bookings.csv` | CSV |

## Como cada tipo de fonte é lido

- **Tabelas do Neon**: lidas com o papel somente leitura `etl_reader`, de forma incremental a cada hora por `updated_at` / `received_at`, e completas toda noite dentro de uma transação consistente. Detalhes em [Conexão com o Neon](../neon-connection.mdx).
- **API de avaliações F5**: `GET /api/v1/reviews?updated_from=<início da hora>&page=N`, todas as páginas, então avaliações editadas também voltam.
- **Feriados F6**: `GET /api/v4/Holidays/{país}/{ano}` para PT, CO, MX, BR e ES, ano atual e seguinte.
- **Câmbio F7**: Frankfurter v2 `/v2/rates`, base USD, cotações COP, EUR, MXN, BRL.
- **Arquivos F4**: o gerador da F4 copia para o S3 os 15 arquivos de agências da semana e um resumo toda segunda às 06:00 UTC. Às 07:00 `bronze_f4_agencias` verifica se a semana está completa (tenta de novo até 6 vezes, a cada 20 minutos) e marca o asset. As **reservas** das agências chegam ao silver pelo Neon (o carregador da F4 chama `reservar()`), não por esses arquivos.
- **F1**: o CSV do Kaggle é baixado uma vez do repositório `hospedaplus-csv`. Seu sha256 é guardado nos metadados do objeto; se já estiver lá com o mesmo hash, nada é enviado.

## Como a extração funciona, em código

Cada DAG de bronze é uma pequena tarefa Python na fila `bronze`. Todos compartilham duas funções: uma que lê o Neon e outra que grava no S3. Os trechos são de `dags/` no repositório do pipeline, cortados só onde aparece `…`.

### As duas funções compartilhadas

`dags/hospedaplus/neon.py` abre uma conexão com o papel somente leitura `etl_reader` (`NEON_READ_URL`), executa uma consulta e devolve as linhas como JSON Lines, exatamente como o Neon entregou:

```python
def dump(sql: str, params: tuple = ()) -> tuple[bytes, int]:
    with psycopg2.connect(neon_url()) as conn, conn.cursor() as cur:
        cur.execute(sql, params)
        cols = [c.name for c in cur.description]
        rows = cur.fetchall()
    lines = [json.dumps(dict(zip(cols, r)), default=str, ensure_ascii=False) for r in rows]
    return ("\n".join(lines) + ("\n" if lines else "")).encode(), len(rows)
```

`dags/hospedaplus/lake.py` grava um objeto no bucket do lakehouse. O worker não tem chaves de acesso: o boto3 usa as credenciais temporárias do papel IAM da EC2 (veja [Serviços da AWS](../aws-services.mdx)).

```python
def s3_client():
    return boto3.client("s3", endpoint_url=os.getenv("S3_ENDPOINT_URL") or None)


def put(key: str, body: bytes, content_type: str = "application/json") -> str:
    s3_client().put_object(Bucket=BUCKET, Key=key, Body=body, ContentType=content_type)
    return f"s3://{BUCKET}/{key}"
```

O mesmo arquivo declara um **Asset** por conjunto de dados. Uma tarefa que coloca um asset em `outlets` o marca como atualizado quando termina bem, e é isso que inicia o silver.

```python
BRONZE_F3_RESERVATIONS = asset("bronze", "f3_reservations")
BRONZE_F7_FX = asset("bronze", "f7_fx")
```

### F2 e F3 do Neon, a cada hora (`bronze_neon_f2_f3.py`)

Cada execução copia só as linhas que mudaram dentro do seu intervalo de dados do Airflow `[início, fim)`. A F3 é lida por `updated_at`, que um trigger no Neon atualiza a cada mudança, então nunca se perde um evento OTA atrasado nem uma mudança de status (no-show, realocada). A chave leva o nome do intervalo, então repetir a hora sobrescreve o mesmo arquivo.

```python
F2_SQL = """
SELECT * FROM streaming.reservation_event_ledger
 WHERE received_at >= %s AND received_at < %s
"""
F3_SQL = """
SELECT * FROM operation.reservations WHERE updated_at >= %s AND updated_at < %s
"""

def _key(prefix: str, start) -> str:
    return f"bronze/{prefix}/fecha={start:%Y-%m-%d}/hora={start:%H}.jsonl"


@dag(schedule="@hourly", start_date=pendulum.datetime(2026, 11, 1, tz="UTC"), catchup=False,
     tags=["bronze", "F2", "F3"], default_args={"retries": 3, "retry_exponential_backoff": True})
def bronze_neon_f2_f3():
    @task(queue="bronze", outlets=[BRONZE_F2_LEDGER])
    def f2_ledger(data_interval_start=None, data_interval_end=None) -> int:
        body, n = _dump(F2_SQL, data_interval_start, data_interval_end)
        put(_key("f2_ledger", data_interval_start), body, "application/x-ndjson")
        return n
    …
```

A cópia completa noturna das mesmas tabelas (`bronze_neon_full_load.py`, uma transação `REPEATABLE READ`, páginas de 50.000 linhas, `_SUCCESS` no final) aparece em [Carga incremental e em lote](../loading.mdx).

### API de avaliações F5, a cada hora (`bronze_f5_reviews.py`)

A API recebe o pedido de tudo o que foi atualizado desde o início da hora e todas as páginas são percorridas. A API só filtra "a partir de", então a tarefa descarta o que passa do fim do intervalo: horas seguidas nunca se sobrepõem.

```python
items, page = [], 1
while True:
    r = requests.get(f"{base}/api/v1/reviews", headers=headers, timeout=60, params={
        "updated_from": data_interval_start.isoformat(), "page": page, "page_size": PAGE_SIZE})
    r.raise_for_status()
    body = r.json()
    items += body["items"]
    if page >= body.get("total_pages", 1):
        break
    page += 1
items = [i for i in items if i.get("updated_at") and pendulum.parse(i["updated_at"]) < data_interval_end]
put(f"bronze/f5_reviews/fecha={data_interval_start:%Y-%m-%d}/hora={data_interval_start:%H}.jsonl", …)
```

### Câmbio F7, todo dia (`bronze_f7_fx.py`)

Uma chamada ao Frankfurter v2 para o dia do intervalo. A resposta é guardada byte a byte.

```python
@task(queue="bronze", outlets=[BRONZE_F7_FX])
def extract(data_interval_start=None) -> str:
    day = data_interval_start.date().isoformat()
    r = requests.get("https://api.frankfurter.dev/v2/rates",
                     params={"date": day, "base": "USD", "quotes": "COP,EUR,MXN,BRL"}, timeout=30)
    r.raise_for_status()
    return put(f"bronze/f7_fx/fecha={day}.json", r.content)
```

### Feriados F6, todo mês (`bronze_f6_holidays.py`)

Um arquivo por país e ano, para este ano e o próximo, porque as reservas são feitas com meses de antecedência.

```python
COUNTRIES = ["PT", "CO", "MX", "BR", "ES"]

for y in (year, year + 1):
    for country in COUNTRIES:
        r = requests.get(f"{NAGER_BASE_URL}/api/v4/Holidays/{country}/{y}", timeout=30)
        r.raise_for_status()
        written.append(put(f"bronze/f6_holidays/anio={y}/pais={country}.json", r.content))
```

### Arquivos de agências F4, toda segunda-feira (`bronze_f4_agencias.py`)

O Airflow não baixa esses arquivos: o gerador da F4 os envia ao S3 por conta própria. O DAG só verifica se a semana está completa e falha (e tenta de novo a cada 20 minutos, até 6 vezes) enquanto não estiver, então o silver nunca começa com meia semana.

```python
week = data_interval_end.strftime("%G-W%V")
prefix = f"bronze/f4_agencias/semana={week}/"
resp = s3_client().list_objects_v2(Bucket=BUCKET, Prefix=prefix)
names = [o["Key"].rsplit("/", 1)[-1] for o in resp.get("Contents", [])]
agency_files = [n for n in names if n.startswith("AG")]
if len(agency_files) < EXPECTED_AGENCIES or "_generation_summary.json" not in names:
    raise RuntimeError(f"{prefix}: {len(agency_files)}/{EXPECTED_AGENCIES} agency files yet; …")
```

## Regras da camada

- **Bruto e completo.** Sem filtro, sem mudança de tipo, sem limpeza. O bronze é a evidência do que chegou.
- **Chaves idempotentes.** A chave depende só de fonte + data/hora. Repetir uma tarefa sobrescreve o mesmo objeto; nunca duplica dados.
- **Incremental por intervalo de dados.** Os DAGs horários copiam exatamente as linhas do seu intervalo do Airflow, então uma hora perdida pode ser repetida sozinha.
- **Novas tentativas.** Todos os DAGs de bronze tentam de novo ao falhar (3 vezes com espera exponencial nos horários).
- **Sem dados pessoais.** `guests` nunca é copiada.
- **Cada gravação atualiza um Asset**, que é o que inicia o silver (veja [DAGs e horários](../dags.mdx)).
