# Fontes de dados

O HospedaPlus Revenue integra sete fontes de dados, de F1 a F7. F1, F6 e F7 são dados públicos reais. F2 a F5 são **simuladas**: a equipe construiu um gerador para cada uma, ele roda o tempo todo na AWS e produz dados com a frequência e o volume pedidos pelo projeto.

## Onde cada fonte é armazenada primeiro

```text
Simuladores na AWS                          Armazenada primeiro em             Lago (S3)
Produtor F2 ─► Kafka ─► consumidor ────────► Neon · streaming + operation ─┐
Seed + simulador F3 ───────────────────────► Neon · operation ─────────────┤ Airflow, a cada hora
CSV de eventos locais F6 ──────────────────► Neon · operation.local_events ┤ e toda noite
Gerador semanal F4 ──┬─ reservar() ────────► Neon · operation ─────────────┤
                     └─ arquivos brutos ────────────────────────────────────┼─► S3 bronze ─► silver ─► gold
API de avaliações F5 ──────────────────────► PostgreSQL da API ─ Airflow ──┤
CSV F1, API de feriados F6, API de câmbio F7 ── Airflow ────────────────────┘
```

- **Primeiro no Neon (F2, F3, eventos F6, reservas F4).** São dados operacionais: toda reserva, de qualquer canal, passa pela mesma função `operation.reservar()`, então todos os canais compartilham um único inventário e nunca há overbooking. O pipeline lê o Neon com um papel somente leitura e copia as mudanças para o S3 a cada hora, além de uma foto completa toda noite.
- **Primeiro no S3 (F1, arquivos F4, feriados F6, F7).** São arquivos ou APIs públicas sem nada a operar, então vão para `s3://…/bronze/` como chegam, sem mudanças.
- **F5** guarda suas avaliações no banco próprio da API, como faria uma plataforma real; o pipeline lê a API a cada hora.

<Note>
  **Seed de dados.** Todos os dados das fontes simuladas são gerados por código versionado em cada repositório. Os geradores usam uma semente aleatória fixa para que os dados sejam reprodutíveis, são idempotentes, permitem escolher o volume (modo pequeno de desenvolvimento ou modo completo), mantêm a integridade referencial com um único catálogo compartilhado (os mesmos códigos de hotel, tipo de quarto, canal e hóspede em todo lugar), injetam os problemas de qualidade conhecidos com uma taxa configurável e rodam tanto localmente com Docker quanto na AWS.
</Note>

<AccessNote icon="alert" title="Problemas de qualidade de dados conhecidos">

Os dados chegam com os seguintes defeitos, e as fontes simuladas os injetam de propósito:

- F1 tem `"NULL"` como texto nos campos de agente e empresa, e valores de ADR negativos ou extremos.
- Reservas com zero adultos, zero crianças e zero bebês (F1, F3).
- Datas de saída anteriores à data de chegada (F3).
- Moedas ausentes nos arquivos das agências (F4, ~10%).
- Reservas duplicadas entre canais com pequenas diferenças no nome do hóspede (F4, ~10%), e avaliações duplicadas entre plataformas (F5, ~5%).
- Eventos de modificação que chegam antes do evento de criação (F2, ~5%).

</AccessNote>
