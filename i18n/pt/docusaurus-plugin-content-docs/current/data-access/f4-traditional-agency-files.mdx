# <SourceTitleIcon icon="file" tone="sky" />F4 · Arquivos de agências tradicionais <SourceType>Arquivos CSV / Excel</SourceType>

Arquivos semanais simulados com as reservas vendidas pelas agências de viagens tradicionais. Essas agências não se conectam por API nem por stream de eventos: cada uma envia uma planilha uma vez por semana, no seu próprio formato. A equipe simula os arquivos com um gerador em Python.

<AccessTable>

| Propriedade | Valor |
| --- | --- |
| Tipo | Arquivos simulados, gerados pela equipe |

| Método de acesso | Um arquivo CSV ou Excel por agência e semana ISO, por exemplo `AG07_2026-W45.xlsx` |

## Como é simulada

O serviço `f4-weekly` (`python -m buenavista_csv.weekly`, Docker Compose) roda a semana atual assim que inicia e depois toda segunda-feira às 06:00 UTC:

1. **Gera** os 15 arquivos da semana (`buenavista_csv.f4_generator`). Cada agência `AG01`…`AG15` recebe 12 reservas por padrão, com um hotel do catálogo compartilhado (`HP-CO-001`…), datas relativas à semana, tipo de quarto, quartos, adultos e crianças, indicador de reembolsável, o hóspede (`guest_ref` `G-0000001`…, compartilhado com F2 e F3), o valor pelas tarifas do catálogo na moeda do hotel (`COP`, `MXN`, `BRL`, `EUR`, `USD`) e uma comissão de 10%.
2. **Valida** os arquivos (`buenavista_csv.validator`), sem alterá-los.
3. **Reserva** cada linha no Neon com `operation.reservar('AGxx', …)`, assim as reservas de agência ocupam quartos do mesmo inventário que os outros canais.
4. **Envia** os arquivos brutos para o S3.

É reprodutível (semente `7`) e pode ser reiniciado sem risco: uma semana que já existe não é gerada de novo, e `reservar()` ignora uma reserva que já tem.

### Frequência e volume

| Variável | Padrão | Significado |
| --- | --- | --- |
| `F4_RUN_WEEKDAY`, `F4_RUN_HOUR_UTC` | `0`, `6` | Segunda-feira, 06:00 UTC. |
| `F4_BOOKINGS_PER_AGENCY` | `12` | Reservas regulares por agência: 15 × 12 = 180. |
| `F4_DUPLICATE_RATE` | `0.10` | Reservas extras copiadas da F2 (ou `F4_DUPLICATE_COUNT` para um número fixo). |
| `F4_MISSING_CURRENCY_RATE` | `0.10` | Proporção de reservas sem moeda. |

A semana `2026-W45` produziu 183 linhas: 21 sem moeda e 3 duplicadas de reservas da F2. Sua carga no Neon confirmou 183 reservas com 0 overbooking.

## Onde é armazenada

```text
f4-weekly ─┬─ arquivos ─► EC2 ./output/f4_agency_files/<semana>/ ─► S3 bronze/f4_agencias/semana=<semana>/
           └─ linhas   ─► Neon operation.reservar('AGxx', …)
Airflow bronze_f4_agencias (segunda 07:00 UTC) verifica e registra a semana no S3
```

Os arquivos vão **direto para o S3**, sem mudanças, porque são arquivos e o lago guarda a cópia bruta. As reservas que eles trazem vão para o **Neon**, porque ocupam quartos reais. O DAG do Airflow `bronze_f4_agencias` roda uma hora depois e verifica que os 15 arquivos da semana estão no S3.

As agências `AG03`, `AG07`, `AG11` e `AG15` enviam `.xlsx` com cabeçalhos em espanhol: `localizador`, `cod_huesped`, `nombre_huesped`, `hotel`, `fecha_llegada`, `fecha_salida`, `tipo_habitacion`, `habitaciones`, `adultos`, `ninos`, `tarifa` (`reembolsable` / `no_reembolsable`), `importe`, `moneda`, `comision`.

</TabItem>

Junto aos arquivos, `_generation_summary.json` informa as linhas por arquivo, as duplicadas criadas e as linhas sem moeda, e `_load_report.json` o resultado de `reservar()` para cada linha.

<AccessNote icon="alert" title="Problemas de qualidade de dados conhecidos">

- Três formatos com nomes, ordem e unidades diferentes, então os arquivos precisam ser unificados antes de combiná-los.
- Cerca de 10% das reservas não têm moeda.
- Cerca de 10% das reservas já existem na F2 (lidas do Neon com `etl_reader`): mesmo hotel, tipo de quarto e check-out, um check-in deslocado em até um dia e um nome de hóspede um pouco diferente (invertido, só a inicial, duas letras trocadas ou em minúsculas).

</AccessNote>

## Executar localmente

```bash
git clone https://github.com/HospedaPlus/hospedaplus-csv.git
cd hospedaplus-csv
cp .env.example .env          # opcional: NEON_READ_URL, NEON_DATABASE_URL, F4_S3_BUCKET
docker compose up -d --build
docker compose logs -f f4-weekly
```
