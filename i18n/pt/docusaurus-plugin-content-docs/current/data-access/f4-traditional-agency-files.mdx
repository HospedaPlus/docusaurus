# <SourceTitleIcon icon="file" tone="sky" />F4 · Arquivos de agências tradicionais <SourceType>Arquivos CSV / Excel</SourceType>

## Como acessar

Cada agência entrega um arquivo CSV por semana, e a plataforma carrega os arquivos em batch. Na simulação, o gerador grava os 15 arquivos semanais em `output/f4_agency_files/`, junto com um resumo do que gerou.

## Como os dados são gerados

O gerador é o módulo `buenavista_csv.f4_generator` do repositório [buenavista-csv](https://github.com/HospedaPlus/buenavista-csv). Ele cria um arquivo por agência com estas regras:

- **Reproduzível.** Usa uma semente fixa (`7` por padrão), então executá-lo de novo produz exatamente os mesmos arquivos.
- **Reservas normais.** Cada agência recebe 12 reservas por padrão. Cada reserva tem um hotel aleatório de `hotel-001` a `hotel-028`, um check-in entre 1º de novembro de 2026 e 30 de janeiro de 2027, uma estadia de 1 a 6 noites, um tipo de quarto (`SINGLE`, `DOUBLE`, `TWIN` ou `SUITE`), uma moeda (`EUR` ou `USD`) e um valor entre 80 e 2.000.
- **Comissão fixa.** Todas as reservas têm comissão de `0.10`, os 10% que as agências tradicionais cobram.
- **Ids de reserva.** Os ids seguem o padrão `AG<agência>-<contador>`, por exemplo `AG01-00001`. O contador continua crescendo entre agências, então um id nunca se repete.
- **Dois layouts.** As agências alternam entre dois layouts de colunas para simular que cada agência usa o seu formato. As 8 agências de número ímpar usam o layout B e as 7 de número par usam o layout A.

### Parâmetros

| Parâmetro | Padrão | Descrição |
| --- | --- | --- |
| `--seed` | `7` | Semente do gerador aleatório. |
| `--bookings-per-agency` | `12` | Reservas normais por agência. |
| `--duplicate-count` | `3` | Reservas copiadas da F2 para criar duplicatas entre canais. |
| `--missing-currency-rate` | `0.10` | Proporção de reservas sem moeda, entre `0.0` e `1.0`. |
| `--f2-events` | `data/f2_reference/events.jsonl` | Eventos da F2 usados como origem das duplicatas. |
| `--output-dir` | `output/f4_agency_files` | Pasta onde os arquivos são gravados. |

### Defeitos que injeta

O gerador adiciona dois dos defeitos de qualidade de dados que a plataforma precisa tratar:

- **Moeda ausente.** Cerca de 10% das reservas têm o campo `currency` vazio. Com a semente padrão, 14 das 183 reservas não têm moeda.
- **Duplicatas entre canais.** O gerador lê eventos `reservation.created` da [F2](./f2-channel-manager-events.mdx) e copia alguns para os arquivos das agências. A cópia mantém o hotel, o check-out, o tipo de quarto, a moeda e o valor, mas recebe um novo id de agência, um check-in deslocado em −1, 0 ou +1 dia e, em geral, um nome de hóspede um pouco diferente. O gerador muda o nome de uma destas formas: nome e sobrenome invertidos (`Ferreira Diego`), sobrenome reduzido à inicial (`Diego F.`), duas letras trocadas (`Diego Ferriera`) ou sobrenome em minúsculas (`Diego ferreira`). Com os valores padrão, as três primeiras agências recebem uma duplicata cada.

Os eventos da F2 não incluem o nome do hóspede, então o gerador deriva um a partir de cada `reservation_id` com sua própria semente. Assim, a reserva original da F2 e sua cópia na F4 podem ser comparadas pelo nome.

### Validação da saída

O repositório também inclui um validador, `buenavista_csv.validator`, que verifica os arquivos sem alterá-los. Ele reconhece o layout de cada arquivo pelo cabeçalho e informa cada defeito que encontra por tipo, como `MISSING_CURRENCY` ou `CROSS_CHANNEL_DUPLICATE`. Com a execução padrão, o resultado é `PASSED_WITH_CATALOGUED_DEFECTS`: os 15 arquivos têm uma estrutura válida, e ele encontra 14 reservas sem moeda e 3 duplicatas. O relatório é gravado em `output/validation_reports/quality_validation_report.json`.

<AccessNote icon="alert" title="Problemas de qualidade de dados conhecidos">

- As agências usam dois layouts diferentes, então os arquivos precisam ser unificados antes de serem combinados.
- Cerca de 10% das reservas não têm moeda, então seu valor não pode ser convertido até que a moeda seja conhecida.
- Algumas reservas já existem pela F2, com pequenas diferenças no nome do hóspede e um check-in deslocado em até um dia. Quando o mesmo hóspede, hotel e datas (±1 dia) aparecem em dois canais, a reserva é marcada e prevalece a do canal com menor comissão.

</AccessNote>

## Executar localmente

Com Python 3.11 ou superior e [uv](https://docs.astral.sh/uv/), clone o repositório e execute o gerador:

```bash
git clone https://github.com/HospedaPlus/buenavista-csv.git
cd buenavista-csv
uv sync --extra test
uv run -m buenavista_csv.f4_generator --seed 7 --bookings-per-agency 12 --duplicate-count 3 --missing-currency-rate 0.10
```

O comando mostra quantos arquivos, linhas, duplicatas e reservas sem moeda gerou. Para verificar os arquivos, execute `uv run -m buenavista_csv.validator`.

<Note>

Os arquivos são gerados do zero a cada execução. Com a mesma semente e os mesmos parâmetros, a saída é idêntica, então as linhas de exemplo desta página podem ser reproduzidas.

</Note>
