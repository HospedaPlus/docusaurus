## Onde é armazenada

**F6a · Feriados → S3.** No dia 1 de cada mês (02:00 UTC) o DAG do Airflow `bronze_f6_holidays` chama a API para Portugal, Colômbia, México, Brasil e Espanha, para o ano atual e o seguinte (as reservas são feitas com meses de antecedência), e guarda cada resposta como chega:

```bash
curl https://nagerholidays.com/api/v4/Holidays/PT/2026   # $NAGER_BASE_URL
# -> s3://…/bronze/f6_holidays/anio=2026/pais=PT.json
```

**F6b · Eventos locais → Neon, depois S3.** Os 33 eventos ficam em um CSV versionado no `db_simulated`. `python -m seed events` os carrega em `operation.local_events` (o CI/CD os recarrega sempre que o CSV muda), porque o banco precisa deles para definir os limites de overbooking. Todos os dias às 02:30 UTC o DAG `bronze_f6_events` copia a tabela para `s3://…/bronze/f6_events/`.

Os dois alimentam `silver/calendario_hotel/` (hotel × dia com feriado, evento e fim de semana).

## Como é usada

- Um feriado ou evento local em uma data adiciona um multiplicador de preço extra de 1,15.
- Nunca é permitido overbooking em datas com um evento de categoria "alta" (`refresh_overbooking_limits()` deixa o limite em 0).
