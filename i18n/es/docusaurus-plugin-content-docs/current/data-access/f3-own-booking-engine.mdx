## Cómo acceder

La base de datos compartida del equipo corre en Neon (PostgreSQL 16 administrado), cargada en modo `full` y verificada con `python -m seed check`.

| Propiedad | Valor |
| --- | --- |
| Host | `ep-divine-cake-b48dsbxg-pooler.c-6.us-east-2.aws.neon.tech` (pooled) · `ep-divine-cake-b48dsbxg.c-6.us-east-2.aws.neon.tech` (directo) |
| Puerto | `5432` |

### Roles

Cada cliente se conecta con su propio rol y solo tiene el acceso que necesita, así un error o una URL filtrada en un lugar no puede borrar los datos.

| Rol | Lo usa | Puede |
| --- | --- | --- |
| `hospedaplus_owner` | Seed (`init`, `seed`, recargas) | Todo. |
| `hospedaplus_api` | FastAPI, consumidores de Kafka | Leer todas las tablas; actualizar `inventory`; insertar y actualizar `reservations` y `guests`; nunca borrar. |
| `hospedaplus_reader` | Equipo (DBeaver, psql), worker bronze de Airflow | Solo lectura. |

### Host pooled o directo

El host `-pooler` pone PgBouncer delante de la base de datos, así muchas conexiones de clientes comparten unas pocas reales. Funciona en modo transacción, por lo que todo lo que necesite una sesión fija (un `SET` duradero, tablas temporales, cargas masivas largas) va al host directo.

| Cliente | Host |
| --- | --- |
| FastAPI, consumidores de Kafka, Airflow | Pooled |
| Seed (`init`, carga con `COPY`) | Directo (el mismo host sin `-pooler`) |
| Equipo en DBeaver o psql | Pooled |

- En DBeaver o pgAdmin, crea una conexión PostgreSQL con los datos de arriba y pon el modo SSL en `require`.
- La base de datos se suspende tras 5 minutos sin uso y despierta con la siguiente consulta, así que la primera consulta puede tardar unos segundos.
- Para correr el seed en local, el repositorio incluye un archivo de Docker Compose con PostgreSQL 16 en el puerto `5437`, para que nunca choque con Neon.

## Qué contiene

| Tabla | Contenido |
| --- | --- |
| `hotels` | 28 hoteles urbanos y de playa, con código (`HP-CO-001`…), ciudad, país, zona horaria y moneda. |
| `room_types` | `SINGLE`, `DOUBLE`, `TWIN` y `SUITE`, con su máximo de huéspedes. |
| `rooms` | Las 4.000 habitaciones físicas, por hotel y tipo de habitación. |
| `channels` | 21 canales de venta con su comisión (RN-02). |
| `rates` | Precio por noche por hotel, tipo de habitación y temporada (`LOW`, `MID`, `HIGH`, RN-05). |
| `inventory` | Habitaciones totales y disponibles por hotel, tipo de habitación y noche. |
| `guests` | Datos personales de los huéspedes, que se seudonimizan antes de la analítica (RN-11). |
| `reservations` | Reservas directas y corporativas, con cancelaciones y no-shows. |
| `reservation_anomalies` | Filas con los problemas de calidad de datos conocidos, separadas a propósito. |

Los hoteles, tipos de habitación y canales vienen del **catálogo compartido** que también leen F2, F4 y F5, para que el pipeline pueda cruzar todas las fuentes.

## Seed de datos

Todos los datos los genera el seed del repositorio (`python -m seed`), nunca se cargan a mano ni desde un dump. El seed:

- **Es reproducible.** El mismo seed y la misma fecha de inicio producen los mismos datos, fila por fila.
- **Es idempotente.** Reemplaza los datos en una sola transacción: ejecutarlo varias veces deja una sola copia, y si falla, los datos anteriores quedan intactos.
- **Tiene dos volúmenes.** El modo `dev` cubre 90 noches pasadas y 30 futuras; el modo `full` cubre 400 pasadas y 180 futuras.
- **Simula una demanda realista.** Los hoteles de ciudad reciben más llegadas de domingo a martes, los resorts el fin de semana, y la temporada alta trae más huéspedes.
- **Nunca sobrevende.** El generador rechaza una reserva cuando el tipo de habitación está lleno, y la base de datos rechaza `available_rooms < 0`.
- **Rechaza reservas en el pasado.** Un trigger rechaza toda reserva cuyo check-in sea anterior al día en que se hizo.
- **Es seguro por defecto.** Los comandos destructivos se detienen en bases de datos remotas salvo que se use `--allow-remote`.
- **Se verifica a sí mismo.** `python -m seed check` ejecuta 21 verificaciones de salud e integridad y solo pasa si todas pasan.

| Comando | Qué hace |
| --- | --- |
| `python -m seed init` | Crea las tablas y los índices. |
| `python -m seed seed` | Vacía las tablas y carga un conjunto de datos nuevo. |
| `python -m seed check` | Ejecuta las verificaciones de salud e integridad (solo lectura). |
| `python -m seed all` | `init` + `seed` + `check`. |

<AccessNote icon="alert" title="Problemas de calidad de datos conocidos">

Las filas que romperían las restricciones van a `reservation_anomalies` en lugar de `reservations` (2% cada una por defecto, configurable):

- Reservas con cero huéspedes.
- Fechas de check-out anteriores a la fecha de check-in.

</AccessNote>
