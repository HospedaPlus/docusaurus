# <SourceTitleIcon icon="file" tone="purple" />F1 · Hotel booking demand <SourceType>CSV</SourceType>

Dataset público con la historia de reservas de un hotel urbano y uno vacacional en Portugal. En HospedaPlus es la historia de dos hoteles de la cadena: `HP-PT-001` (City Hotel) y `HP-PT-002` (Resort Hotel). Son datos reales, así que no se simula.

## Dónde se almacena

El archivo nunca cambia, así que no pasa por Neon. El DAG de Airflow `bronze_f1_historical`, que se lanza una vez a mano, lo descarga del repositorio `hospedaplus-csv` y lo sube a `s3://…/bronze/f1_historical/`. Si el archivo que ya está en S3 tiene el mismo hash, no se vuelve a subir. Después `silver_f1_historico` lo limpia en `silver/historico_f1/`, la base del análisis de cancelaciones por tipo de depósito y anticipación (P1).

## Cómo acceder

Descárgalo de Kaggle, o con la CLI de Kaggle usando un token personal de API (que se queda fuera del repositorio):

```bash
kaggle datasets download -d jessemostipak/hotel-booking-demand --unzip
```

El repositorio `hospedaplus-csv` también lo perfila: `uv run -m buenavista_csv.f1_audit` escribe la auditoría en `output/f1_audit/`.

## Qué contiene

Cada fila es una reserva, con su fecha de llegada, anticipación, canal de distribución, segmento de mercado, ADR, indicador de cancelación y tipo de depósito. Las columnas principales son:

- `hotel`: `City Hotel` o `Resort Hotel`.
- `is_canceled`, `lead_time`, `deposit_type`.
- `arrival_date_year`, `arrival_date_month`, `arrival_date_day_of_month`, `stays_in_weekend_nights`, `stays_in_week_nights`.
- `adults`, `children`, `babies`.
- `market_segment`, `distribution_channel`, `customer_type`, `agent`, `company`.
- `reserved_room_type`, `assigned_room_type`, `adr`, `reservation_status`, `reservation_status_date`.

<AccessNote icon="alert" title="Problemas de calidad de datos conocidos">

- `agent` y `company` traen el texto `"NULL"` en vez de valores vacíos.
- `adr` tiene valores negativos y extremos que hay que tratar (atípicos por IQR).
- Algunas reservas tienen cero adultos, cero niños y cero bebés.

</AccessNote>
