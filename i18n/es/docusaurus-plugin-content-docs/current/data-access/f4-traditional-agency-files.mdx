# <SourceTitleIcon icon="file" tone="sky" />F4 · Archivos de agencias tradicionales <SourceType>Archivos CSV / Excel</SourceType>

Archivos semanales simulados con las reservas que venden las agencias de viaje tradicionales. Las agencias tradicionales no se conectan por una API ni por un flujo de eventos: envían una hoja de cálculo una vez por semana. El equipo simula estos archivos con un generador escrito en Python.

## Cómo acceder

Cada agencia entrega un archivo CSV por semana, y la plataforma carga los archivos en batch. En la simulación, el generador escribe los 15 archivos semanales en `output/f4_agency_files/`, junto con un resumen de lo que generó.

## Cómo se generan los datos

El generador es el módulo `buenavista_csv.f4_generator` del repositorio [buenavista-csv](https://github.com/HospedaPlus/buenavista-csv). Crea un archivo por agencia con estas reglas:

- **Reproducible.** Usa una semilla fija (`7` por defecto), así que al ejecutarlo de nuevo produce exactamente los mismos archivos.
- **Reservas normales.** Cada agencia recibe 12 reservas por defecto. Cada reserva tiene un hotel al azar de `hotel-001` a `hotel-028`, un check-in entre el 1 de noviembre de 2026 y el 30 de enero de 2027, una estadía de 1 a 6 noches, un tipo de habitación (`SINGLE`, `DOUBLE`, `TWIN` o `SUITE`), una moneda (`EUR` o `USD`) y un monto entre 80 y 2.000.
- **Comisión fija.** Todas las reservas llevan una comisión de `0.10`, el 10% que cobran las agencias tradicionales.
- **Ids de reserva.** Los ids siguen el patrón `AG<agencia>-<contador>`, por ejemplo `AG01-00001`. El contador sigue creciendo entre agencias, así que un id nunca se repite.
- **Dos formatos.** Las agencias alternan entre dos formatos de columnas para simular que cada agencia usa el suyo. Las 8 agencias con número impar usan el formato B y las 7 con número par usan el formato A.

### Parámetros

| Parámetro | Por defecto | Descripción |
| --- | --- | --- |
| `--seed` | `7` | Semilla del generador aleatorio. |
| `--bookings-per-agency` | `12` | Reservas normales por agencia. |
| `--duplicate-count` | `3` | Reservas copiadas de F2 para crear duplicados entre canales. |
| `--missing-currency-rate` | `0.10` | Proporción de reservas sin moneda, entre `0.0` y `1.0`. |
| `--f2-events` | `data/f2_reference/events.jsonl` | Eventos de F2 usados como origen de los duplicados. |
| `--output-dir` | `output/f4_agency_files` | Carpeta donde se escriben los archivos. |

### Defectos que inyecta

El generador agrega dos de los defectos de calidad de datos que la plataforma debe manejar:

- **Moneda faltante.** Cerca del 10% de las reservas tienen el campo `currency` vacío. Con la semilla por defecto, 14 de las 183 reservas no tienen moneda.
- **Duplicados entre canales.** El generador lee eventos `reservation.created` de [F2](./f2-channel-manager-events.mdx) y copia algunos en los archivos de las agencias. La copia conserva el hotel, el check-out, el tipo de habitación, la moneda y el monto, pero recibe un id de agencia nuevo, un check-in movido −1, 0 o +1 día y, por lo general, un nombre de huésped un poco distinto. El generador cambia el nombre de una de estas formas: nombre y apellido invertidos (`Ferreira Diego`), apellido reducido a su inicial (`Diego F.`), dos letras intercambiadas (`Diego Ferriera`) o apellido en minúsculas (`Diego ferreira`). Con los valores por defecto, las tres primeras agencias reciben un duplicado cada una.

Los eventos de F2 no incluyen el nombre del huésped, así que el generador deriva uno a partir de cada `reservation_id` con su propia semilla. Así se puede comparar por nombre la reserva original de F2 con su copia en F4.

### Columnas

Esta tabla relaciona cada columna del formato B con su nombre en el formato A, que es el nombre que se usa cuando se unifican los archivos:

| Formato A | Formato B | Tipo | Descripción |
| --- | --- | --- | --- |
| `agency_booking_id` | `booking_ref` | texto | Id de la reserva en la agencia, por ejemplo `AG01-00001`. |
| `guest_name` | `guest_full_name` | texto | Nombre del huésped. Es un dato personal. |
| `hotel_id` | `hotel_id` | texto | Código del hotel, de `hotel-001` a `hotel-028`. |
| `check_in` | `checkin_date` | fecha `YYYY-MM-DD` | Fecha de llegada. |
| `check_out` | `checkout_date` | fecha `YYYY-MM-DD` | Fecha de salida, siempre posterior a la llegada. |
| `room_type` | `room_category` | texto | `SINGLE`, `DOUBLE`, `TWIN` o `SUITE`. |
| `currency` | `currency` | texto, puede estar vacío | `EUR` o `USD`. |
| `total_amount` | `amount` | decimal | Monto total de la reserva, antes de la comisión. |

| Archivo de agencia | Id de agencia | Reserva de F2 | Canal de F2 | Huésped en F2 | Huésped en F4 | Cambio de check-in |

### Validación de la salida

El repositorio también incluye un validador, `buenavista_csv.validator`, que revisa los archivos sin modificarlos. Reconoce el formato de cada archivo por su encabezado e informa cada defecto que encuentra por tipo, como `MISSING_CURRENCY` o `CROSS_CHANNEL_DUPLICATE`. Con la ejecución por defecto, el resultado es `PASSED_WITH_CATALOGUED_DEFECTS`: los 15 archivos tienen una estructura válida, y encuentra 14 reservas sin moneda y 3 duplicados. El informe se escribe en `output/validation_reports/quality_validation_report.json`.

<AccessNote icon="alert" title="Problemas de calidad de datos conocidos">

- Las agencias usan dos formatos distintos, así que los archivos se deben unificar antes de combinarlos.
- Cerca del 10% de las reservas no tienen moneda, así que su monto no se puede convertir hasta conocer la moneda.
- Algunas reservas ya existen por F2, con leves diferencias en el nombre del huésped y un check-in movido hasta un día. Cuando el mismo huésped, hotel y fechas (±1 día) aparecen en dos canales, la reserva se marca y prevalece la del canal con menor comisión.

</AccessNote>

## Ejecutarlo localmente

Con Python 3.11 o superior y [uv](https://docs.astral.sh/uv/), clona el repositorio y ejecuta el generador:

```bash
git clone https://github.com/HospedaPlus/buenavista-csv.git
cd buenavista-csv
uv sync --extra test
uv run -m buenavista_csv.f4_generator --seed 7 --bookings-per-agency 12 --duplicate-count 3 --missing-currency-rate 0.10
```

El comando muestra cuántos archivos, filas, duplicados y reservas sin moneda generó. Para revisar los archivos, ejecuta `uv run -m buenavista_csv.validator`.

<Note>

Los archivos se vuelven a generar desde cero en cada ejecución. Con la misma semilla y los mismos parámetros, la salida es idéntica, así que las filas de ejemplo de esta página se pueden reproducir.

</Note>
