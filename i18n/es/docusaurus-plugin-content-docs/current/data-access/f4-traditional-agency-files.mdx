# <SourceTitleIcon icon="file" tone="sky" />F4 · Archivos de agencias tradicionales <SourceType>Archivos CSV / Excel</SourceType>

Archivos semanales simulados con las reservas que venden las agencias de viajes tradicionales. Estas agencias no se conectan por API ni por un stream de eventos: cada una envía una hoja de cálculo una vez por semana, en su propio formato. El equipo simula los archivos con un generador en Python.

<AccessTable>

| Propiedad | Valor |
| --- | --- |
| Tipo | Archivos simulados, generados por el equipo |
| Ubicación | Servicio `f4-weekly` en AWS EC2 · código fuente en [HospedaPlus/hospedaplus-csv](https://github.com/HospedaPlus/hospedaplus-csv) |
| Método de acceso | Un archivo CSV o Excel por agencia y semana ISO, por ejemplo `AG07_2026-W45.xlsx` |
| Frecuencia | Semanal, cada lunes 06:00 UTC |
| Volumen | 15 agencias, ~183 reservas por semana |
| Se almacena primero en | **S3 bronze, directo** (archivos crudos, `bronze/f4_agencias/semana=YYYY-Www/`) + **Neon** (cada reserva, con `operation.reservar()`) |

## Cómo se simula

El servicio `f4-weekly` (`python -m buenavista_csv.weekly`, Docker Compose) corre la semana actual apenas arranca y luego cada lunes a las 06:00 UTC:

1. **Genera** los 15 archivos de la semana (`buenavista_csv.f4_generator`). Cada agencia `AG01`…`AG15` recibe 12 reservas por defecto, con un hotel del catálogo compartido (`HP-CO-001`…), fechas relativas a la semana, tipo de habitación, habitaciones, adultos y niños, indicador de reembolsable, el huésped (`guest_ref` `G-0000001`…, compartido con F2 y F3), el monto según las tarifas del catálogo en la moneda del hotel (`COP`, `MXN`, `BRL`, `EUR`, `USD`) y una comisión del 10%.
2. **Valida** los archivos (`buenavista_csv.validator`), sin modificarlos.
3. **Reserva** cada fila en Neon con `operation.reservar('AGxx', …)`, así las reservas de agencia toman habitaciones del mismo inventario que los demás canales.
4. **Sube** los archivos crudos a S3.

Es reproducible (semilla `7`) y se puede reiniciar sin riesgo: una semana que ya existe no se vuelve a generar, y `reservar()` ignora una reserva que ya tiene.

### Frecuencia y volumen

| Variable | Por defecto | Significado |
| --- | --- | --- |
| `F4_RUN_WEEKDAY`, `F4_RUN_HOUR_UTC` | `0`, `6` | Lunes, 06:00 UTC. |
| `F4_BOOKINGS_PER_AGENCY` | `12` | Reservas regulares por agencia: 15 × 12 = 180. |
| `F4_DUPLICATE_RATE` | `0.10` | Reservas extra copiadas de F2 (o `F4_DUPLICATE_COUNT` para un número fijo). |
| `F4_MISSING_CURRENCY_RATE` | `0.10` | Proporción de reservas sin moneda. |

La semana `2026-W45` produjo 183 filas: 21 sin moneda y 3 duplicadas de reservas de F2. Su carga en Neon confirmó 183 reservas con 0 sobreventa.

## Dónde se almacena

<F4Flow />

Los archivos van **directo a S3**, sin cambios, porque son archivos y el lago guarda la copia cruda. Las reservas que traen van a **Neon**, porque ocupan habitaciones reales. El DAG de Airflow `bronze_f4_agencias` corre una hora después y verifica que los 15 archivos de la semana estén en S3.

## Qué contiene

<TabItem value="a" label="Formato A (CSV)" default>

```csv title="AG02_2026-W45.csv"
agency_booking_id,guest_ref,guest_name,hotel_id,check_in,check_out,room_type,rooms,adults,children,rate_type,currency,total_amount,commission_rate
```

Agencias pares. Comisión como fracción, `rate_type` `REFUNDABLE` / `NON_REFUNDABLE`.

</TabItem>
<TabItem value="b" label="Formato B (CSV)">

```csv title="AG01_2026-W45.csv"
booking_ref,hotel_id,guest_code,guest_full_name,checkin_date,checkout_date,room_category,num_rooms,pax_adults,pax_children,non_refundable,amount,currency,commission_pct

```

Agencias impares. Otros nombres y orden de columnas, comisión en porcentaje, `non_refundable` `Y` / `N`.

</TabItem>
<TabItem value="c" label="Formato C (Excel)">

Las agencias `AG03`, `AG07`, `AG11` y `AG15` envían `.xlsx` con encabezados en español: `localizador`, `cod_huesped`, `nombre_huesped`, `hotel`, `fecha_llegada`, `fecha_salida`, `tipo_habitacion`, `habitaciones`, `adultos`, `ninos`, `tarifa` (`reembolsable` / `no_reembolsable`), `importe`, `moneda`, `comision`.

</TabItem>
</Tabs>

Junto a los archivos, `_generation_summary.json` informa las filas por archivo, los duplicados creados y las filas sin moneda, y `_load_report.json` el resultado de `reservar()` para cada fila.

<AccessNote icon="alert" title="Problemas de calidad de datos conocidos">

- Tres formatos con nombres, orden y unidades distintos, así que hay que unificar los archivos antes de combinarlos.
- Cerca del 10% de las reservas no tiene moneda.
- Cerca del 10% de las reservas ya existe en F2 (leídas de Neon con `etl_reader`): mismo hotel, tipo de habitación y check-out, un check-in movido hasta un día, y un nombre de huésped un poco distinto (invertido, solo la inicial, dos letras cambiadas o en minúsculas).

</AccessNote>

## Ejecutarlo localmente

```bash
# Descarga el repositorio F4
git clone https://github.com/HospedaPlus/hospedaplus-csv.git
# Entra a su carpeta
cd hospedaplus-csv
# Crea tu .env a partir del ejemplo (opcional: NEON_READ_URL, NEON_DATABASE_URL, F4_S3_BUCKET)
cp .env.example .env
# Construye la imagen y arranca el job semanal en segundo plano
docker compose up -d --build
# Sigue sus logs (Ctrl+C para salir)
docker compose logs -f f4-weekly
```
