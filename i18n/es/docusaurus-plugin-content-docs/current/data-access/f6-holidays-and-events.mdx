Festivos del país de cada hotel (F6a, datos reales de una API pública) más un archivo de eventos locales como congresos y conciertos (F6b, escrito por el equipo).

</AccessTable>

## Dónde se almacena

**F6a · Festivos → S3.** El día 1 de cada mes (02:00 UTC) el DAG de Airflow `bronze_f6_holidays` llama la API para Portugal, Colombia, México, Brasil y España, para el año actual y el siguiente (las reservas se hacen con meses de anticipación), y guarda cada respuesta tal como llega:

```bash
curl https://nagerholidays.com/api/v4/Holidays/PT/2026   # $NAGER_BASE_URL
# -> s3://…/bronze/f6_holidays/anio=2026/pais=PT.json
```

**F6b · Eventos locales → Neon, luego S3.** Los 33 eventos viven en un CSV versionado en `db_simulated`. `python -m seed events` los carga en `operation.local_events` (el CI/CD los recarga cada vez que cambia el CSV), porque la base los necesita para fijar los límites de sobreventa. Todos los días a las 02:30 UTC el DAG `bronze_f6_events` copia la tabla a `s3://…/bronze/f6_events/`.

Los dos alimentan `silver/calendario_hotel/` (hotel × día con festivo, evento y fin de semana).

## Cómo se usa

- Un festivo o evento local en una fecha agrega un multiplicador de precio extra de 1,15.
- Nunca se permite sobreventa en fechas con un evento de categoría "alta" (`refresh_overbooking_limits()` deja el límite en 0).
