# Fuentes de datos

HospedaPlus Revenue integra siete fuentes de datos, de F1 a F7. F1, F6 y F7 son datos públicos reales. F2 a F5 son **simuladas**: el equipo construyó un generador para cada una, corre todo el tiempo en AWS y produce datos con la frecuencia y el volumen que pide el proyecto.

## Dónde se almacena primero cada fuente

<SourcesFlow />

- **Primero en Neon (F2, F3, eventos F6, reservas F4).** Son datos operativos: toda reserva, venga del canal que venga, pasa por la misma función `operation.reservar()`, así que todos los canales comparten un solo inventario y nunca hay sobreventa. El pipeline lee Neon con un rol de solo lectura y copia los cambios a S3 cada hora, más una foto completa cada noche.
- **Primero en S3 (F1, archivos F4, festivos F6, F7).** Son archivos o APIs públicas sin nada que operar, así que van a `s3://…/bronze/` tal como llegan, sin cambios.
- **F5** guarda sus reseñas en la base propia de la API, como lo haría una plataforma real; el pipeline lee la API cada hora.

<Note>
  **Semilla de datos.** Todos los datos de las fuentes simuladas los genera código versionado en cada repositorio. Los generadores usan una semilla aleatoria fija para que los datos sean reproducibles, son idempotentes, permiten elegir el volumen (modo pequeño de desarrollo o modo completo), mantienen la integridad referencial con un solo catálogo compartido (los mismos códigos de hotel, tipo de habitación, canal y huésped en todas partes), inyectan los problemas de calidad conocidos con una tasa configurable y corren tanto en local con Docker como en AWS.
</Note>

<AccessNote icon="alert" title="Problemas de calidad de datos conocidos">

Los datos llegan con los siguientes defectos, y las fuentes simuladas los inyectan a propósito:

- F1 tiene `"NULL"` como texto en los campos de agente y empresa, y valores de ADR negativos o extremos.
- Reservas con cero adultos, cero niños y cero bebés (F1, F3).
- Fechas de salida anteriores a la fecha de llegada (F3).
- Monedas faltantes en los archivos de agencias (F4, ~10%).
- Reservas duplicadas entre canales con pequeñas diferencias en el nombre del huésped (F4, ~10%), y reseñas duplicadas entre plataformas (F5, ~5%).
- Eventos de modificación que llegan antes del evento de creación (F2, ~5%).

</AccessNote>
