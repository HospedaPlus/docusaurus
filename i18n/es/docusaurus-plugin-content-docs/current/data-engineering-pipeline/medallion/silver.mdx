# Capa silver

Silver convierte las copias crudas de bronze en **una tabla limpia y confiable por entidad**. Cada job está escrito en PySpark (`spark_jobs/silver_*.py`), corre en el worker `silver`, lee bronze con un esquema explícito (sin pasada de inferencia), corre sus controles de calidad y solo entonces sobrescribe su carpeta Parquet.

| Tabla silver | Se construye con | Una fila por | Uso principal |
| --- | --- | --- | --- |
| `tasa_cambio_diaria` | F7 | día × moneda | Convertir cada monto a COP |
| `reservas` | Reservas en Neon (F2, F3, F4) + catálogos + FX | código de reserva | P1, P3, P4 |
| `cancelaciones` | `reservas` | reserva cancelada / no-show | P1 |
| `reservas_rechazadas` | Anomalías en Neon | reserva rechazada | Calidad de datos (defectos 5.3) |
| `ocupacion_diaria` | Foto de Neon: inventario, reubicaciones, rechazos | hotel × tipo de habitación × noche | P2, P3 |
| `calendario_hotel` | Festivos F6 + eventos F6 + hoteles | hotel × día | P3 |
| `resenas` | Reseñas F5 + hoteles | reseña (original) | P5 |
| `historico_f1` | CSV Kaggle F1 | reserva histórica | P1 |

## Transformaciones: cómo y por qué

### `tasa_cambio_diaria` (F7)

1. Lee todas las respuestas de Frankfurter (filas `date, base, quote, rate`, base USD) y agrega USD = 1.
2. Arma una **grilla diaria** desde la primera hasta la última fecha para cada moneda y llena cada día con la **última tasa conocida** (relleno hacia adelante).
3. Calcula `cop_por_unidad = tasa(USD→COP) / tasa(USD→moneda)`.

**Por qué:** no hay tasas los fines de semana ni festivos, pero sí hay reservas, así que cada día del calendario necesita una tasa. Frankfurter v2 puede fechar cada moneda distinto (EUR o MXN pueden venir con otra fecha que COP), así que cada moneda se rellena en su propia grilla **antes** de dividir por COP; si no, se perderían días enteros.
**Controles:** no vacía, sin nulos, `(fecha, moneda)` único, tasa > 0, sin días faltantes.

Código (`spark_jobs/silver_fx.py`):

```python
rates = (raw.select(F.to_date("date").alias("fecha"), F.col("quote").alias("moneda"),
                    F.col("rate").cast("double").alias("rate"))
         .dropna().dropDuplicates(["fecha", "moneda"]))           # + USD = 1.0 every day
days = bounds.select(F.explode(F.sequence("a", "b")).alias("fecha"))   # every calendar day
grid = days.crossJoin(rates.select("moneda").distinct())               # day x currency
w = Window.partitionBy("moneda").orderBy("fecha").rowsBetween(Window.unboundedPreceding, 0)
filled = (grid.join(rates, ["fecha", "moneda"], "left")
          .withColumn("rate", F.last("rate", ignorenulls=True).over(w))  # forward fill
          .dropna(subset=["rate"]))
cop = filled.filter("moneda = 'COP'").select("fecha", F.col("rate").alias("usd_cop"))
out = filled.join(cop, "fecha").select(
    "fecha", "moneda", (F.col("usd_cop") / F.col("rate")).alias("cop_por_unidad"))
```

### `reservas`, `cancelaciones`, `reservas_rechazadas` (F2, F3, F4)

Todos los canales escriben en `operation.reservations` con `reservar()`, así un solo job maneja todas las reservas.

1. **Leer solo lo necesario:** la foto completa más reciente (con `_SUCCESS`) más los archivos horarios desde el día anterior a esa foto.
2. **Versión más reciente por código.** La misma reserva aparece varias veces (creada, modificada, cancelada). Una ventana por `code` se queda con la fila de `updated_at` más reciente (o, en archivos viejos, la más reciente entre creada/cancelada/último evento); en empate gana el archivo horario sobre la foto.
   **Por qué:** silver debe mostrar el estado actual de cada reserva, exactamente una vez.
3. **Unir los catálogos** (última copia de hoteles, canales, tipos de habitación) para obtener código de hotel, país, categoría, zona horaria, tipo de canal y comisión.
4. **Campos derivados:** `noches`, `huespedes`, `fecha_reserva`, `lead_time_dias` (check-in − fecha de reserva), `es_cancelada` (cancelada o no-show), `es_duplicado` (estado `duplicate`).
5. **Moneda a COP** con la tasa del día de la reserva. Las reservas anteriores a la primera tasa publicada usan la más antigua y se marcan `fx_estimada = true`.
   **Por qué:** el negocio reporta en COP, y los hoteles venden en EUR, COP, MXN y BRL.
6. **Comisión y neto:** `comision_cop = total_cop × % de comisión del canal` y `neto_cop = total_cop − comision_cop` (P4).
7. **`cancelaciones`:** solo reservas canceladas / no-show que no son duplicadas, con `horas_antes_checkin` (desde la cancelación hasta el check-in a las 15:00) y un rango de anticipación (`0-1`, `1-3`, `3-7`, `7-30`, `30-90`, `90+` días) para P1.
8. **`reservas_rechazadas`:** reservas que Neon rechazó (cero huéspedes, check-out antes del check-in), una por código.

Cómo se trata cada defecto de calidad de las fuentes:

| Defecto | Dónde se trata | Resultado en silver |
| --- | --- | --- |
| F3 cero huéspedes / check-out antes del check-in | Neon lo rechaza y lo registra en `reservation_anomalies` | `reservas_rechazadas`, nunca en métricas |
| F4 reserva duplicada | Marcada `duplicate` en Neon | `es_duplicado = true`, excluida de toda métrica gold |
| F4 moneda faltante | El cargador usa la moneda del hotel | Se conserva |
| F2 eventos fuera de orden | Resuelto en Neon (`last_event_at`) | Ya en orden |

**Controles:** no vacía, `code` único, ninguna fila sin `total_cop` (el error dice qué fuente/moneda no tiene tasa), sin nulos en columnas clave, `check_out > check_in`, al menos un adulto, sin montos negativos, códigos únicos en `cancelaciones`. La tabla se particiona por `source` (F2, F3, F4).

Código (`spark_jobs/silver_reservas.py`):

```python
# 1. newest full snapshot + hourly files from the day before it on
def plan_days(full_days, hourly_days):
    newest = full_days[-1]
    since = (dt.date.fromisoformat(newest) - dt.timedelta(days=1)).isoformat()
    return [newest], [d for d in hourly_days if d >= since]

# 2. one row per booking code: the newest version (hourly file wins a tie: _src = 1)
version = F.coalesce(F.to_timestamp("updated_at"), legacy_greatest_of_dates)
w = Window.partitionBy("code").orderBy(F.col("_version").desc(), F.col("_src").desc())
r = raw.withColumn("_version", version).withColumn("_rn", F.row_number().over(w)).filter("_rn = 1")

# 4. derived fields
df = (df.withColumn("noches", F.datediff("check_out", "check_in"))
        .withColumn("lead_time_dias", F.datediff("check_in", "fecha_reserva"))
        .withColumn("es_duplicado", F.col("status") == "duplicate")
        .withColumn("es_cancelada", F.col("status").isin("cancelled", "no_show")))

# 5-6. COP with the rate of the booking day, then commission and net
df = (df.join(F.broadcast(fx), ["currency", "fecha_reserva"], "left")
        .withColumn("fx_estimada", F.col("_tasa").isNull())
        .withColumn("tasa_cop", F.coalesce("_tasa", "_tasa_min")))
df = (df.withColumn("total_cop", F.round(F.col("total") * F.col("tasa_cop"), 2))
        .withColumn("comision_cop", F.round(F.col("total_cop") * F.col("comision_pct") / 100, 2))
        .withColumn("neto_cop", F.col("total_cop") - F.col("comision_cop")))

# 7. hours between cancellation and check-in (15:00)
horas = (F.unix_timestamp(F.to_timestamp(F.concat_ws(" ", F.col("check_in").cast("string"), F.lit("15:00:00"))))
         - F.unix_timestamp("cancelada_en")) / 3600
```

### `ocupacion_diaria` (inventario F3)

1. Toma la foto de inventario más reciente: habitaciones, vendidas y límite de sobreventa por hotel, tipo de habitación y noche.
2. Agrega **reubicaciones** por noche y **habitaciones rechazadas** por noche (cada reserva rechazada se abre en sus noches).
3. Calcula `disponibles = habitaciones + límite de sobreventa − vendidas`, `ocupacion_pct` y `sobrevendidas` (vendidas por encima de las habitaciones físicas).

**Por qué:** P2 (sobreventa) y P3 (ingresos) necesitan una vista densa noche a noche de la capacidad y de cuántas veces la sobreventa afectó a un huésped.
**Controles:** `(hotel, tipo de habitación, noche)` único, sin nulos, y nunca vendido por encima de habitaciones + límite de sobreventa.

Código (`spark_jobs/silver_ocupacion.py`):

```python
# rejected bookings: one row per night they wanted
nights = F.explode(F.sequence(F.to_date("check_in"), F.date_sub(F.to_date("check_out"), 1)))
j = (rej.select("hotel_id", "room_type_id", nights.alias("fecha"), F.col("rooms_count").cast("int").alias("n"))
     .groupBy("hotel_id", "room_type_id", "fecha").agg(F.sum("n").alias("habitaciones_rechazadas")))

out = (base.join(j, KEY, "left").fillna(0, ["reubicadas", "habitaciones_rechazadas"])
       .withColumn("disponibles", F.col("habitaciones") + F.col("limite_sobreventa") - F.col("vendidas"))
       .withColumn("ocupacion_pct", F.round(F.col("vendidas") * 100.0 / F.col("habitaciones"), 2))
       .withColumn("sobrevendidas", F.greatest(F.lit(0), F.col("vendidas") - F.col("habitaciones"))))

# check: never sold above rooms + overbooking limit
bad = out.filter("vendidas > habitaciones + limite_sobreventa OR vendidas < 0").count()
```

### `calendario_hotel` (F6)

1. Lee los festivos de Nager (tolerante a la forma de la respuesta) y toma el país del nombre del archivo.
2. Arma una fila por **hotel × día** y marca `es_festivo` con el nombre del festivo del país del hotel.
3. Agrega los **eventos locales** del hotel (los eventos de varios días se abren en cada día; si se cruzan varios, gana la categoría más alta: low < medium < high).
4. Agrega año, mes, día de la semana y fin de semana.

**Por qué:** los festivos dependen del país y los eventos del hotel, así que el calendario debe ser por hotel. Gold lo une con la ocupación y el precio (P3).
**Controles:** `(hotel, día)` único, sin nulos, sin días faltantes.

Código (`spark_jobs/silver_calendario.py`):

```python
cal = (hotels.crossJoin(days)                         # hotel x every day
       .join(holidays, ["pais", "fecha"], "left")       # holiday of the hotel's country
       .withColumn("es_festivo", F.col("nombre_festivo").isNotNull()))

ev = (events.select("hotel_code", "name", "category",
                    F.explode(F.sequence(F.to_date("start_date"), F.to_date("end_date"))).alias("fecha"))
      .withColumn("_rank", rank[F.col("category")])     # low=1, medium=2, high=3
      .groupBy("hotel_code", "fecha")
      .agg(F.concat_ws(" / ", F.collect_set("name")).alias("evento"), F.max("_rank").alias("_rank")))
```

### `resenas` (F5)

1. **Última versión** de cada id de reseña (las reseñas editadas vuelven con un `updated_at` más nuevo).
2. **Duplicados entre plataformas:** el mismo huésped publica la misma reseña en otra plataforma minutos u horas después, con una variante del nombre y a veces sin el punto final. Mismo hotel + fecha de estadía + puntaje + texto normalizado (minúsculas, sin espacios extremos, sin puntuación final) = la misma reseña. Se queda la primera publicada y `copias_en` / `duplicados` dicen dónde se copió.
3. País del hotel desde el catálogo y **sentimiento** según el puntaje: 4–5 positivo, 3 neutro, 1–2 negativo.

**Por qué:** sin quitar duplicados, una misma opinión contaría varias veces en la reputación (P5).
**Controles:** `review_id` único, sin nulos, puntaje entre 1 y 5, hotel conocido. Particionada por `fecha_publicacion`.

Código (`spark_jobs/silver_resenas.py`):

```python
def _norm_text(c):   # "Great stay." == "great stay"
    return F.regexp_replace(F.lower(F.trim(c)), r"[\s.!]+$", "")

w_id = Window.partitionBy("id").orderBy(F.to_timestamp("updated_at").desc())
latest = raw.withColumn("_rn", F.row_number().over(w_id)).filter("_rn = 1")   # newest edit

key = ["hotel_code", "fecha_estadia", "puntaje", "_texto_norm"]
w_dup = Window.partitionBy(*key).orderBy("publicada_en", "review_id")
r = (r.withColumn("_texto_norm", _norm_text(F.col("texto")))
      .withColumn("_rn", F.row_number().over(w_dup))
      .withColumn("copias_en", F.collect_set("plataforma").over(Window.partitionBy(*key))))
original = (r.filter("_rn = 1")                                   # first one published
             .withColumn("copias_en", F.expr("array_remove(copias_en, plataforma)"))
             .withColumn("duplicados", F.size("copias_en")))
sentimiento = (F.when(F.col("puntaje") >= 4, "positivo")
                .when(F.col("puntaje") == 3, "neutro").otherwise("negativo"))
```

### `historico_f1` (F1)

1. Renombra y tipa las columnas de Kaggle, arma la fecha de llegada, noches, huéspedes e ingreso (`adr × noches`, en EUR).
2. Traduce `market_segment` a los tipos de canal del proyecto (Online TA → `ota`, Offline TA/TO y Groups → `agency`, Corporate y Aviation → `corporate`, Direct y Complementary → `direct`).
3. Mismos rangos de anticipación que `cancelaciones`.
4. Descarta las filas sin huéspedes, sin noches, con ADR negativo o sin fecha de llegada, y las cuenta.

**Por qué:** F1 es el historial largo (2015–2017) que explica cómo la cancelación depende de la anticipación y del tipo de depósito, algo que los datos en vivo no tienen. Los montos se quedan en EUR porque las tasas solo empiezan en 2026.

Código (`spark_jobs/silver_f1.py`):

```python
CHANNEL_TYPE = {"Online TA": "ota", "Offline TA/TO": "agency", "Groups": "agency",

                "Aviation": "corporate"}

arrival = F.to_date(F.concat_ws("-", "arrival_date_year", "arrival_date_month",
                                "arrival_date_day_of_month"), "yyyy-MMMM-d")

def split_valid(df):
    ok = "huespedes > 0 AND noches > 0 AND adr_eur >= 0 AND fecha_llegada IS NOT NULL"
    return df.filter(ok), df.filter(f"NOT ({ok})").count()   # kept rows, dropped count
```

### Cómo protege cada job a silver

Todos los jobs de silver siguen los mismos tres pasos: **transformar → validar → sobrescribir**. Los controles viven en un solo módulo:

```python title="spark_jobs/quality.py"
class QualityError(Exception): ...

def unique(df, name, keys):
    dup = df.groupBy(*keys).count().filter("count > 1").count()
    if dup:
        raise QualityError(f"{name}: {dup} duplicated keys {keys}")

# every job:  transform -> check(out) -> out.write.mode("overwrite").parquet(...)
# if check() raises, the Airflow task fails and yesterday's Parquet stays untouched
```

## Cuánto tarda

Toda la capa silver corre en unos 2 minutos. `silver_reservas_daily` también corre después de cada copia horaria de bronze, así silver va una hora detrás de Neon.
