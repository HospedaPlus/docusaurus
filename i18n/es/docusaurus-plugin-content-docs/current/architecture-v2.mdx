# Architecture v2

Esta es la arquitectura final de HospedaPlus Revenue en AWS (región **us-east-2, Ohio**): tres EC2 con Docker Compose, Kafka para F2, Airflow 3.1.5 con Celery sobre RabbitMQ, Spark en modo local en los workers, S3 + Athena (Glue Data Catalog llenado con DDL) y Power BI por ODBC.

## Cambios frente a la versión anterior

| Antes | Ahora | Por qué |
| --- | --- | --- |
| Spark en Fargate / EMR | **Spark local** en el EC2 de workers (t3.xlarge) | ~200.000 reservas caben en una máquina; no hay clúster que pagar ni operar |
| Amazon ECR | **GitHub Container Registry (GHCR)** | Las imágenes las construye el CI junto al código |
| Glue Crawler | **Athena DDL** (`CREATE EXTERNAL TABLE`) | La cuenta no permite crawlers; el DDL da nombres y tipos exactos |
| EKS, ALB, WAF, NAT, Secrets Manager | No se usan | No hacen falta a este tamaño; los secretos viven en `.env` fuera del repo y en secretos de GitHub |
| Límites de sobreventa calculados en la operación | **Writeback de gold a Neon** | La operación usa las mismas tasas de cancelación que ve el negocio |
| Precios de F2 por RabbitMQ | **F2 por Kafka** a Neon | RabbitMQ es solo el broker de Celery |
| Kafka y simuladores repartidos | Un **EC2 de fuentes** | Una máquina para todos los simuladores |

## Bloque por bloque

### 1. Fuentes y equipo

- **Equipo dev · GitHub Actions**: ruff, pytest y validación de DAGs; en cada merge sube una imagen a GHCR y despliega por SSH.
- **Equipo de datos**: entra a las máquinas por SSH y abre las UIs de Airflow (`:8080`) y Flower (`:5555`).
- **Productor F2** (eventos OTA, contrato 1.3) y **simulador F3** (`seed simulate`, reservas directas, rol `app_writer`).
- **APIs F5 · F6 · F7**: la API de reseñas del equipo (FastAPI en ECS), Nager.Date y Frankfurter, leídas por HTTPS.
- **F1 Kaggle**: `hotel_bookings.csv` del repo `hospedaplus-csv`, cargado una vez.
- **Catálogo compartido**: la fuente canónica es `db_simulated` (Neon); F2, F4 y F5 usan sus códigos de hotel, tipo de habitación, canal y moneda.

### 2. Entrada

- **GHCR** guarda las imágenes (`ghcr.io/hospedaplus/…`, etiquetas `:sha`, `:main` y `vX.Y.Z`).
- **Internet Gateway** hacia la VPC (subred pública, IPs públicas).
- **Security groups**: `sg-nucleo` abre 22, 8080, 5555 y 15672 solo a la IP del equipo, 80/443 para Nginx (las [UIs de monitoreo](./data-engineering-pipeline/monitoring.mdx)), y 5432, 5672 y 8080 solo a `sg-workers`; `sg-workers` abre 22 al equipo. Los workers llegan al núcleo por su **IP privada**.

### 3. Procesamiento: EC2 en us-east-2

- **EC2 de fuentes** (Docker Compose): `buenavista-streaming` (productor F2 → **Kafka 4.1.1**, tópico `reservation.events.v1_3`, 6 particiones + DLQ → 6 `neon-consumer` que llaman `reservar()`), `db_simulated` (F3 `seed simulate`) y `hospedaplus-csv` (`f4-weekly`, lunes 06:00 UTC, 15 agencias → S3 y Neon).
- **EC2 núcleo** (t3.medium, 30 GB): Airflow 3.1.5 con CeleryExecutor (API server, scheduler, DAG processor, triggerer, PostgreSQL de metadatos), RabbitMQ (colas `bronze`, `silver`, `gold`) y Flower.
- **EC2 workers** (t3.xlarge, 50 GB): tres workers de Celery. **bronze** corre 4 tareas a la vez (Python: Neon, APIs F5–F7, F1 y F4 → `bronze/`); **silver** corre 2 (Spark local: valida, deduplica, pasa a COP); **gold** corre 2 (Spark local: `dim_`, `fact_`, `mart_` P1–P5 y el writeback). Spark 3.5 lee y escribe S3 con `s3a://` usando el rol IAM del EC2. Detalle en [Cómputo y recursos](./data-engineering-pipeline/compute-resources.mdx).

### OLTP: Neon PostgreSQL (SaaS externo)

Esquemas `operation` y `streaming`, ramas `development` y `production`, y `reservar()` con el límite de sobreventa (hoy 0). El pipeline la lee con `etl_reader` cada hora y con una copia completa a las 03:00 UTC, y le devuelve las tasas de cancelación con `app_writer`.

### 4. Data lake (OLAP)

- **Amazon S3 `hospedaplus-lakehouse-buenavista`**, acceso público bloqueado: `bronze/` (JSON/CSV tal cual se extrajo), `silver/` (Parquet: reservas, cancelaciones, ocupación, calendario, reseñas, fx, histórico F1), `gold/` (Parquet: 4 dims, 4 facts, 7 marts, y un JSON para el writeback a Neon), `airflow-logs/` y `athena-results/`.
- Cada DAG publica un **Asset** al terminar y el siguiente arranca solo.
- **Athena DDL → Glue Data Catalog** (`hospedaplus_gold`, se repite solo si cambia un esquema) → **Amazon Athena** (workgroup `primary`).

### 5. Analítica y decisión

**Power BI Desktop** lee gold con el driver ODBC de Amazon Athena (x64) como el usuario IAM de solo lectura `powerbi-reader`; el reporte tiene 4 páginas. El **Revenue Manager y los gerentes** lo usan para decidir precio y ocupación por hotel. Ver [Visualización de datos](./data-visualization/index.mdx).

## Seguridad y operación: lo que hoy está configurado

| Área | Qué hay |
| --- | --- |
| IAM | Rol `hospedaplus-pipeline-role` en núcleo y workers, solo sobre el bucket. Usuario `powerbi-reader`: Athena, Glue y S3 en lectura. |
| Security groups | `sg-nucleo`, `sg-workers`: puertos abiertos solo a la IP del equipo y entre los dos grupos. |
| Credenciales | `.env` en cada EC2 (fuera del repo), secretos de despliegue en GitHub, llaves de AWS vacías (las da el rol). |
| Roles de Neon | `hospedaplus_owner` (migraciones), `app_writer` (consumidores, simuladores, writeback), `etl_reader` (Airflow). |
| S3 | Acceso público bloqueado; logs de Airflow en `airflow-logs/`, resultados de Athena en `athena-results/`. |
| Monitoreo | Flower para los workers, la UI de Airflow, `docker compose logs` y el lag del grupo de Kafka. Ver [Monitoreo](./data-engineering-pipeline/monitoring.mdx). |

## Flujos de datos (leyenda)

- **Tiempo real / OLTP (rosado):** eventos F2 por Kafka y cargas F3/F4 que llaman `reservar()` en Neon.
- **CI/CD y control (morado, punteado):** imágenes en GHCR, despliegue por SSH, órdenes de Airflow por RabbitMQ.
- **Batch / OLAP (azul):** extracción a bronze, luego bronze → silver → gold (workers de Celery + Spark local).
- **Catálogo (verde azulado, punteado):** tablas creadas con Athena DDL en el Glue Data Catalog (sin crawler).
- **Writeback (naranja):** gold → Neon `operation.cancellation_rate_by_lead` (upsert diario).
- **Consumo de gold (verde):** Athena → Power BI (ODBC) → gerentes.
- **Pendiente (gris, punteado):** API de negocio con FastAPI (US-41).
