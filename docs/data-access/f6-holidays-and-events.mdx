# <SourceTitleIcon icon="calendar" tone="blue" />F6 · Holidays and events <SourceType>REST API + CSV</SourceType>

Public holidays of each hotel's country (F6a, real data from a public API) plus a file of local events such as conferences and concerts (F6b, written by the team).

<AccessTable>

| Property | Value |
| --- | --- |
| Type | Real data, public API + team CSV |
| Location | F6a: [Nager.Date](https://date.nager.at) API v4 · F6b: `data/local_events.csv` in [HospedaPlus/db_simulated](https://github.com/HospedaPlus/db_simulated) |

</AccessTable>

## Where it is stored

**F6a · Holidays → S3.** On day 1 of each month (02:00 UTC) the Airflow DAG `bronze_f6_holidays` calls the API for Portugal, Colombia, Mexico, Brazil and Spain, for the current and the next year (bookings are made months ahead), and saves each answer as it comes:

```bash
curl https://nagerholidays.com/api/v4/Holidays/PT/2026   # $NAGER_BASE_URL
# -> s3://…/bronze/f6_holidays/anio=2026/pais=PT.json
```

**F6b · Local events → Neon, then S3.** The 33 events live in a CSV versioned in `db_simulated`. `python -m seed events` loads them into `operation.local_events` (CI/CD reloads them every time the CSV changes), because the database needs them to set the overbooking limits. Every day at 02:30 UTC the DAG `bronze_f6_events` copies the table to `s3://…/bronze/f6_events/`.

Both feed `silver/calendario_hotel/` (hotel × day with holiday, event and weekend).

## How it is used

- A holiday or local event on a date adds an extra price multiplier of 1.15.
- Overbooking is never allowed on dates with a "high" category event (`refresh_overbooking_limits()` sets the limit to 0).
