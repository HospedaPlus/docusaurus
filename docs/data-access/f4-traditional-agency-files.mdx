## How to access it

Each agency delivers one CSV file per week, and the platform loads the files in batch. In the simulation, the generator writes the 15 weekly files to `output/f4_agency_files/`, together with a summary of what it generated.

## How the data is generated

The generator is the module `buenavista_csv.f4_generator` of the [buenavista-csv](https://github.com/HospedaPlus/buenavista-csv) repository. It creates one file per agency with these rules:

- **Reproducible.** It uses a fixed seed (`7` by default), so running it again produces exactly the same files.
- **Regular bookings.** Each agency gets 12 bookings by default. Each booking has a random hotel from `hotel-001` to `hotel-028`, a check-in between 1 November 2026 and 30 January 2027, a stay of 1 to 6 nights, a room type (`SINGLE`, `DOUBLE`, `TWIN` or `SUITE`), a currency (`EUR` or `USD`) and an amount between 80 and 2,000.
- **Fixed commission.** Every booking carries a commission of `0.10`, the 10% that traditional agencies charge.
- **Booking ids.** Ids follow the pattern `AG<agency>-<counter>`, for example `AG01-00001`. The counter keeps growing across agencies, so an id is never repeated.
- **Two layouts.** Agencies alternate between two column layouts to simulate that each agency uses its own format. The 8 odd-numbered agencies use Layout B and the 7 even-numbered agencies use Layout A.

### Parameters

| Parameter | Default | Description |
| --- | --- | --- |
| `--seed` | `7` | Seed for the random generator. |
| `--bookings-per-agency` | `12` | Regular bookings per agency. |
| `--duplicate-count` | `3` | Bookings copied from F2 to create duplicates across channels. |
| `--missing-currency-rate` | `0.10` | Share of bookings without a currency, between `0.0` and `1.0`. |
| `--f2-events` | `data/f2_reference/events.jsonl` | F2 events used as the origin of the duplicates. |
| `--output-dir` | `output/f4_agency_files` | Folder where the files are written. |

### Defects it injects

The generator adds two of the data quality defects that the platform must handle:

- **Missing currency.** About 10% of the bookings have an empty `currency` field. With the default seed, 14 of the 183 bookings have no currency.
- **Duplicates across channels.** The generator reads `reservation.created` events from [F2](./f2-channel-manager-events.mdx) and copies some of them into the agency files. The copy keeps the hotel, check-out, room type, currency and amount, but gets a new agency id, a check-in moved by −1, 0 or +1 day, and usually a slightly different guest name. The generator changes the name in one of these ways: first and last name swapped (`Ferreira Diego`), last name reduced to its initial (`Diego F.`), two letters swapped (`Diego Ferriera`) or last name in lowercase (`Diego ferreira`). With the default values, the first three agencies get one duplicate each.

F2 events don't include the guest's name, so the generator derives one from each `reservation_id` with its own seed. That way the original F2 booking and its F4 copy can be compared by name.

### Columns

This table maps each Layout B column to its Layout A name, which is the name used once the files are unified:

| Layout A | Layout B | Type | Description |
| --- | --- | --- | --- |
| `agency_booking_id` | `booking_ref` | text | Booking id in the agency, for example `AG01-00001`. |
| `guest_name` | `guest_full_name` | text | Name of the guest. It is personal data. |
| `hotel_id` | `hotel_id` | text | Hotel code, from `hotel-001` to `hotel-028`. |
| `check_in` | `checkin_date` | date `YYYY-MM-DD` | Arrival date. |
| `check_out` | `checkout_date` | date `YYYY-MM-DD` | Departure date, always after the arrival. |
| `room_type` | `room_category` | text | `SINGLE`, `DOUBLE`, `TWIN` or `SUITE`. |
| `currency` | `currency` | text, may be empty | `EUR` or `USD`. |
| `total_amount` | `amount` | decimal | Total amount of the booking, before commission. |
| `commission_rate` | `commission_pct` | decimal | Agency commission, always `0.1`. |

### Output validation

The repository also includes a validator, `buenavista_csv.validator`, that checks the files without changing them. It recognizes the layout of each file by its header and reports every defect it finds by type, such as `MISSING_CURRENCY` or `CROSS_CHANNEL_DUPLICATE`. With the default run, the result is `PASSED_WITH_CATALOGUED_DEFECTS`: the 15 files have a valid structure, and it finds 14 bookings without currency and 3 duplicates. The report is written to `output/validation_reports/quality_validation_report.json`.

<AccessNote icon="alert" title="Known data quality issues">

- Agencies use two different layouts, so the files must be unified before they are combined.
- About 10% of the bookings have no currency, so their amount can't be converted until the currency is known.
- Some bookings already exist through F2, with slight differences in the guest's name and a check-in moved by up to one day. When the same guest, hotel and dates (±1 day) appear in two channels, the booking is flagged and the one from the channel with the lowest commission prevails.

</AccessNote>

## Run it locally

With Python 3.11 or later and [uv](https://docs.astral.sh/uv/), clone the repository and run the generator:

```bash
git clone https://github.com/HospedaPlus/buenavista-csv.git
cd buenavista-csv
uv sync --extra test
uv run -m buenavista_csv.f4_generator --seed 7 --bookings-per-agency 12 --duplicate-count 3 --missing-currency-rate 0.10
```

The command prints how many files, rows, duplicates and bookings without currency it generated. To check the files, run `uv run -m buenavista_csv.validator`.

<Note>

Files are regenerated from scratch on each run. With the same seed and parameters, the output is identical, so the sample rows on this page can be reproduced.

</Note>
