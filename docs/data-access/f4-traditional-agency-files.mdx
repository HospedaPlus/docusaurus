# <SourceTitleIcon icon="file" tone="sky" />F4 · Traditional agency files <SourceType>CSV / Excel files</SourceType>

Simulated weekly files with the bookings sold by traditional travel agencies. These agencies don't connect through an API or an event stream: each one sends a spreadsheet once a week, in its own format. The team simulates the files with a Python generator.

| Access method | One CSV or Excel file per agency and ISO week, e.g. `AG07_2026-W45.xlsx` |

| Volume | 15 agencies, ~183 bookings per week |
| Stored first in | **S3 bronze, directly** (raw files, `bronze/f4_agencias/semana=YYYY-Www/`) + **Neon** (each booking, through `operation.reservar()`) |

## How it is simulated

The service `f4-weekly` (`python -m buenavista_csv.weekly`, Docker Compose) runs the current week as soon as it starts and then every Monday at 06:00 UTC:

1. **Generates** the 15 files of the week (`buenavista_csv.f4_generator`). Each agency `AG01`…`AG15` gets 12 bookings by default, with a hotel from the shared catalog (`HP-CO-001`…), dates relative to the week, room type, rooms, adults and children, refundable flag, the guest (`guest_ref` `G-0000001`…, shared with F2 and F3), the amount from the catalog rates in the hotel's currency (`COP`, `MXN`, `BRL`, `EUR`, `USD`) and a 10% commission.
2. **Validates** them (`buenavista_csv.validator`), without changing them.
3. **Books** every row in Neon with `operation.reservar('AGxx', …)`, so agency bookings take rooms from the same inventory as the other channels.
4. **Uploads** the raw files to S3.

It is reproducible (seed `7`) and safe to restart: an existing week is not generated again, and `reservar()` ignores a booking it already has.

### Frequency and volume

| Variable | Default | Meaning |
| --- | --- | --- |
| `F4_RUN_WEEKDAY`, `F4_RUN_HOUR_UTC` | `0`, `6` | Monday, 06:00 UTC. |
| `F4_BOOKINGS_PER_AGENCY` | `12` | Regular bookings per agency: 15 × 12 = 180. |
| `F4_DUPLICATE_RATE` | `0.10` | Extra bookings copied from F2 (or `F4_DUPLICATE_COUNT` for a fixed number). |
| `F4_MISSING_CURRENCY_RATE` | `0.10` | Share of bookings without a currency. |

Week `2026-W45` produced 183 rows: 21 without currency and 3 duplicates of F2 bookings. Its Neon load confirmed 183 bookings with 0 overbooking.

## Where it is stored

```text
f4-weekly ─┬─ files ─► EC2 ./output/f4_agency_files/<week>/ ─► S3 bronze/f4_agencias/semana=<week>/
           └─ rows  ─► Neon operation.reservar('AGxx', …)
Airflow bronze_f4_agencias (Monday 07:00 UTC) checks and registers the week in S3
```

The files go **straight to S3**, unchanged, because they are files and the lake keeps the raw copy. The bookings in them go to **Neon**, because they take real rooms. The Airflow DAG `bronze_f4_agencias` runs one hour later and checks that the 15 files of the week are in S3.

Odd-numbered agencies. Other column names and order, commission in percent, `non_refundable` `Y` / `N`.

</TabItem>
<TabItem value="c" label="Layout C (Excel)">

Agencies `AG03`, `AG07`, `AG11` and `AG15` send `.xlsx` with Spanish headers: `localizador`, `cod_huesped`, `nombre_huesped`, `hotel`, `fecha_llegada`, `fecha_salida`, `tipo_habitacion`, `habitaciones`, `adultos`, `ninos`, `tarifa` (`reembolsable` / `no_reembolsable`), `importe`, `moneda`, `comision`.

</TabItem>

Next to the files, `_generation_summary.json` reports the rows per file, the duplicates created and the rows without currency, and `_load_report.json` the result of `reservar()` for each row.

<AccessNote icon="alert" title="Known data quality issues">

- Three layouts with different names, order and units, so the files must be unified before they are combined.
- About 10% of the bookings have no currency.
- About 10% of the bookings already exist in F2 (read from Neon with `etl_reader`): same hotel, room type and check-out, a check-in moved by up to one day, and a slightly different guest name (swapped, initial only, two letters swapped or lowercase).

</AccessNote>

## Run it locally

```bash
git clone https://github.com/HospedaPlus/hospedaplus-csv.git
cd hospedaplus-csv
cp .env.example .env          # optional: NEON_READ_URL, NEON_DATABASE_URL, F4_S3_BUCKET
docker compose up -d --build
docker compose logs -f f4-weekly
```
