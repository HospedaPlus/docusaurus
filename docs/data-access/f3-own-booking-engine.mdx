# <SourceTitleIcon icon="database" tone="teal" />F3 · Own booking engine <SourceType>PostgreSQL database</SourceType>

Simulated PostgreSQL database of the chain's own booking engine. It holds the hotel catalog, the room inventory, the rates and the direct bookings.

<AccessTable>

| Property | Value |
| --- | --- |
| Type | Simulated database |
| Location | PostgreSQL database, populated by a seed |
| Access method | Database connection (SQL) |
| Frequency | Continuous |
| Volume | 28 hotels, ~4,000 rooms |

</AccessTable>

## How to access it

Connect to the PostgreSQL database with SQL. Connection credentials come from environment variables and are never stored in the repository or in container images.

## What it contains

- Hotels and room types.
- Inventory by hotel, room type and date.
- Rates by season.
- Direct bookings.

## Data seed

All data in this database is generated by a seed versioned in the repository, never loaded by hand or from a dump. The seed:

- Uses a fixed random seed, so the data is reproducible.
- Is idempotent: running it several times does not duplicate data.
- Lets us choose the volume (small development mode or full mode).
- Keeps referential integrity and a catalog consistent with the simulated APIs and events.
- Injects the known data quality issues at a configurable rate.
- Runs both locally and against the database in AWS.

<AccessNote icon="alert" title="Known data quality issues">

- Bookings with zero adults, zero children and zero babies.
- Departure dates earlier than the arrival date.

</AccessNote>
