For example, with `psql`:

```bash
psql "postgresql://hospedaplus_owner:npg_edEG9kmaAOv3@ep-divine-cake-b48dsbxg-pooler.c-6.us-east-2.aws.neon.tech/hospedaplus?sslmode=require&channel_binding=require"
```

- The `-pooler` host suits clients with many short connections, such as the API. The seed uses the direct host (the same host without `-pooler`).
- The database sleeps after 5 minutes idle and wakes on the next query, so the first query can take a few seconds.
- To run the seed locally instead, the repository includes a Docker Compose file with PostgreSQL 16.

## What it contains

| Table | Content |
| --- | --- |
| `hotels` | 28 urban and resort hotels, with code (`HP-CO-001`…), city, country, time zone and currency. |
| `room_types` | `SINGLE`, `DOUBLE`, `TWIN` and `SUITE`, with their maximum guests. |
| `rooms` | The 4,000 physical rooms, by hotel and room type. |
| `channels` | 21 sales channels with their commission (RN-02). |
| `rates` | Price per night by hotel, room type and season (`LOW`, `MID`, `HIGH`, RN-05). |
| `inventory` | Total and available rooms by hotel, room type and night. |
| `guests` | Guest personal data, to be pseudonymized before analytics (RN-11). |
| `reservations` | Direct and corporate bookings, with cancellations and no-shows. |
| `reservation_anomalies` | Rows with known data quality issues, kept apart on purpose. |

Hotels, room types and channels come from the **shared catalog** that F2, F4 and F5 also read, so the pipeline can join every source.

## Data seed

All data is generated by the seed in the repository (`python -m seed`), never loaded by hand or from a dump. The seed:

- **Is reproducible.** The same seed and start date produce the same data, row for row.
- **Is idempotent.** It replaces the data in one transaction: running it several times gives one copy, and a failed run leaves the previous data untouched.
- **Has two volumes.** `dev` mode covers 90 past and 30 future nights; `full` mode covers 400 past and 180 future nights.
- **Simulates realistic demand.** City hotels get more arrivals from Sunday to Tuesday, resorts on weekends, and high season brings more guests.
- **Never overbooks.** The generator refuses a booking when the room type is full, and the database rejects `available_rooms < 0`.
- **Rejects bookings in the past.** A trigger rejects any reservation whose check-in is earlier than the day it was made.
- **Is safe by default.** Destructive commands stop on remote databases unless `--allow-remote` is given.
- **Checks itself.** `python -m seed check` runs 21 health and integrity checks and passes only if all of them pass.

| Command | What it does |
| --- | --- |
| `python -m seed init` | Creates tables and indexes. |
| `python -m seed seed` | Empties the tables and loads a fresh dataset. |
| `python -m seed check` | Runs the health and integrity checks (read-only). |
| `python -m seed all` | `init` + `seed` + `check`. |

<AccessNote icon="alert" title="Known data quality issues">

Rows that would break the constraints go to `reservation_anomalies` instead of `reservations` (2% each by default, configurable):

- Bookings with zero guests.
- Check-out dates earlier than the check-in date.

</AccessNote>
