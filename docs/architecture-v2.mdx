# Architecture v2

This is the final architecture of HospedaPlus Revenue on AWS (region **us-east-2, Ohio**): three EC2 machines with Docker Compose, Kafka for F2, Airflow 3.1.5 with Celery on RabbitMQ, Spark in local mode on the workers, S3 + Athena (Glue Data Catalog filled with DDL) and Power BI over ODBC.

## Changes from the previous version

| Before | Now | Why |
| --- | --- | --- |
| Spark on Fargate / EMR | **Spark in local mode** on the workers EC2 (t3.xlarge) | ~200,000 bookings fit in one machine; no cluster to pay for or run |
| Amazon ECR | **GitHub Container Registry (GHCR)** | Images are built by CI next to the code |
| Glue Crawler | **Athena DDL** (`CREATE EXTERNAL TABLE`) | Crawlers are blocked on the account; DDL gives exact names and types |
| EKS, ALB, WAF, NAT, Secrets Manager | Not used | Not needed at this size; secrets live in `.env` files outside the repo and in GitHub secrets |
| Overbooking limits computed in the operation | **Write-back from gold to Neon** | The operation uses the same cancellation rates the business sees |
| F2 prices through RabbitMQ | **F2 through Kafka** to Neon | RabbitMQ is only the Celery broker |
| Kafka and simulators spread out | One **sources EC2** | One machine for every simulator |

## Block by block

### 1. Sources and team

- **Dev team · GitHub Actions**: ruff, pytest and DAG validation; on every merge an image is pushed to GHCR and deployed over SSH.
- **Data team**: connects to the machines with SSH and opens the Airflow (`:8080`) and Flower (`:5555`) UIs.
- **F2 producer** (OTA events, contract 1.3) and **F3 simulator** (`seed simulate`, direct bookings, role `app_writer`).
- **APIs F5 · F6 · F7**: the team's reviews API (FastAPI on ECS), Nager.Date and Frankfurter, read over HTTPS.
- **F1 Kaggle**: `hotel_bookings.csv` from the `hospedaplus-csv` repo, loaded once.
- **Shared catalog**: the canonical source is `db_simulated` (Neon); F2, F4 and F5 use its hotel, room type, channel and currency codes.

### 2. Entry

- **GHCR** stores the images (`ghcr.io/hospedaplus/…`, tags `:sha`, `:main` and `vX.Y.Z`).
- **Internet Gateway** into the VPC (public subnet, public IPs).
- **Security groups**: `sg-nucleo` opens 22, 8080, 5555 and 15672 only to the team's IP, 80/443 for Nginx (the [monitoring UIs](./data-engineering-pipeline/monitoring.mdx)), and 5432, 5672 and 8080 only to `sg-workers`; `sg-workers` opens 22 to the team. The workers reach the core on its **private IP**.

### 3. Processing: EC2 in us-east-2

- **Sources EC2** (Docker Compose): `buenavista-streaming` (F2 producer → **Kafka 4.1.1**, topic `reservation.events.v1_3`, 6 partitions + DLQ → 6 `neon-consumer` that call `reservar()`), `db_simulated` (F3 `seed simulate`) and `hospedaplus-csv` (`f4-weekly`, Monday 06:00 UTC, 15 agencies → S3 and Neon).
- **Core EC2** (t3.medium, 30 GB): Airflow 3.1.5 with CeleryExecutor (API server, scheduler, DAG processor, triggerer, metadata PostgreSQL), RabbitMQ (queues `bronze`, `silver`, `gold`) and Flower.
- **Workers EC2** (t3.xlarge, 50 GB): three Celery workers. **bronze** runs 4 tasks at a time (Python: Neon, APIs F5–F7, F1 and F4 → `bronze/`); **silver** runs 2 (Spark local: validates, deduplicates, converts to COP); **gold** runs 2 (Spark local: `dim_`, `fact_`, `mart_` P1–P5 and the write-back). Spark 3.5 reads and writes S3 with `s3a://` using the EC2 IAM role. Details in [Compute and resources](./data-engineering-pipeline/compute-resources.mdx).

### OLTP: Neon PostgreSQL (external SaaS)

Schemas `operation` and `streaming`, branches `development` and `production`, and `reservar()` with the overbooking limit (0 today). The pipeline reads it with `etl_reader` every hour and with a full copy at 03:00 UTC, and writes back the cancellation rates with `app_writer`.

### 4. Data lake (OLAP)

- **Amazon S3 `hospedaplus-lakehouse-buenavista`**, public access blocked: `bronze/` (JSON/CSV as extracted), `silver/` (Parquet: bookings, cancellations, occupancy, calendar, reviews, FX, F1 history), `gold/` (Parquet: 4 dims, 4 facts, 7 marts, plus a JSON for the Neon write-back), `airflow-logs/` and `athena-results/`.
- Each DAG publishes an **Asset** when it finishes, and the next one starts by itself.
- **Athena DDL → Glue Data Catalog** (`hospedaplus_gold`, run again only if a schema changes) → **Amazon Athena** (workgroup `primary`).

### 5. Analytics and decision

**Power BI Desktop** reads gold with the Amazon Athena ODBC driver (x64) as the read-only IAM user `powerbi-reader`; the report has 4 pages. The **Revenue Manager and hotel managers** use it to decide price and occupancy per hotel. See [Data Visualization](./data-visualization/index.mdx).

## Security and operation, as configured today

| Area | What is in place |
| --- | --- |
| IAM | Role `hospedaplus-pipeline-role` on core and workers, only on the bucket. User `powerbi-reader`: Athena, Glue and S3, read only. |
| Security groups | `sg-nucleo`, `sg-workers`: ports open only to the team's IP and between the two groups. |
| Credentials | `.env` on each EC2 (outside the repo), deploy secrets in GitHub, AWS keys left empty (the role gives them). |
| Neon roles | `hospedaplus_owner` (migrations), `app_writer` (consumers, simulators, write-back), `etl_reader` (Airflow). |
| S3 | Public access blocked; Airflow logs in `airflow-logs/`, Athena results in `athena-results/`. |
| Monitoring | Flower for the workers, the Airflow UI, `docker compose logs` and the Kafka group lag. See [Monitoring](./data-engineering-pipeline/monitoring.mdx). |

## Data flows (legend)

- **Real time / OLTP (pink):** F2 events through Kafka and F3/F4 loads that call `reservar()` in Neon.
- **CI/CD and control (purple, dashed):** images in GHCR, deploy over SSH, Airflow orders through RabbitMQ.
- **Batch / OLAP (blue):** extraction to bronze, then bronze → silver → gold (Celery workers + Spark local).
- **Catalog (teal, dashed):** tables created with Athena DDL in the Glue Data Catalog (no crawler).
- **Write-back (orange):** gold → Neon `operation.cancellation_rate_by_lead` (daily upsert).
- **Gold consumption (green):** Athena → Power BI (ODBC) → managers.
- **Pending (grey, dashed):** business API with FastAPI (US-41).
