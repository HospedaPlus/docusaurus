# Data Sources

HospedaPlus Revenue integrates seven data sources, from F1 to F7. F1, F6 and F7 are real public data. F2 to F5 are **simulated**: the team built a generator for each one, it runs all the time on AWS, and it produces data at the frequency and volume the project asks for.

## Where each source is stored first

<SourcesFlow />

- **Neon first (F2, F3, F6 events, F4 bookings).** These are operational data: every booking, from any channel, goes through the same function `operation.reservar()`, so all channels share one inventory and nothing is oversold. The pipeline reads Neon with a read-only role and copies the changes to S3 every hour, plus a full snapshot every night.
- **S3 first (F1, F4 files, F6 holidays, F7).** These are files or public APIs with nothing to operate on, so they go to `s3://…/bronze/` as they arrive, unchanged.
- **F5** keeps its reviews in the API's own database, as a real review platform would; the pipeline reads the API every hour.

<Note>
  **Data seed.** All data in the simulated sources is generated by code versioned in each repository. The generators use a fixed random seed so data is reproducible, are idempotent, let us choose the volume (small development mode or full mode), keep referential integrity through one shared catalog (same hotel, room type, channel and guest codes everywhere), inject the known data quality issues at a configurable rate, and run both locally with Docker and on AWS.
</Note>

<AccessNote icon="alert" title="Known data quality issues">

The data arrives with the following defects, and the simulated sources inject them on purpose:

- F1 has `"NULL"` as text in the agent and company fields, and negative or extreme ADR values.
- Bookings with zero adults, zero children and zero babies (F1, F3).
- Departure dates earlier than the arrival date (F3).
- Missing currencies in agency files (F4, ~10%).
- Bookings duplicated across channels with slight differences in the guest's name (F4, ~10%), and reviews duplicated across platforms (F5, ~5%).
- Modification events that arrive before the creation event (F2, ~5%).

</AccessNote>
