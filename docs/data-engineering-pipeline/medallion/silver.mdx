# Silver layer

Silver turns the raw bronze copies into **one clean, trustworthy table per entity**. Every job is written in PySpark (`spark_jobs/silver_*.py`), runs on the `silver` worker, reads bronze with an explicit schema (no inference pass), runs its quality checks and only then overwrites its Parquet folder.

| Silver table | Built from | One row per | Main use |
| --- | --- | --- | --- |
| `tasa_cambio_diaria` | F7 | day × currency | Convert every amount to COP |
| `reservas` | Neon bookings (F2, F3, F4) + catalogs + FX | booking code | P1, P3, P4 |
| `cancelaciones` | `reservas` | cancelled / no-show booking | P1 |
| `reservas_rechazadas` | Neon anomalies | refused booking | Data quality (defects 5.3) |
| `ocupacion_diaria` | Neon snapshot: inventory, relocations, rejections | hotel × room type × night | P2, P3 |
| `calendario_hotel` | F6 holidays + F6 events + hotels | hotel × day | P3 |
| `resenas` | F5 reviews + hotels | review (original) | P5 |
| `historico_f1` | F1 Kaggle CSV | historical booking | P1 |

## Transformations, how and why

### `tasa_cambio_diaria` (F7)

1. Reads every Frankfurter answer (rows `date, base, quote, rate`, base USD) and adds USD = 1.
2. Builds a **daily grid** from the first to the last date for every currency and fills each day with the **last known rate** (forward fill).
3. Computes `cop_por_unidad = rate(USD→COP) / rate(USD→currency)`.

**Why:** there are no rates on weekends and holidays, but there are bookings, so every calendar day needs a rate. Frankfurter v2 can date each currency differently (EUR or MXN may come with another date than COP), so each currency is filled on its own grid **before** dividing by COP; otherwise whole days would be lost.
**Checks:** not empty, no nulls, unique `(fecha, moneda)`, rate > 0, no missing days.

Code (`spark_jobs/silver_fx.py`):

```python
# One rate per day and currency, from the raw Frankfurter answers
rates = (raw.select(F.to_date("date").alias("fecha"), F.col("quote").alias("moneda"),
                    F.col("rate").cast("double").alias("rate"))
         # + USD = 1.0 every day
         .dropna().dropDuplicates(["fecha", "moneda"]))
# every calendar day
days = bounds.select(F.explode(F.sequence("a", "b")).alias("fecha"))
# day x currency
grid = days.crossJoin(rates.select("moneda").distinct())
# For each currency, look at every earlier day up to this one
w = Window.partitionBy("moneda").orderBy("fecha").rowsBetween(Window.unboundedPreceding, 0)
# Put the known rates on the grid
filled = (grid.join(rates, ["fecha", "moneda"], "left")
          # forward fill
          .withColumn("rate", F.last("rate", ignorenulls=True).over(w))
          # Days before the first known rate are dropped
          .dropna(subset=["rate"]))
# How many COP one USD is worth each day
cop = filled.filter("moneda = 'COP'").select("fecha", F.col("rate").alias("usd_cop"))
# COP per unit of each currency = (COP per USD) / (currency per USD)
out = filled.join(cop, "fecha").select(
    "fecha", "moneda", (F.col("usd_cop") / F.col("rate")).alias("cop_por_unidad"))
```

### `reservas`, `cancelaciones`, `reservas_rechazadas` (F2, F3, F4)

All channels write into `operation.reservations` through `reservar()`, so one job handles every booking.

1. **Read only what is needed:** the newest full snapshot (with `_SUCCESS`) plus the hourly files from the day before that snapshot on.
2. **Newest version per code.** The same booking appears several times (created, modified, cancelled). A window per `code` keeps the row with the latest `updated_at` (or, in older files, the latest of created/cancelled/last event); on a tie the hourly file wins over the snapshot.
   **Why:** silver must show the current state of each booking, exactly once.
3. **Join the catalogs** (latest copy of hotels, channels, room types) to get hotel code, country, category, time zone, channel type and commission.
4. **Derived fields:** `noches`, `huespedes`, `fecha_reserva`, `lead_time_dias` (check-in − booking date), `es_cancelada` (cancelled or no-show), `es_duplicado` (status `duplicate`).
5. **Currency to COP** with the rate of the booking day. Bookings older than the first published rate use the oldest one and are marked `fx_estimada = true`.
   **Why:** the business reports in COP, and hotels sell in EUR, COP, MXN and BRL.
6. **Commission and net:** `comision_cop = total_cop × commission % of the channel` and `neto_cop = total_cop − comision_cop` (P4).
7. **`cancelaciones`:** only cancelled / no-show bookings that are not duplicates, with `horas_antes_checkin` (from the cancellation to check-in at 15:00) and a lead-time bucket (`0-1`, `1-3`, `3-7`, `7-30`, `30-90`, `90+` days) for P1.
8. **`reservas_rechazadas`:** bookings Neon refused (zero guests, check-out before check-in), one per code.

How each data-quality defect of the sources is handled:

| Defect | Where it is handled | Result in silver |
| --- | --- | --- |
| F3 zero guests / check-out before check-in | Refused by Neon, logged in `reservation_anomalies` | `reservas_rechazadas`, never in metrics |
| F4 duplicated booking | Marked `duplicate` in Neon | `es_duplicado = true`, excluded from every gold metric |
| F4 missing currency | The loader uses the hotel currency | Kept |
| F2 events out of order | Resolved in Neon (`last_event_at`) | Already in order |

**Checks:** not empty, unique `code`, no row without `total_cop` (the error says which source/currency is missing a rate), no nulls in key columns, `check_out > check_in`, at least one adult, no negative amounts, unique codes in `cancelaciones`. The table is partitioned by `source` (F2, F3, F4).

Code (`spark_jobs/silver_reservas.py`):

```python
# 1. newest full snapshot + hourly files from the day before it on
def plan_days(full_days, hourly_days):
    # The newest complete snapshot day
    newest = full_days[-1]
    # One day earlier, to cover changes made while the snapshot ran
    since = (dt.date.fromisoformat(newest) - dt.timedelta(days=1)).isoformat()
    # Snapshot day + hourly days from that date on
    return [newest], [d for d in hourly_days if d >= since]

# 2. one row per booking code: the newest version (hourly file wins a tie: _src = 1)
# Version = updated_at (or the newest date of the row for old data)
version = F.coalesce(F.to_timestamp("updated_at"), legacy_greatest_of_dates)
# Group by code, newest first
w = Window.partitionBy("code").orderBy(F.col("_version").desc(), F.col("_src").desc())
# Number the rows of each code and keep number 1
r = raw.withColumn("_version", version).withColumn("_rn", F.row_number().over(w)).filter("_rn = 1")

# 4. derived fields
# Nights = check-out minus check-in
df = (df.withColumn("noches", F.datediff("check_out", "check_in"))
        # Days booked in advance
        .withColumn("lead_time_dias", F.datediff("check_in", "fecha_reserva"))
        # Duplicate flag
        .withColumn("es_duplicado", F.col("status") == "duplicate")
        # Cancelled or no-show counts as cancelled
        .withColumn("es_cancelada", F.col("status").isin("cancelled", "no_show")))

# 5-6. COP with the rate of the booking day, then commission and net
# Add the exchange rate of the booking day (broadcast: the rates table is small)
df = (df.join(F.broadcast(fx), ["currency", "fecha_reserva"], "left")
        # True when that day had no rate and an estimate is used
        .withColumn("fx_estimada", F.col("_tasa").isNull())
        # The day's rate, or the nearest known one
        .withColumn("tasa_cop", F.coalesce("_tasa", "_tasa_min")))
# Total in COP
df = (df.withColumn("total_cop", F.round(F.col("total") * F.col("tasa_cop"), 2))
        # Commission in COP
        .withColumn("comision_cop", F.round(F.col("total_cop") * F.col("comision_pct") / 100, 2))
        # Net = total - commission
        .withColumn("neto_cop", F.col("total_cop") - F.col("comision_cop")))

# 7. hours between cancellation and check-in (15:00)
# (check-in date at 15:00 - cancellation moment) in seconds, / 3600 = hours
horas = (F.unix_timestamp(F.to_timestamp(F.concat_ws(" ", F.col("check_in").cast("string"), F.lit("15:00:00"))))
         - F.unix_timestamp("cancelada_en")) / 3600
```

### `ocupacion_diaria` (F3 inventory)

1. Takes the newest inventory snapshot: rooms, sold rooms and overbooking limit per hotel, room type and night.
2. Adds **relocations** per night and **rejected rooms** per night (each rejected booking is exploded into its nights).
3. Computes `disponibles = rooms + overbooking limit − sold`, `ocupacion_pct`, and `sobrevendidas` (sold above physical rooms).

**Why:** P2 (overbooking) and P3 (revenue) need a dense night-by-night view of capacity and how often overbooking hurt a guest.
**Checks:** unique `(hotel, room type, night)`, no nulls, and never sold above rooms + overbooking limit.

Code (`spark_jobs/silver_ocupacion.py`):

```python
# rejected bookings: one row per night they wanted
nights = F.explode(F.sequence(F.to_date("check_in"), F.date_sub(F.to_date("check_out"), 1)))
# Rejected rooms per hotel, room type and night
j = (rej.select("hotel_id", "room_type_id", nights.alias("fecha"), F.col("rooms_count").cast("int").alias("n"))
     .groupBy("hotel_id", "room_type_id", "fecha").agg(F.sum("n").alias("habitaciones_rechazadas")))

# Add them to the daily inventory; days without data get 0
out = (base.join(j, KEY, "left").fillna(0, ["reubicadas", "habitaciones_rechazadas"])
       # Available = rooms + overbooking limit - sold
       .withColumn("disponibles", F.col("habitaciones") + F.col("limite_sobreventa") - F.col("vendidas"))
       # Occupancy %
       .withColumn("ocupacion_pct", F.round(F.col("vendidas") * 100.0 / F.col("habitaciones"), 2))
       # Rooms sold above the real capacity (never negative)
       .withColumn("sobrevendidas", F.greatest(F.lit(0), F.col("vendidas") - F.col("habitaciones"))))

# check: never sold above rooms + overbooking limit
bad = out.filter("vendidas > habitaciones + limite_sobreventa OR vendidas < 0").count()
```

### `calendario_hotel` (F6)

1. Reads the Nager holidays (tolerant to the payload shape) and takes the country from the file name.
2. Builds one row per **hotel × day** and marks `es_festivo` with the holiday name of the hotel's country.
3. Adds the hotel's **local events** (multi-day events are exploded into each day; if several overlap, the highest category wins: low < medium < high).
4. Adds year, month, weekday and weekend.

**Why:** holidays depend on the country and events on the hotel, so the calendar must be per hotel. Gold joins it to occupancy and price (P3).
**Checks:** unique `(hotel, day)`, no nulls, no missing days.

Code (`spark_jobs/silver_calendario.py`):

```python
# hotel x every day
cal = (hotels.crossJoin(days)
       # holiday of the hotel's country
       .join(holidays, ["pais", "fecha"], "left")
       # true when the day has a holiday name
       .withColumn("es_festivo", F.col("nombre_festivo").isNotNull()))

# Local events: one row per day of each event
ev = (events.select("hotel_code", "name", "category",
                    F.explode(F.sequence(F.to_date("start_date"), F.to_date("end_date"))).alias("fecha"))
      # low=1, medium=2, high=3
      .withColumn("_rank", rank[F.col("category")])
      # One row per hotel and day
      .groupBy("hotel_code", "fecha")
      # Join the event names and keep the highest category
      .agg(F.concat_ws(" / ", F.collect_set("name")).alias("evento"), F.max("_rank").alias("_rank")))
```

### `resenas` (F5)

1. **Latest version** of each review id (edited reviews come back with a newer `updated_at`).
2. **Cross-platform duplicates:** the same guest posts the same review on another platform minutes or hours later, with a name variant and sometimes without the final period. Same hotel + stay date + rating + normalised text (lower case, trimmed, no trailing punctuation) = the same review. The first one published is kept and `copias_en` / `duplicados` say where it was copied.
3. Hotel country from the catalog and **sentiment** from the rating: 4–5 positive, 3 neutral, 1–2 negative.

**Why:** without removing duplicates, one opinion would count several times in the reputation score (P5).
**Checks:** unique `review_id`, no nulls, rating between 1 and 5, known hotel. Partitioned by `fecha_publicacion`.

Code (`spark_jobs/silver_resenas.py`):

```python
# "Great stay." == "great stay"
def _norm_text(c):
    # Lower case, no spaces at the ends, no final dots or exclamation marks
    return F.regexp_replace(F.lower(F.trim(c)), r"[\s.!]+$", "")

# Each review id, newest edit first
w_id = Window.partitionBy("id").orderBy(F.to_timestamp("updated_at").desc())
# newest edit
latest = raw.withColumn("_rn", F.row_number().over(w_id)).filter("_rn = 1")

# Same hotel, stay date, score and text = the same review on another platform
key = ["hotel_code", "fecha_estadia", "puntaje", "_texto_norm"]
# Inside each group, the first one published comes first
w_dup = Window.partitionBy(*key).orderBy("publicada_en", "review_id")
# Add the normalized text
r = (r.withColumn("_texto_norm", _norm_text(F.col("texto")))
      # Position inside its group
      .withColumn("_rn", F.row_number().over(w_dup))
      # Platforms where that same review appears
      .withColumn("copias_en", F.collect_set("plataforma").over(Window.partitionBy(*key))))
# first one published
original = (r.filter("_rn = 1")
             # Other platforms only (remove its own)
             .withColumn("copias_en", F.expr("array_remove(copias_en, plataforma)"))
             # How many copies it had
             .withColumn("duplicados", F.size("copias_en")))
# Score 4-5 positive, 3 neutral, 1-2 negative
sentimiento = (F.when(F.col("puntaje") >= 4, "positivo")
                .when(F.col("puntaje") == 3, "neutro").otherwise("negativo"))
```

### `historico_f1` (F1)

1. Renames and types the Kaggle columns, builds the arrival date, nights, guests and income (`adr × nights`, in EUR).
2. Maps `market_segment` to the project's channel types (Online TA → `ota`, Offline TA/TO and Groups → `agency`, Corporate and Aviation → `corporate`, Direct and Complementary → `direct`).
3. Same lead-time buckets as `cancelaciones`.
4. Drops rows with no guests, no nights, negative ADR or no arrival date, and counts them.

**Why:** F1 is the long history (2015–2017) that explains how cancellation depends on lead time and deposit type, which the live data does not have. Amounts stay in EUR because the FX rates only start in 2026.

Code (`spark_jobs/silver_f1.py`):

```python
# Kaggle market segment -> our channel type
CHANNEL_TYPE = {"Online TA": "ota", "Offline TA/TO": "agency", "Groups": "agency",
                "Corporate": "corporate", "Direct": "direct", "Complementary": "direct",
                "Aviation": "corporate"}

# Arrival date from year + month name + day, e.g. 2016-July-1
arrival = F.to_date(F.concat_ws("-", "arrival_date_year", "arrival_date_month",
                                "arrival_date_day_of_month"), "yyyy-MMMM-d")

# Separates valid rows from invalid ones
def split_valid(df):
    # A row is valid with guests, nights, a price >= 0 and an arrival date
    ok = "huespedes > 0 AND noches > 0 AND adr_eur >= 0 AND fecha_llegada IS NOT NULL"
    # kept rows, dropped count
    return df.filter(ok), df.filter(f"NOT ({ok})").count()
```

### How every job protects silver

All silver jobs share the same three steps: **transform → check → overwrite**. The checks live in one module:

```python title="spark_jobs/quality.py"
# Error raised when the data breaks a rule
class QualityError(Exception): ...

# Rule: no two rows may have the same keys
def unique(df, name, keys):
    # Count the key combinations that appear more than once
    dup = df.groupBy(*keys).count().filter("count > 1").count()
    # If any exists...
    if dup:
        # ...stop with a clear message
        raise QualityError(f"{name}: {dup} duplicated keys {keys}")

# every job:  transform -> check(out) -> out.write.mode("overwrite").parquet(...)
# if check() raises, the Airflow task fails and yesterday's Parquet stays untouched
```

## How long it takes

The whole silver layer runs in about 2 minutes. `silver_reservas_daily` also runs after every hourly bronze copy, so silver is about one hour behind Neon.
