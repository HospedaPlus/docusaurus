# Gold layer and data model

Gold is the analytical layer. Once a night `gold_modelo_daily` (`spark_jobs/gold_modelo.py`, queue `gold`) reads the silver tables and the latest Neon catalogs, rebuilds **every** gold table in full, checks them all and overwrites them. All amounts are in **COP** and duplicated bookings (F4) never count.

## Data model

### Which model it is: a star schema

The model is a **star schema**, not a snowflake. Every fact table joins **directly** to its dimensions, and no dimension depends on another dimension: the hotel's country, city and category live inside `dim_hotel`, not in separate `dim_pais` or `dim_ciudad` tables. A few descriptive columns (`channel_type`, `hotel_pais`) are also copied into the facts so the most common filters need no join at all.

**Why a star and not a snowflake:** Power BI's engine is built for stars (one-to-many relationships from each dimension to each fact, filters flowing one way), the dimensions are small (28 hotels, a handful of channels and room types), so normalising them would add joins without saving any space, and the model stays easy to read for the business.

### How it looks

```text
                              ┌──────────────────────┐
                              │      dim_fecha       │
                              │ PK fecha             │
                              │ anio, mes, semana…   │
                              └──────────┬───────────┘
                                         │
 ┌──────────────────────┐     ┌──────────┴───────────┐     ┌──────────────────────┐
 │      dim_canal       │     │        FACTS         │     │ dim_tipo_habitacion  │
 │ PK channel_code      ├─────┤ fact_reservas        ├─────┤ PK room_type         │
 │ channel_type, comis. │     │ fact_cancelaciones   │     │ nombre, capacidad    │
 └──────────────────────┘     │ fact_ocupacion_diaria│     └──────────────────────┘
                              │ fact_resenas         │
                              └──────────┬───────────┘
                                         │
                              ┌──────────┴───────────┐
                              │      dim_hotel       │
                              │ PK hotel_code        │
                              │ ciudad, pais, categ. │
                              └──────────────────────┘
                     marts P1–P5 are built from the facts
```

Relationships (all one-to-many, from the dimension to the fact):

| Fact | `dim_fecha` | `dim_hotel` | `dim_canal` | `dim_tipo_habitacion` |
| --- | --- | --- | --- | --- |
| `fact_reservas` | `check_in`, `fecha_reserva`, `check_out` | `hotel_code` | `channel_code` | `room_type` |
| `fact_cancelaciones` | `check_in`, `fecha_cancelacion` | `hotel_code` | `channel_code` | `room_type` |
| `fact_ocupacion_diaria` | `fecha` (night) | `hotel_code` | – | `room_type` |
| `fact_resenas` | `fecha_publicacion`, `fecha_estadia` | `hotel_code` | – | – |

`dim_fecha` is a **role-playing** dimension: the same table is used for the check-in date, the booking date, the cancellation date, the night of occupancy and the publication date of a review. Holidays are not in `dim_fecha` because they depend on the hotel's country: they are in `fact_ocupacion_diaria` (from `silver/calendario_hotel`).

### Dimensions

| Table | Grain (PK) | Columns |
| --- | --- | --- |
| `dim_fecha` | one day (`fecha`) | `fecha_key` (yyyyMMdd), `anio`, `trimestre`, `mes`, `nombre_mes`, `semana_iso`, `dia_semana`, `es_fin_de_semana`, `anio_mes`. From one year back to the last check-out. |
| `dim_hotel` | `hotel_code` | `nombre`, `categoria`, `ciudad`, `pais`, `moneda`, `zona_horaria`, `habitaciones` (max rooms on a night) |
| `dim_canal` | `channel_code` | `nombre`, `channel_type` (ota, direct, corporate, agency), `comision_pct` |
| `dim_tipo_habitacion` | `room_type` | `nombre`, `capacidad` |

### Facts

| Table | Grain | Keys to dimensions | Measures |
| --- | --- | --- | --- |
| `fact_reservas` | one booking (`code`), duplicates excluded | `hotel_code`, `channel_code`, `room_type`, `fecha_reserva`, `check_in`, `check_out` | `noches`, `habitaciones`, `huespedes`, `lead_time_dias`, `total_cop`, `comision_cop`, `neto_cop`, `penalidad_cop`; flags `es_cancelada`, `reembolsable`, `fx_estimada`; `rango_anticipacion`, `status`, `source` |
| `fact_cancelaciones` | one cancelled / no-show booking | `hotel_code`, `channel_code`, `room_type`, `check_in`, `fecha_cancelacion` | `horas_antes_checkin`, `total_cop`, `penalidad_cop`, `ingreso_perdido_cop` (total − penalty); `rango_anticipacion` |
| `fact_ocupacion_diaria` | hotel × room type × night | `hotel_code`, `room_type`, `fecha` | `habitaciones`, `vendidas`, `limite_sobreventa`, `disponibles`, `sobrevendidas`, `reubicadas`, `habitaciones_rechazadas`, `ocupacion_pct`, `ingreso_cop`; `es_festivo`, `nombre_festivo`, `hay_evento`, `evento`, `categoria_evento` |
| `fact_resenas` | one review (originals only) | `hotel_code`, `fecha_publicacion`, `fecha_estadia` | `puntaje`, `sentimiento`, `duplicados`; `plataforma`, `idioma`, `pais_huesped` |

### Marts (one per business pain)

The marts are pre-aggregated answers built from the facts, so each dashboard page reads one small table.

| Mart | Pain | Grain | What it gives |
| --- | --- | --- | --- |
| `mart_p1_cancelacion` | P1 cancellations | channel × lead bucket × refundable × check-in month | bookings, cancelled, `tasa_cancelacion`, penalty and lost income in COP |
| `mart_p1_historico_f1` | P1 (history) | hotel type × channel type × lead bucket × deposit type | cancellation rate from F1 2015–2017 |
| `mart_p2_sobreventa` | P2 overbooking | hotel × night | rooms, sold, overbooking limit, oversold, relocated, rejected, `% relocation` |
| `mart_p3_revenue` | P3 revenue | hotel × night | occupancy %, **ADR**, **RevPAR**, rooms on the books 14 days before vs last year (**pickup %**), holiday and event flags |
| `mart_p3_precio_sugerido` | P3 pricing | hotel × room type × night, next 90 nights | suggested price = rate × pickup factor (1.10 / 0.92 when pickup is over ±15 %) × event factor (1.15 on holiday or event), kept between 0.75 and 1.60 of the base rate (RN-05/RN-06), also in COP |
| `mart_p4_comisiones` | P4 channel cost | channel × hotel × month | gross, commission and net income in COP, effective commission % |
| `mart_p5_reputacion` | P5 reputation | hotel × day | RN-10 rating over the last 90 days with the last 30 weighing double, reviews in 90 days, % positive, % negative |

Plus `neon_cancellation_rate_by_lead` (hotel × lead bucket), a small JSON file that `gold_neon_writeback` loads into Neon. See [Connection to Neon](../neon-connection.mdx).

## How the model is built, in code

Everything lives in `spark_jobs/gold_modelo.py`. The job has three steps: **read** silver and the Neon catalogs, **build** every table with pure functions (no reading or writing inside them, so they can be tested), then **check** and **write**. The excerpts are from that file, shortened only where marked with `…`.

### 1. Read: silver plus the latest catalogs

```python
def run() -> dict[str, int]:
    s = spark("gold_modelo")
    silver = {name: s.read.parquet(path("silver", name))
              for name in ("reservas", "cancelaciones", "ocupacion_diaria", "calendario_hotel", "tasa_cambio_diaria")}
    silver["resenas"] = _optional(lambda: s.read.parquet(path("silver", "resenas")))
    silver["historico_f1"] = _optional(lambda: s.read.parquet(path("silver", "historico_f1")))
    dims = {name: sr._latest_dim(s, name) for name in ("hotels", "channels", "room_types")}
    dims["rates"] = _optional(lambda: sr._latest_dim(s, "rates"))
    tables = build(silver, dims, dt.datetime.now(dt.timezone.utc).date(), s)
    check(tables)
    …
```

`_optional` returns `None` when a folder does not exist yet, so a missing optional source (reviews, F1, rates) never stops P1 to P4.

### 2. Build: dimensions

`dim_fecha` is generated, not read: one row per day from a year ago to the last check-out.

```python
def dim_fecha(first: dt.date, last: dt.date, spark: SparkSession) -> DataFrame:
    d = spark.range(1).select(F.explode(F.sequence(F.lit(first), F.lit(last))).alias("fecha"))
    dow = F.dayofweek("fecha")  # 1 = Sunday
    return (d.withColumn("fecha_key", F.date_format("fecha", "yyyyMMdd").cast("int"))
            .withColumn("anio", F.year("fecha")).withColumn("trimestre", F.quarter("fecha"))
            .withColumn("mes", F.month("fecha")).withColumn("nombre_mes", F.date_format("fecha", "MMMM"))
            .withColumn("semana_iso", F.weekofyear("fecha"))
            .withColumn("dia_semana", F.date_format("fecha", "EEEE"))
            .withColumn("es_fin_de_semana", dow.isin(1, 7))
            .withColumn("anio_mes", F.date_format("fecha", "yyyy-MM")))
```

The other dimensions rename the Neon catalog columns. `dim_hotel` keeps city, country and category inside the same table (that is what makes it a star and not a snowflake) and adds the number of rooms:

```python
def dim_hotel(hotels: DataFrame, ocupacion: DataFrame) -> DataFrame:
    rooms = (ocupacion.groupBy("hotel_code", "fecha").agg(F.sum("habitaciones").alias("h"))
             .groupBy("hotel_code").agg(F.max("h").alias("habitaciones")))
    return (hotels.select(F.col("code").alias("hotel_code"), F.col("name").alias("nombre"),
                          F.col("category").alias("categoria"), F.col("city").alias("ciudad"),
                          F.col("country").alias("pais"), F.col("currency").alias("moneda"),
                          F.col("timezone").alias("zona_horaria"))
            .join(rooms, "hotel_code", "left"))
```

### 3. Build: facts

`fact_reservas` is silver bookings without the F4 duplicates, plus the lead-time bucket used by P1:

```python
def fact_reservas(reservas: DataFrame) -> DataFrame:
    return (reservas.filter("NOT es_duplicado")
            .select("code", "source", "hotel_code", "channel_code", "channel_type", "room_type", "status",
                    "fecha_reserva", "check_in", "check_out", "noches", "habitaciones", "huespedes",
                    "lead_time_dias", "reembolsable", "es_cancelada", "currency", "fx_estimada",
                    "total_cop", "comision_pct", "comision_cop", "neto_cop", "penalidad_cop")
            .withColumn("rango_anticipacion", lead_bucket(F.col("lead_time_dias"))))
```

Revenue per night needs one row per booking and night of stay. `_nights` "explodes" each booking into its nights, and `fact_ocupacion` adds that revenue and the holiday/event flags to the silver occupancy:

```python
def _nights(fact_res: DataFrame) -> DataFrame:
    night = F.explode(F.sequence("check_in", F.date_sub("check_out", 1)))
    return fact_res.filter("noches > 0").select(
        "hotel_code", "room_type", "habitaciones", "fecha_reserva", "es_cancelada",
        F.to_date(F.col("_cancelada_en")).alias("fecha_cancelacion"),
        (F.col("total_cop") / F.col("noches")).alias("ingreso_noche_cop"), night.alias("fecha"))


def fact_ocupacion(ocupacion: DataFrame, n: DataFrame, calendario: DataFrame) -> DataFrame:
    ingreso = (n.filter("NOT es_cancelada").groupBy("hotel_code", "room_type", "fecha")
               .agg(F.round(F.sum(F.col("ingreso_noche_cop") * 1.0), 2).alias("ingreso_cop")))
    cal = calendario.select("hotel_code", "fecha", "es_festivo", "nombre_festivo", "hay_evento", "evento",
                            "categoria_evento")
    return (ocupacion.join(ingreso, ["hotel_code", "room_type", "fecha"], "left")
            .join(cal, ["hotel_code", "fecha"], "left")
            .fillna({"ingreso_cop": 0.0, "es_festivo": False, "hay_evento": False}))
```

### 4. Build: marts, ready for analysis

A mart is a fact already grouped at the level a dashboard page needs. For example P3 (occupancy, ADR, RevPAR per hotel and night):

```python
def mart_p3_revenue(fo: DataFrame, otb: DataFrame) -> DataFrame:
    …
    return (fo.groupBy("hotel_code", "fecha")
            .agg(F.sum("habitaciones").alias("habitaciones"), F.sum("vendidas").alias("vendidas"),
                 F.round(F.sum("ingreso_cop"), 2).alias("ingreso_cop"), …)
            .join(p, ["hotel_code", "fecha"], "left")
            .withColumn("ocupacion_pct", F.round(F.when(F.col("habitaciones") > 0,
                                                        F.col("vendidas") * 100.0 / F.col("habitaciones")), 2))
            .withColumn("adr_cop", F.round(F.when(F.col("vendidas") > 0, F.col("ingreso_cop") / F.col("vendidas")), 2))
            .withColumn("revpar_cop", F.round(F.when(F.col("habitaciones") > 0,
                                                     F.col("ingreso_cop") / F.col("habitaciones")), 2))
            .withColumn("pickup_pct", _pickup_pct()))
```

`build()` puts it all together. Facts used by several marts are cached so Spark computes them once:

```python
def build(silver, dims, today, spark) -> dict[str, DataFrame]:
    res, ocup, cal = silver["reservas"], silver["ocupacion_diaria"], silver["calendario_hotel"]
    fr = fact_reservas(res).cache()
    n = nights(res).cache()
    otb = on_the_books(n).cache()
    fo = fact_ocupacion(ocup, n, cal).cache()
    t = {
        "dim_fecha": dim_fecha(…), "dim_hotel": dim_hotel(dims["hotels"], ocup),
        "dim_canal": dim_canal(dims["channels"]), "dim_tipo_habitacion": dim_tipo_habitacion(dims["room_types"]),
        "fact_reservas": fr, "fact_cancelaciones": fact_cancelaciones(silver["cancelaciones"]),
        "fact_ocupacion_diaria": fo,
        "mart_p1_cancelacion": mart_p1_cancelacion(fr), "mart_p2_sobreventa": mart_p2_sobreventa(fo),
        "mart_p3_revenue": mart_p3_revenue(fo, otb), "mart_p4_comisiones": mart_p4_comisiones(fr),
        "neon_cancellation_rate_by_lead": neon_cancellation_rates(fr, today),
    }
    …
    return t
```

### 5. Check, then write

`check()` runs before anything is written. For example it refuses bookings whose hotel or channel is not in the dimensions:

```python
fr = t["fact_reservas"]
orphan = fr.join(t["dim_hotel"], "hotel_code", "left_anti").count() + \
    fr.join(t["dim_canal"], "channel_code", "left_anti").count()
if orphan:
    raise quality.QualityError(f"gold.fact_reservas: {orphan} rows without their hotel or channel")
```

Only when every check passes is each table overwritten in S3 as Parquet. The small table for Neon is written as one JSON file:

```python
for name, df in tables.items():
    if name == "neon_cancellation_rate_by_lead":
        df.coalesce(1).write.mode("overwrite").json(path("gold", name))
    else:
        df.write.mode("overwrite").parquet(path("gold", name))
```

From there Athena reads the tables through the Glue catalog and Power BI reads Athena (see [Athena configuration](../athena.mdx)).

## Quality checks before writing

- Every dimension, fact and main mart is not empty and unique on its key.
- No `fact_reservas` row without its hotel or channel in the dimensions (no orphans).
- Cancellation rates for Neon between 0 and 1.
- Suggested prices inside the RN-06 band.

If one check fails nothing is written and yesterday's gold stays in place. `fact_resenas`, `mart_p5_reputacion`, `mart_p1_historico_f1` and `mart_p3_precio_sugerido` are built only when their inputs exist, so a missing optional source never stops P1 to P4.

## Storage

Parquet in `s3://hospedaplus-lakehouse-buenavista/gold/<table>/`, **without partitions**: each run rewrites the whole folder, so Athena always reads the latest run. Registered in Athena as the database `hospedaplus_gold` (see [Athena configuration](../athena.mdx)).
