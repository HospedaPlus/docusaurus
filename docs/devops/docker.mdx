# Dockerization of each repository

Every repository runs in **Docker**, so the same command starts it on a laptop, in CI and on AWS. Two files do the work:

- **`Dockerfile`**: the recipe of *one image* (base system + dependencies + code + start command).
- **`docker-compose.yml`**: the list of *containers* that run together (which image, variables, ports, volumes, order of start).

## Ideas repeated in every repository

| Practice | Why |
| --- | --- |
| Dependencies are copied and installed **before** the code | Docker caches that layer: changing code does not reinstall packages, builds take seconds. |
| Containers run as a **non-root user** (`app`, `seeder`, `airflow`) | If the app is attacked, the attacker is not root inside the container. |
| **No secret inside the image** | Passwords arrive at run time through `.env` (Compose) or Secrets Manager (ECS). The same image works in dev and prod. |
| `healthcheck` + `depends_on: condition: service_healthy` | A container starts only when the one it needs is really ready (e.g. Airflow waits for Postgres and RabbitMQ). |
| One-shot jobs (`kafka-init`, `neon-migrate`, `airflow-init`, `seed`) with `restart: "no"` | They prepare something (topics, schema, admin user) and stop; the long-running services wait for them with `service_completed_successfully`. |
| `restart: unless-stopped` / `always` on services | If the EC2 reboots or the process dies, Docker starts it again. |

## 1. hospedaplus-pipeline (Airflow + Spark)

### Dockerfile

```dockerfile title="Dockerfile"
# Airflow 3 + Spark (local mode inside each Celery worker) + S3 (s3a).
FROM apache/airflow:3.1.5

USER root
RUN apt-get update \
 && apt-get install -y --no-install-recommends openjdk-17-jre-headless curl \
 && rm -rf /var/lib/apt/lists/* \
 && ln -s "$(dirname "$(dirname "$(readlink -f "$(which java)")")")" /usr/lib/jvm/default-java
ENV JAVA_HOME=/usr/lib/jvm/default-java          # Spark runs on the JVM

# Jars so Spark can read/write s3a:// (same Hadoop version that pyspark 3.5 ships).
RUN mkdir -p /opt/spark-jars \
 && curl -fsSL -o /opt/spark-jars/hadoop-aws-3.3.4.jar \
      https://repo1.maven.org/maven2/org/apache/hadoop/hadoop-aws/3.3.4/hadoop-aws-3.3.4.jar \
 && curl -fsSL -o /opt/spark-jars/aws-java-sdk-bundle-1.12.262.jar \
      https://repo1.maven.org/maven2/com/amazonaws/aws-java-sdk-bundle/1.12.262/aws-java-sdk-bundle-1.12.262.jar

USER airflow
COPY requirements.txt /requirements.txt
RUN pip install --no-cache-dir "apache-airflow==${AIRFLOW_VERSION}" -r /requirements.txt
```

**How it works:** it starts from the official Airflow image, adds Java (Spark needs it) and the two jars that let Spark talk to S3 (`s3a://`), then installs `pyspark`, `boto3`, `psycopg2` and the Amazon/Postgres/Celery providers. Pinning `apache-airflow==${AIRFLOW_VERSION}` in the same `pip install` stops pip from upgrading or downgrading Airflow by accident.

### Compose: one common block, two machines

All Airflow containers share the same settings through a YAML **anchor** (`&airflow-common`), and each service only says what is different (its `command`).

```yaml title="docker-compose.nucleo.yaml (excerpt)"
x-airflow-common: &airflow-common
  build: .
  image: hospedaplus-pipeline:local
  env_file: [.env]
  environment: &airflow-common-env
    AIRFLOW__CORE__EXECUTOR: CeleryExecutor
    AIRFLOW__DATABASE__SQL_ALCHEMY_CONN: postgresql+psycopg2://airflow:${POSTGRES_PASSWORD:-airflow}@postgres/airflow
    AIRFLOW__CELERY__BROKER_URL: amqp://${RABBITMQ_USER:-hospedaplus}:${RABBITMQ_PASSWORD:-hospedaplus}@rabbitmq:5672//
    AIRFLOW__CELERY__RESULT_BACKEND: db+postgresql://airflow:${POSTGRES_PASSWORD:-airflow}@postgres/airflow
    AIRFLOW__SCHEDULER__CREATE_CRON_DATA_INTERVALS: "True"   # [previous run, this run) for incremental extracts
    AIRFLOW__LOGGING__REMOTE_BASE_LOG_FOLDER: s3://${S3_BUCKET}/airflow-logs
  volumes:
    - ./dags:/opt/airflow/dags            # DAGs are mounted, not baked: git pull is enough to update them
    - ./spark_jobs:/opt/airflow/spark_jobs
  user: "${AIRFLOW_UID:-50000}:0"
  depends_on:
    postgres: {condition: service_healthy}
    rabbitmq: {condition: service_healthy}

services:
  rabbitmq:
    image: rabbitmq:3.13-management
    ports:
      - "127.0.0.1:15672:15672"   # management UI, only through Nginx
      - "5672:5672"               # AMQP for the workers EC2 (security group: workers only)
  airflow-scheduler:
    <<: *airflow-common
    command: scheduler
  airflow-init:                   # migrates the metadata DB and creates the admin user, then stops
    <<: *airflow-common
    command: version
    environment:
      <<: *airflow-common-env
      _AIRFLOW_DB_MIGRATE: 'true'
      _AIRFLOW_WWW_USER_CREATE: 'true'
    restart: "no"
```

On the **workers** machine the same block points to the core through its private IP (`NUCLEO_HOST`), and each worker listens to one Celery queue:

```yaml title="docker-compose.workers.yaml (excerpt)"
    AIRFLOW__DATABASE__SQL_ALCHEMY_CONN: postgresql+psycopg2://airflow:${POSTGRES_PASSWORD:-airflow}@${NUCLEO_HOST}:5432/airflow
    AIRFLOW__CELERY__BROKER_URL: amqp://${RABBITMQ_USER:-hospedaplus}:${RABBITMQ_PASSWORD:-hospedaplus}@${NUCLEO_HOST}:5672//
    AIRFLOW__CORE__EXECUTION_API_SERVER_URL: 'http://${NUCLEO_HOST}:8080/execution/'

services:
  worker-bronze:
    <<: *worker
    command: celery worker --queues bronze --concurrency 4   # light Python extracts, 4 at a time
  worker-silver:
    <<: *worker
    command: celery worker --queues silver --concurrency 2   # Spark jobs, memory-heavy
  worker-gold:
    <<: *worker
    command: celery worker --queues gold --concurrency 2
```

A task decides its worker with `@task(queue="silver")`. **Commands:**

```bash
# EC2 core
docker compose -f docker-compose.nucleo.yaml up -d
# EC2 workers (NUCLEO_HOST=<private IP of the core> in .env)
docker compose -f docker-compose.workers.yaml up -d
# Everything on one laptop
docker compose up -d
```

## 2. buenavista-streaming (F2: Kafka → Neon)

```dockerfile title="Dockerfile"
# One image for the F2 producer and the Kafka -> Neon consumer.
FROM python:3.12-slim
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
WORKDIR /app
COPY pyproject.toml README.md ./
COPY src ./src
COPY catalog ./catalog
RUN pip install --no-cache-dir . && useradd --create-home --uid 10001 app
USER app
CMD ["python", "-m", "src.neon_consumer"]   # Compose changes it for the producer
```

**One image, two roles:** the producer and the consumer are the same code; Compose chooses the role with `command:`.

```yaml title="docker-compose.yml (excerpt)"
services:
  kafka:                         # Kafka 4 in KRaft mode: no ZooKeeper
    image: apache/kafka:4.1.1
    environment:
      KAFKA_PROCESS_ROLES: broker,controller
      KAFKA_LISTENERS: PLAINTEXT://:9092,INTERNAL://:29092,CONTROLLER://:9093
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092,INTERNAL://kafka:29092
    volumes: [kafka_data:/var/lib/kafka/data]
    healthcheck:
      test: ["CMD-SHELL", "/opt/kafka/bin/kafka-broker-api-versions.sh --bootstrap-server localhost:9092"]

  kafka-init:                    # creates the topics once and stops
    image: apache/kafka:4.1.1
    depends_on: {kafka: {condition: service_healthy}}
    entrypoint: ["/bin/sh", "-c"]
    command:
      - |
        K=/opt/kafka/bin/kafka-topics.sh
        $$K --bootstrap-server kafka:29092 --create --if-not-exists --topic reservation.events.v1_3 --partitions 6 --replication-factor 1
        $$K --bootstrap-server kafka:29092 --create --if-not-exists --topic reservation.events.dlq --partitions 1 --replication-factor 1
    restart: "no"

  neon-migrate:                  # applies migrations/*.sql to Neon as the owner and stops
    image: postgres:16-alpine
    environment:
      NEON_OWNER_URL: ${NEON_OWNER_URL:?Falta NEON_OWNER_URL en .env (usuario hospedaplus_owner)}
    volumes: [./migrations:/migrations:ro]
    entrypoint: ["/bin/sh", "-c"]
    command:
      - |
        for f in /migrations/*.sql; do psql "$$NEON_OWNER_URL" -v ON_ERROR_STOP=1 -q -f "$$f"; done
    restart: "no"

  producer:
    build: .
    command: ["python", "-m", "src.kafka_producer", "--continuous",
              "--base-rate", "${F2_BASE_RATE:-0.05}", "--peak-rate", "${F2_PEAK_RATE:-15}"]
    depends_on: {kafka-init: {condition: service_completed_successfully}}

  neon-consumer:
    build: .
    environment:
      KAFKA_BOOTSTRAP_SERVERS: kafka:29092
      NEON_DATABASE_URL: ${NEON_DATABASE_URL:?Falta NEON_DATABASE_URL en .env (usuario app_writer)}
    depends_on:
      kafka-init: {condition: service_completed_successfully}
      neon-migrate: {condition: service_completed_successfully}
    deploy:
      replicas: ${NEON_CONSUMERS:-2}   # 2 consumers in the same group share the 6 partitions
```

**Two Kafka addresses:** containers use `kafka:29092` (the Docker network), your laptop uses `localhost:9092`. `${VAR:?message}` makes Compose stop with a clear message if a Neon URL is missing, and `$$` passes a literal `$` to the shell inside the container. **Command:** `docker compose up -d --build`.

## 3. db_simulated (F3: booking engine on PostgreSQL / Neon)

```dockerfile title="Dockerfile"
# Seed job image: runs `python -m seed <command>` against DATABASE_URL.
FROM python:3.12-slim
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1 PIP_NO_CACHE_DIR=1
WORKDIR /app
RUN pip install "psycopg[binary]>=3.2,<4" tzdata      # dependencies first: cached layer
COPY seed/ seed/
COPY sql/ sql/
COPY catalog/ catalog/
COPY data/ data/
RUN useradd --create-home --uid 10001 seeder
USER seeder
ENTRYPOINT ["python", "-m", "seed"]
CMD ["all"]                                            # docker compose run seed check -> python -m seed check
```

`ENTRYPOINT` + `CMD` turn the image into a command line tool: whatever you write after the service name replaces `all`.

```yaml title="docker-compose.yml (excerpt)"
services:
  postgres:                                  # local database
    image: postgres:16-alpine
    volumes:
      - pgdata:/var/lib/postgresql/data
      # executed only the first time (empty volume), in this order
      - ./sql/schema.sql:/docker-entrypoint-initdb.d/01_schema.sql:ro
      - ./sql/indexes.sql:/docker-entrypoint-initdb.d/02_indexes.sql:ro
      - ./sql/functions.sql:/docker-entrypoint-initdb.d/03_functions.sql:ro

  neon-seed:                                 # full load into Neon as hospedaplus_owner
    build: .
    profiles: ["neon"]                       # not started by a plain `up`
    environment:
      DATABASE_URL: ${NEON_OWNER_URL:-}
    command: ["all", "--allow-remote"]       # replacing remote data must be explicit

  neon-simulator:                            # continuous bookings on Neon as app_writer
    build: .
    profiles: ["neon"]
    environment:
      DATABASE_URL: ${NEON_APP_URL:-}
      SIM_BOOKINGS_PER_MIN: ${SIM_BOOKINGS_PER_MIN:-6}   # 1 in production (.env)
    command: ["simulate"]
    restart: unless-stopped
```

**Profiles** keep dangerous or one-off services out of `docker compose up`. **Commands:**

```bash
docker compose up -d postgres && docker compose run --rm seed all     # local database + seed
docker compose --profile neon run --rm neon-check                     # 24 read-only checks on Neon
docker compose --profile neon up -d neon-simulator                    # what runs on the EC2 sources
```

## 4. hospedaplus-csv (F4: weekly agency files)

```dockerfile title="Dockerfile"
FROM python:3.11-slim
WORKDIR /app
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1 PYTHONPATH=/app/src
COPY pyproject.toml README.md ./
COPY src/ ./src/
COPY schemas/ ./schemas/
COPY data/ ./data/
RUN pip install --no-cache-dir -e ".[neon,s3]"   # extras: psycopg (Neon) and boto3 (S3)
CMD ["python3", "-m", "buenavista_csv.validator"]
```

```yaml title="docker-compose.yml"
services:
  f4-weekly:
    build: .
    command: ["python", "-m", "buenavista_csv.weekly"]   # sleeps until Monday 06:00 UTC, generates, loads, uploads
    env_file: .env                                       # NEON_READ_URL, NEON_DATABASE_URL, F4_S3_BUCKET
    environment:
      F4_OUTPUT_DIR: /app/output/f4_agency_files
    volumes:
      - ./output:/app/output        # the files also stay on the EC2 disk
    restart: unless-stopped
```

The **volume** maps a folder of the EC2 into the container, so the generated Excel/CSV files survive a restart and can be opened from the server. **Command:** `docker compose up -d --build && docker compose logs -f f4-weekly`.

## 5. api-reviews (F5: FastAPI)

The most optimized image: a **multi-stage** build. The first stage has `uv` and builds the virtual environment; the second only copies the result, so the final image has no build tools.

```dockerfile title="Dockerfile"
# ---------- Stage 1: builder ----------
FROM python:3.12-slim AS builder
COPY --from=ghcr.io/astral-sh/uv:0.11 /uv /bin/uv
WORKDIR /app
ENV UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy UV_PYTHON_DOWNLOADS=never
COPY pyproject.toml uv.lock ./
RUN --mount=type=cache,target=/root/.cache/uv uv sync --frozen --no-install-project --no-dev
COPY alembic.ini ./
COPY alembic ./alembic
COPY src ./src
RUN --mount=type=cache,target=/root/.cache/uv uv sync --frozen --no-dev

# ---------- Stage 2: runtime (no uv, non-root) ----------
FROM python:3.12-slim AS runtime
ENV PYTHONUNBUFFERED=1 PATH="/app/.venv/bin:$PATH" RUN_MIGRATIONS=true
RUN groupadd --system app && useradd --system --gid app --no-create-home app
WORKDIR /app
COPY --from=builder --chown=app:app /app /app
COPY --chown=app:app --chmod=755 entrypoint.sh ./entrypoint.sh
USER app
EXPOSE 8000
HEALTHCHECK --interval=15s --timeout=5s --start-period=20s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')"
ENTRYPOINT ["./entrypoint.sh"]
CMD ["fastapi", "run", "src/main.py", "--host", "0.0.0.0", "--port", "8000"]
```

```sh title="entrypoint.sh"
#!/bin/sh
set -e
if [ "$RUN_MIGRATIONS" = "true" ]; then
    alembic upgrade head          # the schema is always up to date before the API starts
fi
exec "$@"                         # then runs CMD (the API) as PID 1
```

```yaml title="docker-compose.yml (excerpt)"
services:
  db:
    image: postgres:16-alpine
    ports: ["${POSTGRES_PORT:-5433}:5432"]     # 5433 on the host to avoid clashes
  api:
    build: .
    environment:
      DATABASE_URL: postgresql://${POSTGRES_USER:-postgres}:${POSTGRES_PASSWORD:-postgres}@db:5432/${POSTGRES_DB:-reviews}
    depends_on: {db: {condition: service_healthy}}
  seed:                                        # same image, runs once
    build: .
    command: ["python", "-m", "src.seed"]
    environment: {RUN_MIGRATIONS: "false"}     # the api already migrated
    depends_on: {api: {condition: service_healthy}}
  simulator:                                   # every 15 min inserts the reviews "published" since the last pass
    build: .
    command: ["python", "-m", "src.seed", "--live"]
    restart: unless-stopped
```

On AWS the same image runs as two **ECS Fargate** services (`api` and `simulator`, see `deploy/ecs/task-definition*.json`); `DATABASE_URL` comes from Secrets Manager. **Command (local):** `docker compose up --build`, then open `http://localhost:8000/docs`.

## Useful commands for any repository

```bash
docker compose ps                    # which containers are running and their health
docker compose logs -f <service>     # follow the logs of one service
docker compose up -d --build         # rebuild what changed and restart it
docker compose exec <service> bash   # open a shell inside a container
docker compose down                  # stop everything (volumes and data are kept)
```
